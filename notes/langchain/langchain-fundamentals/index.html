LangChain Fundamentals

Write one piece of code that works with any LLM provider, and snap together prompts, models, parsers and chains like building blocks.

One piece of code for any LLM?

The phone charger abroadYou fly from Bengaluru to London, then to Tokyo. Your phone charger is the same, but every country has a different wall socket. You don’t buy a new phone for each trip, you carry a universal travel adapter. LangChain is that adapter: your app stays the same, and LangChain handles each AI provider’s “socket”.

That is the problem this note solves: what if one piece of code could work with any LLM provider?

To see why LangChain is useful, we will first call two LLMs the “raw” way, with each company’s own official library. Then we will feel the pain, and fix it with LangChain.

Calling LLMs with their official SDKs

The simplest way to use an LLM from Python is the company’s own SDK. An SDK (Software Development Kit) is a company’s official Python library for using its service. OpenAI gives us openai; Google gives us google-genai.

OpenAI SDK: the basic template

This is the basic template from the official OpenAI documentation (developers.openai.com → Libraries → Python): install the SDK, create a client, and send a request with the Responses API. We add two lines to load our API key from a .env file.

pip install openai python-dotenv
openai_basic.py
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()  # reads OPENAI_API_KEY from the .env file

client = OpenAI()

response = client.responses.create(
    model="gpt-5",
    input="Write a one-sentence bedtime story about a unicorn.",
)

print(response.output_text)
python openai_basic.py
Under a silver moon, a little unicorn named Luna wished every child sweet dreams.

Gemini SDK: the basic template

Now the same job with Google’s Gemini, using the official google-genai SDK and an API key from Google AI Studio. This time we also ask the user for the question.

pip install google-genai python-dotenv
gemini_basic.py
import os
from dotenv import load_dotenv
from google import genai

load_dotenv()
client = genai.Client(api_key=os.getenv("GEMINI_API_KEY"))

question = input("Ask Gemini: ")

response = client.models.generate_content(
    model="gemini-3.6-flash",
    contents=question,
)

print(response.text)

Imagine your company built a chatbot with OpenAI, and the manager now says: “Gemini is cheaper, let’s switch.” You must rewrite every model call in the app. Add Claude next month and you learn a third library. Every provider has its own library, function names and response format.

A real app needs much more than one call

Switching providers is only the first problem. A real LLM application, like a support chatbot or a document assistant, also needs:

Reusable prompts

The same prompt with different inputs, like a form with blanks.

Easy model switching

Try GPT today and Gemini tomorrow without rewriting the app.

Connected steps

Prompt → model → clean output → next step.

Memory

Remembering earlier messages in a conversation.

Tools

Letting the model search the web, call an API or use a calculator.

Your own documents

Answering questions from PDFs and company files.

With raw SDKs you write all of this yourself, separately for every provider. That is a lot of repeated work, and a lot of places for bugs.

LangChain: the solution

Developers kept writing the same plumbing code again and again, so a framework was created to provide it ready-made.

LangChain is an open-source framework for building applications powered by Large Language Models (LLMs). It does not create its own AI model. Instead, it helps your application connect with and work with different AI models and other components.

One interface

Work with different AI providers using the same LangChain style of code.

Building blocks

Ready components you combine into an app: models, prompts, tools, chains and more.

Chains

Connect multiple steps together so the output of one feeds the next.

Why LLM apps need it

An LLM on its own is a text-in, text-out brain. On its own it:

  • forgets earlier messages (it is stateless),
  • doesn’t know your private data (PDFs, databases),
  • can’t use live tools (weather, calculator, search),
  • has a different API for every provider (Gemini, GPT, Claude),
  • and multi-step workflows get messy to code by hand.

LangChain solves each of these with a ready-made component:

ProblemLangChain solution
Different APIs for each providerModels: one standard interface
Hard-coded, repeated instructionsPrompts: reusable templates
Messy multi-step workflowsChains: connect steps with |

AI forgets the conversationMemory: keeps past messages

Your first LangChain program: one interface, two models

Let’s ask the same question to both OpenAI and Gemini, with the same code. Install LangChain and its connectors (called integrations) for the two providers:

pip install langchain langchain-openai langchain-google-genai python-dotenv
one_interface.py
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model

load_dotenv()  # OPENAI_API_KEY and GOOGLE_API_KEY from .env

openai_model = init_chat_model("openai:gpt-4o")
gemini_model = init_chat_model("google_genai:gemini-2.5-flash")

question = "Explain what an API is in one sentence."

print("OpenAI :", openai_model.invoke(question).text)
print("Gemini :", gemini_model.invoke(question).text)
OpenAI : An API is a set of rules that lets one program use another’s data or services.
Gemini : An API is a contract that lets different software systems talk to each other.
openai:gpt-4o

Provider: which integration to use (openai, google_genai, anthropic, ollama…).

Model name: the exact model at that provider.

  • init_chat_model("openai:gpt-4o") creates an OpenAI chat model; "google_genai:gemini-2.5-flash" creates a Gemini one.
  • Both are used in exactly the same way: .invoke(question) sends the question and .text gives the answer text.
  • To switch provider, you change only the model string. The “manager wants Gemini” problem is now a one-line change.
In the field (FDE) Customers often have a mandated provider (an Azure OpenAI contract, a Vertex AI account, an on-prem Ollama box). Keep the model string in config or an environment variable, e.g. init_chat_model(os.environ["CHAT_MODEL"]), and the same code ships to every customer.

A basic LangChain workflow

Suppose an employee asks your company assistant: “What is the leave policy in my company?” LangChain manages the flow between the components:

  1. 1
    Receive the question“What is the leave policy?”
  2. 2
    Prepare the promptThe question is combined with instructions for the LLM. → prompt template
  3. 3
    Get informationThe app may search a PDF, database, website or other source. → retriever
  4. 4
    Send it to the LLMQuestion + relevant information go to the model. → chat model
  5. 5
    Generate the final answerThe LLM produces a clear answer, which goes back to the user. → output parser

Raw SDK calls vs LangChain

We have now built the same kind of program both ways. Let’s compare them properly.

Direct SDK approach

Your code talks straight to one provider using its own library.

  • Simple: one package, a few lines, done.
  • Fast and light: no extra layer, fewest dependencies.
  • Newest features first: new provider features appear in their own SDK on day one.
  • But every provider needs different code, and everything beyond one call (prompts, memory, tools, steps) is hand-written.

What LangChain adds

It keeps the model call but adds ready-made blocks around it.

  • One standard interface for all providers (.invoke(), .text).
  • Prompt templates reused with different inputs.
  • Output parsers for clean text or structured data.
  • Chains that connect steps with the | pipe.
  • Ready support for memory, tools, documents and agents as the app grows.
Choose…When…
The raw SDKOne provider, one simple call, or you need a brand-new provider feature today.
LangChainMultiple providers, multi-step flows, templates, tools, retrieval or agents.
In the field (FDE) It is not all-or-nothing. A common production pattern is LangChain for the pipeline (prompts, retrieval, parsing) with a raw SDK call in the one place you need a provider-only feature. Pick the simpler tool per job, and be ready to explain the choice to the customer’s engineers.

The next sections take each brick in turn, with code. All imports come from langchain_core (the shared basics) or a provider integration such as langchain_google_genai.

Models

The model component communicates with the AI model. Your application never talks to Gemini, GPT or Claude directly. It talks to LangChain’s model interface, and LangChain handles the provider details. LangChain has three kinds of models:

1. Chat models

A chat model is an AI you talk to like a conversation. Instead of one plain sentence, you send it a list of messages, and each message says who is speaking:

  • System: the rules for the AI (“You are a friendly teacher”).
  • Human: what the user says.
  • AI: what the model replied earlier.

Because the model knows who said what, it can follow the conversation and understand follow-ups like “give me an example”.

from langchain_core.messages import SystemMessage, HumanMessage
from langchain_google_genai import ChatGoogleGenerativeAI

chat_model = ChatGoogleGenerativeAI(model="gemini-2.5-flash")

response = chat_model.invoke([
    SystemMessage(content="You are a friendly teacher."),
    HumanMessage(content="What is a variable?"),
])
print(response.text)     # response is an AIMessage

2. LLMs (text-completion models)

The older, simpler style. They take one string and return one string, with no roles and no message list.

from langchain_openai import OpenAI       # the text-completion class, not ChatOpenAI

llm = OpenAI(model="gpt-3.5-turbo-instruct")
llm.invoke("Hi")            # → 'Hello! How can I help you today?'  (a plain str)

chat_model.invoke([HumanMessage(content="Hi")])   # chat model, for contrast → AIMessage
Use chat models for new work Almost every modern model is served as a chat model. The plain-text LLM classes still exist for a few older completion models, but you will rarely pick one.

3. Embedding models

An embedding model takes text and returns a vector: a list of numbers that captures its meaning. Texts with similar meaning get similar vectors, which is how search by meaning and retrievers work.

from langchain_openai import OpenAIEmbeddings

emb = OpenAIEmbeddings(model="text-embedding-3-small")
emb.embed_query("Hi")       # → [0.12, -0.45, ...]  (1,536 numbers)

Messages

A message is one piece of a conversation. Each message has two things: a role (who is speaking) and content (what they said).

TypeClassMeaning
SystemSystemMessageRules for the AI (“You are a teacher”)
HumanHumanMessageWhat the user says
AIAIMessageWhat the model replied
messages.py
from langchain_core.messages import SystemMessage, HumanMessage, AIMessage
from langchain_google_genai import ChatGoogleGenerativeAI

messages = [
    SystemMessage(content="You are a friendly teacher."),
    HumanMessage(content="What is a variable?"),
    AIMessage(content="A variable is a named box that stores a value."),
    HumanMessage(content="Give me an example."),
]

chat_model = ChatGoogleGenerativeAI(model="gemini-2.5-flash")

response = chat_model.invoke(messages)
print(response.text)     # the answer text
print(type(response))    # <class 'langchain_core.messages.ai.AIMessage'>

Shortcut: tuples

You can write messages as simple (role, content) pairs instead of classes:

messages = [
    ("system", "You are a friendly teacher."),
    ("human", "What is a variable?"),
]
response = chat_model.invoke(messages)
.text or .content? response.content is the raw content, which some providers return as a list of content blocks (text, reasoning, images) rather than a plain string. response.text always gives you just the text as a string, so prefer it when you want to print or store the answer.

Prompts and prompt templates

A prompt is the instruction or input you give the AI. “Explain Python” is a prompt. Hard-coding a new sentence every time is messy, so LangChain lets you build reusable, dynamic prompts called prompt templates: a prompt with {blanks} that you fill in later.

The railway reservation formThe form is printed once: Name ____ From ____ To ____. Lakhs of passengers fill in their own blanks. A prompt template is that printed form, and each invoke is one passenger filling it in.
Explain {topic} in a {tone} tone.

Fixed text, written once.

{topic} = "Python"

{tone} = "simple" → “Explain Python in a simple tone.”

1. PromptTemplate (plain-text prompt)

Produces a single string. It matches the text-style LLM.

from langchain_core.prompts import PromptTemplate

prompt = PromptTemplate.from_template("Explain {topic} in a {tone} tone.")

filled = prompt.invoke({"topic": "Python", "tone": "simple"})
print(filled.to_string())   # Explain Python in a simple tone.

2. ChatPromptTemplate (message-based prompt)

Produces a list of messages with roles. This is the one to use with chat models, since they expect system, human and AI messages.

from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a {role}."),
    ("human", "Explain {topic} in a {tone} tone."),
])

messages = prompt.invoke({
    "role": "friendly teacher",
    "topic": "Python",
    "tone": "simple",
})
# → [SystemMessage("You are a friendly teacher."),
#    HumanMessage("Explain Python in a simple tone.")]

For a single human message there is a shortcut: ChatPromptTemplate.from_template("Explain {topic} in one line.").

3. MessagesPlaceholder (for conversation history)

A normal {input} holds one piece of text. A MessagesPlaceholder is a reserved spot that holds a list of messages, so the past chat can be sent to the model along with the new question. This is how the AI “remembers”.

from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder

prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful assistant."),
    MessagesPlaceholder("history"),     # old messages go here
    ("human", "{input}"),
])

prompt.invoke({
    "history": [("human", "Hi, I'm Asha."), ("ai", "Hello Asha!")],
    "input": "What's my name?",
})
Literal braces In a template, { and } mean “a blank”. If your prompt contains real JSON like {"name": "..."}, double the braces: {{"name": "..."}}, or LangChain will complain about a missing variable.

Output parsers and structured output

A chat model returns an AIMessage object, not clean text. An output parser converts the model’s raw output into the format you actually need: a plain string, a list, JSON, or a Python object.

AIMessageoutput parserstr · dict · object

1. StrOutputParser: message → plain string

Takes the AIMessage and returns just the text as a str. This is the most used parser. Here we run each step by hand so you can see what happens:

from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_google_genai import ChatGoogleGenerativeAI

chat_model = ChatGoogleGenerativeAI(model="gemini-2.5-flash")
prompt = ChatPromptTemplate.from_template("Explain {topic} in one line.")

formatted_prompt = prompt.invoke({"topic": "Python"})   # 1. create the prompt
response = chat_model.invoke(formatted_prompt)          # 2. send it to Gemini
parser = StrOutputParser()
result = parser.invoke(response)                        # 3. AIMessage → str
print(result)
Python is a simple, readable, general-purpose programming language.

2. JsonOutputParser: text → Python dict

Turns the model’s JSON reply into a Python dictionary. Its get_format_instructions() gives you text to paste into the prompt, telling the model to answer in JSON.

from langchain_core.output_parsers import JsonOutputParser

parser = JsonOutputParser()
prompt = ChatPromptTemplate.from_template(
    "Give name and age of a famous scientist.\n{format_instructions}"
)

formatted_prompt = prompt.invoke({
    "format_instructions": parser.get_format_instructions()
})
response = chat_model.invoke(formatted_prompt)
result = parser.invoke(response)      # → {'name': 'Albert Einstein', 'age': 76}
print(result["name"])

3. Structured output with Pydantic (best for real apps)

Often we don’t want a long, free-form answer. We want a fixed format. Think of it like a form: you give the model a form with blanks (name, age, field) and it must fill in each blank. You describe the form as a Pydantic class, and you get back a clean Python object.

  1. 1
    Make the formA Pydantic class lists each field, its type and a description.
  2. 2
    Give the form to the modelwith_structured_output(Person) wraps the model.
  3. 3
    Ask your questionYou get a Person object back, not text.
structured.py
from pydantic import BaseModel, Field

# Step 1: make the form
class Person(BaseModel):
    name: str = Field(description="Full name")
    age: int = Field(description="Age in years")
    field: str = Field(description="Area of work")

# Step 2: give the form to the model
structured_model = chat_model.with_structured_output(Person)

# Step 3: ask your question
result = structured_model.invoke("Tell me about Marie Curie.")

print(result.name)    # Marie Curie
print(result.age)     # 66
print(result.field)   # Physics and Chemistry
In the field (FDE) Customer systems (CRMs, ticketing tools, databases) need exact fields, not prose. with_structured_output uses the provider’s native JSON or tool-calling mode, so it is far more reliable than asking nicely for JSON. Still validate: catch errors and retry or flag the record instead of letting a bad row into the customer’s system.

Chains and the | pipe (LCEL)

A chain connects multiple steps into one workflow. The output of one step automatically becomes the input of the next. In the previous section we passed each result by hand; with a chain, LangChain handles the connections.

The dosa counterAt a busy darshini, one person spreads the batter, the next adds the masala, the last folds and plates it. Nobody walks the dosa around by hand; the counter moves it along. prompt | model | parser is that counter.
langchain_chain.py
from dotenv import load_dotenv
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_google_genai import ChatGoogleGenerativeAI

load_dotenv()

chat_model = ChatGoogleGenerativeAI(model="gemini-2.5-flash")
parser = StrOutputParser()
prompt = ChatPromptTemplate.from_template("Explain {topic} in one line.")

chain = prompt | chat_model | parser

print(chain.invoke({"topic": "Python"}))
{topic}PromptChat modelParsertext

This | style is called LCEL, the LangChain Expression Language. Every block (prompt, model, parser, retriever…) is a Runnable, so they all share the same methods:

MethodWhat it does
chain.invoke(x)Run once on one input, return the result.
chain.batch([x1, x2, …])Run on many inputs, in parallel where possible.
chain.stream(x)Yield the answer piece by piece as it is generated, for chat UIs.
Swap one brick Because every block has the same shape, changing chat_model to an OpenAI or Claude model changes nothing else in the chain.

Retrievers and tools

Retrievers

A retriever finds the most relevant information from your stored data, based on the user’s question. Think of it as a search assistant. Suppose you have a 500-page company PDF and the user asks, “What is the company’s leave policy?” Instead of giving the entire PDF to the AI, the retriever pulls out just the leave-policy section:

Retrievers usually sit on top of embeddings stored in a vector store. A tiny in-memory example:

from langchain_core.vectorstores import InMemoryVectorStore
from langchain_openai import OpenAIEmbeddings

store = InMemoryVectorStore.from_texts(
    ["Employees get 24 days of paid leave per year.",
     "Office hours are 9:30 to 6:00.",
     "Laptops are refreshed every 3 years."],
    embedding=OpenAIEmbeddings(model="text-embedding-3-small"),
)
retriever = store.as_retriever(search_kwargs={"k": 1})

retriever.invoke("What is the leave policy?")
# → [Document(page_content='Employees get 24 days of paid leave per year.')]

You will build full retrieval pipelines (loading, chunking, vector databases) in the RAG module.

Tools

A tool is a Python function that the AI can choose to call. A chat model on its own can only produce text: it cannot check live weather, do exact maths, or search your database. Tools give it those abilities.

QuestionAI decidesasks for tool callyour code runs itresult back to AIfinal answer
The AI does not run the tool It only asks for a tool call: the tool’s name plus arguments. Your code (or an agent loop) actually runs the function and sends the result back.
from langchain_core.tools import tool

@tool
def multiply(a: float, b: float) -> float:
    """Multiply two numbers."""
    return a * b

model_with_tools = chat_model.bind_tools([multiply])
msg = model_with_tools.invoke("What is 12.5 times 8?")

print(msg.tool_calls)
# [{'name': 'multiply', 'args': {'a': 12.5, 'b': 8}, 'id': '...', 'type': 'tool_call'}]

multiply.invoke(msg.tool_calls[0]["args"])   # → 100.0  (your code runs it)

The docstring and type hints matter: LangChain turns them into the tool description the model reads to decide when and how to call it.

In the field (FDE) Tools are how an assistant touches a customer’s real systems: “look up order 4512”, “create a Jira ticket”. Give each tool a narrow job, a clear docstring, and validate the arguments before acting. Anything that writes or spends money should need a human approval step.

The LangChain ecosystem

LangChain is not just one package: it is a family of tools that work together, from basic building blocks up to full agents and monitoring.

LangChain Core

LangChain Core (langchain-core) is the bottom of the stack: the basic building blocks every other part uses.

  • Messages: system, human and AI messages.
  • Prompt templates: like our ChatPromptTemplate.
  • Chat model interface: the common .invoke() style shared by all models.
  • Output parsers: like our StrOutputParser.
  • The | pipe: how blocks are joined into chains (LCEL).

Look back at langchain_chain.py: we imported ChatPromptTemplate and StrOutputParser from langchain_core. We were already using LangChain Core.

Integrations

Core defines how a chat model should behave, but not how to reach a specific company’s model. That is the job of integrations: small packages that each connect LangChain to one provider or tool.

Integration packageConnects LangChain to
langchain-openaiOpenAI GPT models
langchain-google-genaiGoogle Gemini models
langchain-anthropicAnthropic Claude models
langchain-ollamaFree open models running on your own laptop

Integrations are not only for models. There are also integrations for vector databases, document loaders (PDF, websites, Google Drive) and tools (web search, calculators). When we wrote init_chat_model("google_genai:..."), LangChain used langchain-google-genai behind the scenes.

LangGraph

Our chain ran in a straight line: prompt → model → parser. Many real tasks don’t. A support assistant may need to decide what kind of ticket it is, take an action, check whether the answer is good, and try again if it is not.

LangGraph is for building these agents and multi-step workflows. You describe the app as a graph, like a flowchart: boxes are steps, and arrows can branch and loop.

Branching

Refund question → check the order; bug report → search the docs.

Loops

If the answer isn’t good enough, go back and try again.

Memory and state

Remember what happened in earlier steps.

Human in the loop

Pause and ask a person to approve an action.

LangChain’s own agents are built on top of LangGraph, which is why pip install langchain also installs langgraph. You will build agents in a later module.

LangSmith

As apps get more steps, a new problem appears: when the answer is wrong, which step caused it? The prompt? The model? A tool? LangSmith is the platform for tracing, debugging and evaluating LLM apps. Once switched on, it records every step of every request:

  • The exact prompt that was sent to the model.
  • The model’s answer, tokens used, time taken and cost.
  • Each step’s input and output, so you can find where things went wrong.
# .env — turning on LangSmith tracing needs no code changes
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=your_langsmith_key
In the field (FDE) When a customer says “the bot gave a wrong answer on Tuesday”, a trace lets you open that exact request and see the prompt, the retrieved documents and the model output. Check the customer’s data policy first: traces contain their data, so they may require a self-hosted setup or tracing switched off in production.

An open-source framework for building LLM-powered applications. It gives one interface to many model providers plus reusable building blocks; it is not a model itself.
init_chat_model
A LangChain helper that creates a chat model from a "provider:model" string, so switching providers is a one-line change.
Chat model
A model that takes a list of role-tagged messages and returns an AIMessage. The standard way to use modern LLMs.
Embedding model
A model that turns text into a vector (a list of numbers) capturing its meaning, used for search by meaning.
Message
One turn of a conversation with a role (system, human or AI) and content.
Prompt template
A reusable prompt with {placeholders} that are filled in at run time. ChatPromptTemplate produces a list of messages for chat models.
MessagesPlaceholder
A slot in a chat prompt template that holds a whole list of messages, typically the conversation history.
Output parser
A component that converts a model’s raw output into a usable format such as a string, a dict or a Python object.
Structured output
Making a model fill a predefined schema (for example a Pydantic class) via with_structured_output, returning a typed object.
Chain / LCEL
Steps joined with the | pipe so each step’s output becomes the next step’s input; LCEL is the LangChain Expression Language that defines this.
Retriever
A component that finds the most relevant pieces of your stored data for a question, so only those are sent to the model.
Tool
A Python function the model can ask to call, with a name and arguments; your code runs it and returns the result.
LangGraph
The part of the LangChain ecosystem for agents and workflows that branch, loop, keep state and pause for human approval.
LangSmith
A platform for tracing, debugging and evaluating LLM apps by recording each step’s inputs, outputs, tokens, time and cost.

Why use a retriever instead of pasting a 500-page PDF into the prompt?

  1. Models cannot read PDFs at all
  2. It sends only the relevant pages, which is cheaper, faster and more focused
  3. Retrievers make the model larger
  4. It removes the need for a model

The retriever finds the few relevant chunks, so the model works with less, better-targeted text.

All of it, in one sentence

LangChain gives you one interface for every model provider plus building blocks (models, messages, prompt templates, output parsers, retrievers and tools) that you snap together into chains with |, while LangGraph handles agents and LangSmith shows you what happened.
