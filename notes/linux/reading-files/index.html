Essential Commands: Reading Files

See what is inside any file from the terminal, and pick the right tool for a 5-line note, a 50,000-line log, or just a quick peek at the top.

Why we need file-reading commands

So far you have used touch, mkdir, cp, mv and rm to create and manage files. But given a file like app.txt, the obvious next question is: what is actually inside it? We need commands that show file contents right in the terminal.

Reading the newspaperA one-line SMS you read in full. The Sunday newspaper you flip through page by page, jumping to the sports section. A thick exam guide you only check the contents page of. You don’t always want to read an entire file, so Linux gives you a different tool for each situation.

For the big log you want to read, scroll, search, go backward and go forward:

readscrollsearchgo backwardgo forward

cat · display the complete file

Full form: concatenate. Program location: /bin/cat. cat prints a file’s contents straight into the terminal, all at once. It is the most convenient choice for small files.

filecatentire content appears
syntax
cat filename

Suppose app.txt contains three lines. Run:

cat app.txt
Linux is an operating system.
Linux is widely used on servers.
Linux is important in DevOps.

What happened? Linux opened app.txt, read its contents and sent them to the terminal.

open app.txtread contentssend to terminal

Line numbers with -n

Sometimes you need to know which line contains something, for example when an error message says “line 2”. The -n option numbers every line:

cat -n app.txt
     1  Linux is an operating system.
     2  Linux is widely used on servers.
     3  Linux is important in DevOps.

Reading and combining several files

cat isn’t limited to one file. Given these two:

file1.txt
Hello
Welcome to Linux
file2.txt
Linux is powerful
Linux is flexible
cat file1.txt file2.txt
Hello
Welcome to Linux
Linux is powerful
Linux is flexible

Notice the order: all of file1.txt, then all of file2.txt, joined end to end. That joining is where the name concatenate comes from.

Saving the combined result

Because cat produces file1 content + file2 content, you can redirect that output into a new file with >:

cat file1.txt file2.txt > combined.txt
> replaces If combined.txt already exists, > overwrites it. Use >> to append instead. The Pipes & Redirection note covers both in detail.

The limitation of cat

Now try cat server.log on a log with thousands of lines:

line 1
line 2
line 3
...
line 5000
line 5001
line 5002
...

The output races past your screen and you are left looking at the last few lines. cat isn’t broken. The problem is that you asked it to show everything, when you don’t actually want everything at once. That is where less comes in.

less · browse a file interactively

Program location: /usr/bin/less. less lets you read a large file one screen at a time, like turning the pages of a book.

syntax
less filename
less server.log

Instead of printing the whole file, less takes over the terminal, shows one screenful and waits for your keys.

KeyPurpose
SpaceMove forward one screen
bMove backward one screen
↑ / ↓Move line by line
gGo to the beginning of the file
GGo to the end of the file
/wordSearch forward for “word”
?wordSearch backward for “word”
nJump to the next search result
qQuit and return to the terminal
Why “less”? An older pager was called more (it could only go forward). less came later and does more, including going backward. Hence the joke: “less is more”.

Practise less on a log file

First build a small server.log. > creates the file with the first line, and each >> appends one more line:

Create the practice log

echo "Server started" > server.log
echo "User admin logged in" >> server.log
echo "Database connected" >> server.log
echo "Request received" >> server.log
echo "Request completed" >> server.log
echo "ERROR database connection failed" >> server.log
echo "User john logged in" >> server.log
echo "Database backup started" >> server.log
echo "Database backup completed" >> server.log
echo "ERROR network unavailable" >> server.log
# repeat these lines a few more times to make the file longer than one screen

cat server.log shows every line at once. Now open it with less server.log. For a small file you may not notice much difference; the more lines you add, the more useful it gets.

Move through the file

Press Space to go one screen forward. Went too far? Press b to go back one screen.

Screen 1SpaceScreen 2bScreen 1

Find an error

Imagine server.log has 10,000 lines and somewhere inside is ERROR database connection failed. Don’t scroll manually. Inside less, type /ERROR and press Enter. less jumps to the first match and highlights it. Press n for the next one, and again for the one after:

/ERRORfirst ERRORnnext ERRORnnext ERROR

Near the end of the file and want to look upwards? Use ?ERROR + Enter to search backward.

/ERROR

Search forward (down the file).

?ERROR

Search backward (up the file).

n follows your direction After ?ERROR, n keeps searching backward. N (capital) always goes the opposite way.

Jump to the start, the end, and out

  1. g
    Beginning of the fileFrom anywhere in a huge file, g takes you straight to line 1.
  2. G
    End of the fileLogs grow at the bottom, so G shows you the latest entries.
  3. q
    QuitLeaves less and returns you to your normal terminal prompt.
less server.logread / move / searchqnormal terminal
In the field (FDE) When a customer says “the app crashed around 3 pm”, your first move is often less /var/log/app.log, then G to jump to the latest lines and ?ERROR to walk backward through the failures. It is read-only, so you can’t accidentally edit a production log.

head · read the beginning of a file

Sometimes you only need to know: “What does the start of this file look like?” Is it a CSV with a header? What format are the log lines in? users.txt may hold 1,000 lines (User 1 … User 1000), but you only want the first few. head shows you the beginning of a file, quickly.

syntax
head filename           # first 10 lines (the default)
head -n NUMBER filename # first NUMBER lines

Practical example

echo "Line 1" > app.log
echo "Line 2" >> app.log
echo "Line 3" >> app.log
# ...keep going up to...
echo "Line 12" >> app.log

cat app.log      # shows all 12 lines
head app.log     # shows only the first 10
Line 1
Line 2
Line 3
Line 4
Line 5
Line 6
Line 7
Line 8
Line 9
Line 10

Ten lines too many, or too few? Tell head exactly how many:

head -n 5 app.log
Line 1
Line 2
Line 3
Line 4
Line 5
Its twin: tail tail is the mirror image: it shows the last 10 lines (tail -n 20 app.log for 20). tail -f app.log keeps the file open and prints new lines as they are written, perfect for watching a live log.

Choosing the right tool

CommandShowsBest forInteractive?
catthe whole file at oncesmall files, combining filesno
cat -nthe whole file with line numbersfinding “which line”no
lessone screen at a timelarge files and logs; scrolling and searchingyes (q to quit)
headthe first 10 lineschecking the format or headerno
head -n Nthe first N linesa custom-sized peekno
Rule of thumb If you don’t know how big a file is, never start with cat. Use less or head first; wc -l file (from the Text Filters note) tells you the line count.

Key terms

cat
Short for concatenate. Prints the full contents of one or more files to the terminal, one after another.
cat -n
Prints a file with a line number in front of every line.
Concatenate
To join things end to end. cat a b outputs all of a followed by all of b.
less
An interactive pager that shows a file one screen at a time and lets you scroll, search and jump; press q to quit.
Pager
A program that displays long text one page (screenful) at a time instead of printing it all at once.
/pattern and ?pattern
Inside less, search forward (/) or backward (?) for text; n jumps to the next match.
head
Prints the first lines of a file, 10 by default; -n N sets how many.
tail
Prints the last lines of a file, 10 by default; tail -f keeps following new lines as they are added.

Self-check

Pick an answer. You’ll see right away whether it’s correct and why.

You need to scroll through a 50,000-line log and search it. Which command fits best?

  1. cat server.log
  2. less server.log
  3. head server.log
  4. cat -n server.log

less shows one screen at a time and supports scrolling and searching. cat would flood the terminal.

What does cat a.txt b.txt print?

  1. Only a.txt
  2. The lines of both files interleaved
  3. b.txt, then a.txt
  4. All of a.txt, followed by all of b.txt

cat concatenates: files are printed whole, in the order you list them.

How many lines does head app.log show by default?

  1. 10
  2. 5
  3. 20
  4. The whole file

head defaults to the first 10 lines. Use -n to change it.

Inside less, you searched with /ERROR. How do you jump to the next match?

  1. b
  2. q
  3. n
  4. G

n repeats the last search. b goes back a screen, q quits, G jumps to the end.

You want the newest entries at the bottom of a log you opened in less. Which key?

  1. g
  2. G
  3. Space
  4. ?

Capital G jumps to the end of the file; lowercase g goes to the beginning.

Which command saves the joined contents of two files into a new file?

  1. cat file1.txt + file2.txt
  2. less file1.txt file2.txt
  3. head file1.txt file2.txt combined.txt
  4. cat file1.txt file2.txt > combined.txt

cat outputs both files in order, and > redirects that output into combined.txt.

Why is cat a poor choice for a huge file?

  1. It changes the file
  2. It can only read files under 1 MB
  3. It prints everything at once, so the text scrolls past too fast to read
  4. It deletes lines it can’t show

cat works fine; it just shows everything, which is not what you want for a big file.

All of it, in one sentence

Use cat to see a small file in full (or join files), less to scroll and search a big one one screen at a time, and head to peek at just the beginning.
