Files & Directories

Create, copy, move, rename and delete files and folders straight from the terminal, and do it without ever losing something by accident.

Quick recap before we start

Your study tableNotebooks are your files, the shelf boxes labelled “Maths” and “Physics” are your directories, and “second box from the left, top notebook” is the path. Until now you have only looked at the shelf. This note is about changing it: adding, copying, moving and throwing things away.

The previous notes (The Linux File System Structure and the navigation commands) covered these ideas in detail. Here is the short version:

File

A named container of data: text, configuration, a log or a program. In Linux, “everything is a file”.

Directory

A folder that groups related files. Directories nest inside each other to form a tree.

Path

The address of a file or folder. Absolute starts at /; relative starts from where you are now.

CommandAnswers the question
pwdWhere am I?
lsWhat is here?
cdTake me somewhere else.
ls -lShow details (size, owner, date).
ls -aShow hidden files too (names starting with .).
Not comfortable yet? If any of these five commands feel unfamiliar, review the earlier notes first. Everything below assumes you can move around with pwd, ls and cd.

touch · creating files

Program location: /usr/bin/touch. Imagine starting a new project that needs these files:

project/
├── README.md
├── notes.txt
├── config.txt
└── script.sh

You could open an editor and save each one. Linux gives you a faster way: touch creates an empty file directly from the terminal.

touch README.md

This creates the file immediately.

syntax
touch filename
touch notes.txt     # touch = command, notes.txt = file name

Creating files

First check where you are:

pwd

Create one file, then check it is there:

touch file.txt     # instantly creates an empty file named file.txt here
ls

How do you know the file is empty?

ls -l file.txt

Look at the 0. That column is the file size in bytes, so 0 means the file currently contains no data.

touch does not write content

Running touch file.txt creates the file, but it does not put any text inside it.

Many files at once

touch app.txt config.txt notes.txt
ls

All three files are created together in a single command, much faster than running touch three separate times.

A file inside another directory

Suppose you have /home/ubuntu/students and want to create /home/ubuntu/students/notes.txt. You can first enter the directory, then create the file:

cd students
touch notes.txt

# or, without moving:
touch students/notes.txt

What if the file already exists?

Suppose file.txt already contains Hello Linux, and you run touch file.txt again. touch does not erase the content: the file still contains Hello Linux. Instead, it updates the file’s timestamps to the current time.

Where does the name come from? touch was built to “touch” a file, i.e. refresh its access and modification times. Creating the file when it doesn’t exist is a side effect that turned out to be very handy.

mkdir · creating directories

Full form: make directory. Program location: /bin/mkdir. Files need organisation. Picture 500 of these in one place:

notes.txt  image.jpg  app.py  data.csv  resume.pdf  config.txt  ...

Finding anything becomes painful. Instead we organise them into folders:

project/
├── documents/
├── scripts/
├── data/
└── images/

Linux uses the mkdir command to create directories.

Creating a directory

mkdir project

This creates a single new folder named project inside your current location.

Creating multiple directories

mkdir docs images backup

Just like touch, mkdir can create several folders in one go: three separate, empty directories appear side by side after this single command.

Creating nested directories

mkdir project/src

This creates a src folder inside project, but only works if project already exists. If it doesn’t exist yet, Linux refuses and shows an error, because it won’t guess whether you meant to create the parent folder too:

mkdir: cannot create directory 'project/src': No such file or directory

Creating parent directories automatically

Suppose you want to create project2/src2/main, but none of these directories exist. Use -p:

mkdir -p project2/src2/main

The -p (parents) option tells Linux: create the required parent directories as well. It also stays quiet if the folder already exists.

Verify with a recursive listing

ls -R project2

cp · copying files

Full form: copy. Program location: /bin/cp. Before editing report.txt, you want a backup:

cp report.txt report_backup.txt

Now there are two files. The original report.txt is untouched, and a new copy report_backup.txt exists next to it.

syntax
cp SOURCE DESTINATION
# SOURCE      = what you want to copy
# DESTINATION = where the copy goes / what to call it

For example: cp notes.txt backup.txt.

Practical example

Let’s create a simple file first:

touch file1.txt

Now add some content to it using >, and check the content:

echo "This is my first file" > file1.txt   # > writes text into the file
cat file1.txt

Now we have a file with actual content, so let’s copy it and check:

cp file1.txt file2.txt
ls

Now verify that the content was copied:

cat file2.txt

Copying a file into a directory

Suppose you have file1.txt and a documents/ folder, and you want a copy of file1.txt inside documents:

cp file1.txt documents/

Copying and renaming at the same time

You can also give the copied file a different name:

cp file1.txt documents/report.txt

Copying multiple files

Suppose you have file1.txt, file2.txt, file3.txt and documents/, and want to copy all three files into documents.

cp file1.txt file2.txt file3.txt documents/   # the last argument must be a folder
Copying a whole folder cp skips directories unless you add -r (recursive): cp -r project project_backup copies the folder and everything inside it.

mv · moving and renaming

Program location: /bin/mv. mv does two jobs: move a file or directory somewhere else, and rename it. Unlike cp, it never makes a second copy.

Shifting the tiffinWhen you move your tiffin box from the kitchen table to your bag, there is no tiffin left on the table. mv physically relocates the item; after the move it is no longer at the original place.

Think of it like physically taking something from one place and putting it somewhere else:

SOURCEDESTINATION
syntax (same pattern as cp)
mv SOURCE DESTINATION
# SOURCE      = the file or folder to move or rename
# DESTINATION = where it should end up / what it should be called
# before
.
├── file1.txt
└── documents/
# after: mv file1.txt documents/
.
└── documents/
    └── file1.txt

The file has changed its location. There is no file1.txt in the original location anymore.

Moving files

Let’s create a file, add some content using >, and check it:

touch file1.txt
echo "This is my first file" > file1.txt
ls
cat file1.txt

Now create a directory and check the current structure:

mkdir documents
ls

Now move the file and check the current directory:

mv file1.txt documents/
ls

The file is no longer in the current directory. Check inside documents, and look at its content there too:

cd documents/
ls
cat file1.txt

Moving a directory

mv moves whole folders too, with no extra option needed. Suppose you have:

project/
├── app.txt
└── config.txt
backup/

You can move project inside backup:

mv project backup/
backup/
└── project/
    ├── app.txt
    └── config.txt

Renaming files

This is where mv becomes interesting. Suppose you have old_name.txt and want it to become new_name.txt:

mv old_name.txt new_name.txt
ls

old_name.txt no longer exists; it has become new_name.txt. Same file, same content, same timestamps, just a new label.

Renaming directories

The same idea applies to folders:

mv old_project new_project

old_project and everything inside it is now called new_project. Nothing inside the folder needs to change, only the folder’s own name.

Move and rename in one step

Because mv’s destination can include both a path and a new name, you can relocate and rename a file in a single command. You have report.txt and a documents/ folder. You want it inside documents, renamed to final_report.txt:

mv report.txt documents/final_report.txt

One command does both jobs at once: the file leaves its current folder and arrives in documents already carrying its new name.

How mv reads the destination

The same command does different things depending on what already exists at the destination:

Silent overwrite If the destination is an existing file, mv replaces it without asking, and there is no undo. Use mv -i to be asked first, and double-check the destination name.

cp vs mv

Both use the same source → destination syntax and both can rename on the way. The difference is what happens to the original. A simple way to remember it: cp leaves two, mv leaves one.

cpmv
Original afterwardsstays exactly where it wasno longer exists at the old location
Files at the endtwo independent filesone file
Foldersneeds -rworks directly
Typical usebackups, templatesorganising, renaming

rm · removing files

Program location: /bin/rm. rm removes files (and, with an option, directories).

No Recycle Bin Desktop file managers move deleted files to a Trash. rm doesn’t. Once a file is removed with rm, it is gone; there is no built-in undo.
# before
.
├── file1.txt
└── file2.txt
# after: rm file1.txt
.
└── file2.txt

Removing a single file

Let’s create a file first, add some content, and check it:

touch file1.txt
echo "This file will be removed" > file1.txt
cat file1.txt

Now remove it and check:

rm file1.txt
ls

file1.txt has been permanently deleted.

Removing multiple files, or a pattern

rm file1.txt file2.txt file3.txt    # all three in one go
ls

Using wildcards, you can also remove files that match a pattern:

rm *.txt                            # every file ending in .txt in this folder

The options that change rm’s behaviour

-i · interactive

Asks before deleting each file. Type y + Enter to confirm; anything else cancels.

-f · force

Never asks and hides most errors (e.g. for missing files). Useful in scripts, where no one can answer a prompt.

-r / -R · recursive

Goes inside a directory and removes its files and subfolders, then the directory itself.

Interactive removal with -i

Because rm deletes permanently and without warning by default, it’s easy to remove the wrong file by mistake. The -i (interactive) option makes rm ask for confirmation before deleting each file:

rm -i report.txt

You may see rm: remove regular file 'report.txt'? (or regular empty file when the file is empty). Typing y and pressing Enter confirms the deletion; anything else cancels it. This small habit is one of the easiest ways to avoid an accidental, unrecoverable mistake.

Force removal with -f

The -f (force) option does the opposite of -i: it removes files without asking for confirmation and suppresses most error messages, even for files that don’t normally prompt.

rm -f old_file.txt      # no question, no complaint if it is missing

This is useful in scripts, where no one is available to answer a confirmation prompt. On the command line it also removes your last safety net, so use it deliberately, not out of habit.

Removing directories recursively with -r / -R

The -r option means recursive. Suppose you have:

project/
├── app.txt
└── images/
    ├── logo.png
    └── photo.jpg

To remove the entire project directory:

rm -r project

Linux goes inside the directory and removes its contents and subdirectories.

Make -i a habit One confirmation prompt is a small price for avoiding an unrecoverable mistake. Keep -f for scripts and situations where you are already certain.

The risk of rm -rf

Combine recursive and force and you get:

rm -rf foldername

This deletes a folder and everything inside it without asking at any step. It is one of the most powerful and most dangerous commands in Linux:

  1. 1
    No confirmationA typo in the path is executed immediately.
  2. 2
    No recycle binThe deletion cannot be undone.
  3. 3
    One stray space changes everythingYou meant folder/subfolder, but typed a space before the slash.
A small safety net Modern GNU rm refuses to operate on / itself unless you add --no-preserve-root. Don’t rely on it: rm -rf folder /* would still wipe everything it is allowed to.

Safe removal practices

  • Preview before deleting. Run ls on the exact target first (e.g. ls *.log before rm *.log).
  • Prefer -i for anything important.
  • Avoid -f out of habit. If unsure, run the command without -f first.
  • Be extra careful with wildcards and variables. rm -rf *.log from the wrong folder matches different files; an empty variable in a script can turn rm -rf "$DIR"/* into rm -rf /*.
  • Keep backups of anything irreplaceable. rm never checks whether a copy exists elsewhere.
In the field (FDE) On a customer’s production server you are a guest. Before any delete, run pwd and ls on the target, and take a quick backup (cp -r logs logs.bak or a tarball). Cleaning up disk space is a classic request, and a careless rm -rf there can end a project.

rmdir · removing empty directories

Program location: /bin/rmdir. One very important rule: rmdir can remove only empty directories.

If a directory contains files or other directories, rmdir will not remove it.

syntax
rmdir DIRECTORY
rmdir documents     # removes documents only if it is empty

Removing an empty directory

Suppose you have temp/ and it contains nothing:

rmdir temp                  # temp is empty: removed, no flags needed
ls                          # temp is gone

Because it was empty, rmdir removed it without any extra flags or confirmation.

Removing multiple empty directories

Like mkdir, rmdir can take several directory names in a single command:

rmdir docs images backup    # several empty folders at once

If one of several folders still has something in it, rmdir removes the empty ones and reports an error only for that one; it doesn’t stop the whole command.

Why it refuses non-empty folders

project/
├── notes.txt
└── src/
rmdir project
rmdir: failed to remove 'project': Directory not empty

This is deliberate. rmdir is a safe cleanup command. To remove a directory together with its contents you need rm -r.

rmdirrm -r

Good habit Reach for rmdir when tidying up empty folders, and keep rm -r for when you really mean to delete everything a folder contains.

Key terms

touch
Creates an empty file if it doesn’t exist; on an existing file it only updates the timestamps and leaves the content alone.
mkdir -p
Creates a directory along with any missing parent directories in its path, and does not complain if it already exists.
cp
Copies a file to a new location or name, leaving the original in place. Needs -r to copy directories.
mv
Moves or renames a file or directory. No copy is made; the original location no longer holds it.
rm
Permanently deletes files (no Recycle Bin). With -r it deletes directories and everything inside them.
rm -i
Interactive removal: asks for confirmation before deleting each file.
rm -rf
Recursive, forced removal: deletes a directory tree with no prompts and no undo. Powerful and dangerous.
rmdir
Removes a directory only if it is empty; otherwise it fails with “Directory not empty”.
Wildcard (*)
A pattern character that matches any text in file names, e.g. *.txt matches every file ending in .txt.
Recursive
Applying an operation to a directory, then to everything inside it, then everything inside those, all the way down.

Self-check

Pick an answer. You’ll see right away whether it’s correct and why.

notes.txt contains “Hello”. What does touch notes.txt do?

  1. Empties the file
  2. Creates a second file called notes.txt
  3. Keeps the content and updates the timestamps
  4. Shows an “already exists” error

On an existing file, touch only refreshes the access and modification times.

Nothing exists yet. Which command creates app/src/main in one go?

  1. mkdir -p app/src/main
  2. mkdir app/src/main
  3. touch app/src/main
  4. mkdir -r app/src/main

-p creates any missing parent directories. Without it mkdir fails because app doesn’t exist.

After mv a.txt b.txt, how many of these files exist?

  1. Two: a.txt and b.txt
  2. None
  3. Only a.txt
  4. Only b.txt

mv renames; it doesn’t copy. cp leaves two, mv leaves one.

report.txt already exists. What happens with mv draft.txt report.txt?

  1. mv asks before replacing it
  2. report.txt is silently overwritten by draft.txt
  3. draft.txt is moved inside report.txt
  4. The command fails

If the destination is an existing file, mv overwrites it without warning (unless you use -i).

rmdir project prints “Directory not empty”. How do you remove it with its contents?

  1. rmdir -f project
  2. rm project
  3. rm -r project
  4. mv project /dev

rmdir only removes empty folders. rm -r removes a directory and everything in it.

Why is rm -rf folder / so dangerous?

  1. The space makes / a separate target: the whole file system
  2. It moves the folder to the root
  3. It only deletes hidden files
  4. It asks too many questions

The shell splits on spaces, so rm receives two targets: folder and /.

Which command copies a whole directory?

  1. cp project backup
  2. cp -r project backup
  3. mv -r project backup
  4. mkdir -p project backup

cp skips directories unless you pass -r (recursive).

What does rm -i add?

  1. It deletes faster
  2. It ignores missing files
  3. It deletes folders recursively
  4. It asks for confirmation before each deletion

-i = interactive. Only y confirms; anything else cancels.

All of it, in one sentence

touch and mkdir create, cp duplicates, mv moves or renames, and rm / rmdir delete, permanently, so always look before you remove.
