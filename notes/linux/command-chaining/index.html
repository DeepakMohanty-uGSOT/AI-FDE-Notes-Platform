Essential Commands: Command Chaining

Put several commands on one line, and decide what happens after each one finishes: run the next one anyway, only on success, or only on failure.

Why chain commands?

Making teaBoil water and then pour it in the cup. If the kettle doesn’t work, you don’t pour cold water. Command chaining is that “and then, but only if…” logic for the terminal.

Normally we run commands one at a time:

three separate commands
mkdir project
cd project
touch app.txt

Linux lets us put them together on one line:

mkdir project && cd project && touch app.txt

This is command chaining. The operator between two commands decides whether the next command should run.

; · anyway

Run the next command no matter what happened before.

&& · on success

Run the next command only if the previous one succeeded.

|| · on failure

Run the next command only if the previous one failed.

How does Linux know “success”? Every command finishes with an exit status: 0 means success, anything else means failure. See the last one with echo $?.

; · run commands one after another

Sometimes we just want to say: “Run this, then run that. I don’t care whether the first one worked.”

syntax
command1 ; command2

Try it

mkdir chaining_practice
cd chaining_practice
mkdir project ; echo "Done"

Now run the same line again:

mkdir failed because the folder already exists, but echo "Done" still ran. That is exactly what ; means.

mkdir projectFAIL;echo "Done" runs

&& · run only if the previous command succeeds

Now we have a different requirement: create a directory → enter it → create a file. If creating the directory fails, we don’t want to continue.

syntax
command1 && command2      # command2 runs only if command1 succeeds

See both outcomes

mkdir project2 && cd project2     # works: you are now inside project2
pwd                                 # check where you are
cd ..                               # go back
mkdir project2 && echo "Created"   # fails: project2 exists, so "Created" never prints
mkdir project2SUCCESScd project2 runs
mkdir project2FAIL&& → STOP

Several && in a row

mkdir project3 && cd project3 && touch app.txt

Each command now depends on the one before it. The chain stops at the first failure.

Situationmkdir project3cd project3touch app.txt
Everything works✅ success✅ runs✅ runs
First command fails❌ fail⛔ not run⛔ not run
Second command fails✅ success❌ fail⛔ not run
mkdir ✓cd ✗touch app.txt
Why this matters Without &&, a failed cd would leave you in the wrong folder, and the next command (say, a delete) would run there. && keeps a broken step from causing damage further down.

|| · run only if the previous command fails

Sometimes we want: “Try the first command. If it fails, do something else.” That is a fallback.

syntax
command1 || command2      # command2 runs only if command1 fails
cd /wrong/path || echo "Directory not found"
cd /wrong/pathFAILecho runs
cd /tmpSUCCESS|| → STOP (echo skipped)

The three operators, side by side

OperatorNext command runs when…Read it asTypical use
;always“then”independent steps
&&previous succeeded (exit 0)“and then, if OK”steps that depend on each other
||previous failed (exit ≠ 0)“or else”fallbacks and error messages

Combining chains

You can mix operators to get an “if it worked / if it didn’t” pattern:

mkdir reports && echo "Folder created" || echo "Could not create folder"
  1. 1
    mkdir succeeds&& lets echo "Folder created" run. That echo succeeds, so || skips the last part.
  2. 2
    mkdir fails&& skips the first echo; the failure reaches ||, so “Could not create folder” prints.
Careful: it is not a true if/else. In A && B || C, C also runs if B fails. When the middle step can fail, use a real if statement in a script.

A practical workflow

Set up a project folder, enter it, create starter files and confirm, stopping at the first problem:

One line, safe at every step

mkdir -p ~/apps/demo && cd ~/apps/demo && touch app.py README.md && ls -l || echo "Setup failed. Check the step above."
In the field (FDE) Deploy scripts on customer servers lean on this all the time, e.g. git pull && pip install -r requirements.txt && systemctl restart app. If the pull fails, nothing restarts on half-updated code.

Key terms

Command chaining
Writing several commands on one line, joined by operators that control whether each next command runs.
Exit status
The number a command returns when it finishes: 0 = success, non-zero = failure. Shown by echo $?.
; (semicolon)
Runs the next command regardless of whether the previous one succeeded.
&& (AND operator)
Runs the next command only if the previous command succeeded.
|| (OR operator)
Runs the next command only if the previous command failed. Used for fallbacks.

Self-check

Pick an answer. You’ll see right away whether it’s correct and why.

Which operator runs the next command no matter what?

  1. ;
  2. &&
  3. ||
  4. |

; just runs commands in sequence and ignores success or failure.

project2 already exists. What does mkdir project2 && echo "Created" print?

  1. Only “Created”
  2. Only the mkdir error
  3. The error and then “Created”
  4. Nothing at all

mkdir fails and prints its error, so && stops the chain. “Created” never runs.

In mkdir a && cd a && touch x, the cd fails. What happens to touch x?

  1. It runs in folder a
  2. It runs in the current folder
  3. It does not run
  4. It runs twice

Every && needs the step before it to succeed. The chain stops at the first failure.

You want a message only when cd /data fails. Which line is right?

  1. cd /data ; echo "missing"
  2. cd /data && echo "missing"
  3. echo "missing" || cd /data
  4. cd /data || echo "missing"

|| runs the right-hand side only when the left-hand side fails.

What exit status means “success”?

  1. 1
  2. 0
  3. -1
  4. Any positive number

0 means success; any non-zero value means some kind of failure.

In A && B || C, when does C run?

  1. Only when A fails
  2. Only when B fails
  3. When A fails, or when A succeeds but B fails
  4. Never

C sees the result of whatever ran last. A failure in either A or B reaches ||, so this is not a true if/else.

All of it, in one sentence

; means then, anyway, && means then, only if it worked, and || means otherwise. Together they let one line of shell run a whole workflow safely.
