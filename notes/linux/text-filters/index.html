Essential Commands: Text Filters

Count, sort, de-duplicate, slice and transform text with five tiny tools: wc, sort, uniq, cut and tr.

Why text filters matter

The rule of Linux: almost everything is text. The settings that run the system are text files. The diaries the system keeps (logs) are text. Even the answers you get after typing a command are just text.

The problem: information overload. Those files grow huge. Finding one error in tens of thousands of lines by reading is simply not possible.

The solution: text filters, small programs that act like smart reading assistants. They take a big chunk of text, process it (search, sort, chop it up) according to your instructions, and hand back only the pieces you care about.

The water filterTap water goes in, the filter cleans it, clean water comes out. The filter doesn’t make water; it only changes what passes through. A text filter takes text in, processes it, and prints the result. It never creates text of its own.

1. Takes text

From a file, or from another command through a pipe |.

2. Processes it

Counts, sorts, removes duplicates, cuts out parts, or swaps characters.

3. Shows the result

Prints to the screen. Your original file stays untouched.

wc · measure your text

wc stands for word count, but that name is modest. Think of it as a quick measuring tape for text: it counts lines, words, characters and bytes.

syntax
wc filename
file1.txt
Linux is powerful
Linux is secure
Linux is fast
wc file1.txt
 3  9 48 file1.txt
3 9 48 file1.txt

lines

words

bytes (17 + 15 + 13 visible characters, plus one invisible newline at the end of each line)

file name

The invisible newline Every time you press Enter, the file stores a hidden newline character (\n). It counts as one character and one byte. That is why byte counts are a little bigger than the letters you can see.

Counting one thing at a time

Options make wc print just one number:

OptionCountsSample fileCommandOutput
-llines (how many times Enter was pressed)todo.txt: Buy milk / Clean room / Call Momwc -l todo.txt3 todo.txt
-wwords (groups of characters separated by spaces)note.txt: Linux is very coolwc -w note.txt4 note.txt
-mcharacters (letters, digits, spaces, punctuation, newlines)hi.txt: Hello World!wc -m hi.txt13 hi.txt
-cbytes (how much space the text takes)data.txt: Hello worldwc -c data.txt12 data.txt

Hello World! has 12 visible characters (H-e-l-l-o, a space, W-o-r-l-d, !). wc -m says 13 because the newline at the end of the line counts too. Likewise Hello world is 10 letters and a space: 11 visible characters + newline = 12 bytes.

Characters vs bytes

They are not always a 1-to-1 match. One character on screen can need several bytes of storage.

Normal English text

A, b, 7, !, space: 1 character = 1 byte, so -m and -c agree.

Special text

Accented letters, Hindi script, symbols and emojis (😀) take 2 to 4 bytes each in UTF-8, so -c is bigger than -m.

echo "😀" | wc -m     # 2  (the emoji + newline)
echo "😀" | wc -c     # 5  (4 bytes for the emoji + 1 for newline)

wc with several files and with pipes

Several files at once

Like putting items on a weighing scale one by one and reading the total at the end:

wc file1.txt file2.txt
  10   50  300 file1.txt
  20   70  500 file2.txt
  30  120  800 total

Each file gets its own row (lines, words, bytes), and the last row, total, adds them up.

With a pipe |

The pipe acts like a tunnel that sends one command’s output straight into wc to be counted:

command|wcresult

How many items are in this folder?

ls | wc -l
  1. 1
    lslists your files, one per line when sent into a pipe.
  2. 2
    |sends that list to the counter instead of the screen.
  3. 3
    wc -lcounts the lines, and each line is one file.
file.txt

cat file.txt | wc -w

cat reads the text, | sends it through the tunnel, and wc -w counts every word. When wc reads from a pipe, it prints no file name.

sort · put lines in order

Data usually arrives in a messy, first-come-first-served order: names, prices, log events, user IDs. sort is the “Sort A to Z” button for your command line.

syntax
sort filename
names.txt
Zebra
Apple
Monkey
Banana
sort names.txt
Apple
Banana
Monkey
Zebra

Human readability

Finding “Banana” in an alphabetical list is much easier than in a random one.

Other tools need it

Many Linux tools, like uniq below, only work properly on sorted data.

Numbers, reverse and unique: -n, -r, -u

Numeric sort -n

Plain sort compares text character by character, so it thinks 10 comes before 2 (because “1” comes before “2”). -n tells it to compare whole numbers by value.

sort numbers.txt       # 1 10 2 50  (text order)
sort -n numbers.txt    # 1 2 10 50  (numeric order)

Reverse sort -r

Flips the order: Z to A, or 10 to 1.

fruits.txt
Apple
Banana
Cherry
sort -r fruits.txt
Cherry
Banana
Apple

Combine them: -nr

Options can be joined. Largest number first, e.g. prices from most to least expensive:

points.txt
10
50
25
sort -nr points.txt
50
25
10

Sort and remove duplicates: -u

If a line appears three times, -u (unique) keeps it once. The fastest way to get a clean list.

members.txt
Alice
Bob
Alice
Charlie
Bob
sort -u members.txt
Alice
Bob
Charlie

Useful for email lists and usernames, and combined with wc it counts unique people:

sort -u members.txt | wc -l
3

uniq · remove repeated lines

uniq is a duplicate remover, with one important rule: uniq only removes duplicates that are consecutive, right next to each other.

list.txt
apple
apple
banana
apple
uniq list.txt
apple
banana
apple
sort list.txt | uniq
apple
banana

Alone, uniq merged the first two apples (they were touching) but missed the third. That is why you almost always write sort file | uniq.

Count duplicates with -c

-c puts a counter in front of each line showing how many copies were found:

fruits.txt
apple
apple
banana
banana
uniq -c fruits.txt
      2 apple
      2 banana
Messy file? Sort first. uniq -c on unsorted data gives several small counts for the same word. Use sort file | uniq -c.
In the field (FDE) “Which IPs hit the API most?” cut -d ' ' -f1 access.log | sort | uniq -c | sort -nr | head gives a ranked top 10 in one line. You’ll use this sort → uniq -c → sort -nr pattern constantly when reading customer logs.

cut · extract part of every line

cut extracts specific parts of text. Instead of showing whole lines, it cuts out only the portion you need, from every line.

syntax
cut [option] filename     # option says which part to keep
cut -c 3 file.txt         # -c = character position: the 3rd character of each line
file.txt
Apple
Banana
Cherry
cut -c 3 file.txt
p
n
e

Apple → 3rd character p; Banana → n; Cherry → e.

Counting positions

Positions start at 1, not 0. Here is how cut -c sees the line HELLOWORLD:

Single position, range, and open ranges

emp.txt

PROGRAMMING
cut -c 9 emp.txt       # the 9th character

T
I
cut -c 5-9 emp.txt     # characters 5 to 9
OWORL
XSYST
RAMMI

The 9th characters: HELLOWORLD → L, LINUXSYSTEM → T, PROGRAMMING → I.

FormMeaningOn HELLOWORLDOutput
cut -c 3one positioncut -c 3 text.txtL
cut -c 5-9from 5 to 9cut -c 5-9 text.txtOWORL
cut -c 5-from 5 to the end of the linecut -c 5- text.txtOWORLD
cut -c -3from the start up to 3cut -c -3 text.txtHEL
cut -c 3-5,7-10several ranges, joinedcut -c 3-5,7-10 text.txtLLOORLD

The last one: characters 3–5 are LLO, characters 7–10 are ORLD, and both are printed together: LLO + ORLD = LLOORLD.

Columns, not just characters For data with separators (CSV, /etc/passwd), use -d for the delimiter and -f for the field number: cut -d ',' -f 2 users.csv prints the 2nd comma-separated column; cut -d ':' -f 1 /etc/passwd lists every username.

tr · translate characters

tr stands for translate. It reads text, changes characters, and prints the result. It does not change the original file.

Replace

Every a becomes 4.

Convert

lowercase → UPPERCASE.

Delete -d

Remove symbols or digits.

Squeeze -s

“helloooooo” → “hello”.

syntax
tr [options] SET1 SET2    # characters in SET1 are replaced by the matching characters in SET2
JobCommandOutput
Replace one character (a → o)echo "apple" | tr 'a' 'o'opple
Replace h → Hecho "hello" | tr 'h' 'H'Hello
Replace several (e→E, o→O)echo "hello" | tr 'eo' 'EO'hEllO
Lowercase → uppercaseecho "linux" | tr 'a-z' 'A-Z'LINUX
Uppercase → lowercaseecho "LINUX" | tr 'A-Z' 'a-z'linux
Delete digitsecho "hello123" | tr -d '0-9'hello
Delete spacesecho "hello world" | tr -d ' 'helloworld
Squeeze repeatsecho "hellooooo" | tr -s 'o'hello

echo "apple" prints the word, the pipe hands it to tr 'a' 'o', and every a becomes o: apple → opple. Ranges like a-z mean “all 26 lowercase letters”, so tr 'a-z' 'A-Z' is a Caps Lock converter. Lowercasing is handy for standardising data so “Apple” and “apple” are treated the same.

tr takes no file name Unlike the other filters, tr only reads its input stream. Feed it with a pipe (cat names.txt | tr 'a-z' 'A-Z') or with input redirection (tr 'a-z' 'A-Z' < names.txt). tr 'a-z' 'A-Z' names.txt is an error.

The five filters at a glance

FilterJobKey options
wcmeasure text-l lines, -w words, -m characters, -c bytes
sortorder lines-n numeric, -r reverse, -u unique
uniqcollapse adjacent duplicates-c count (sort first!)
cutkeep part of each line-c positions, -d + -f fields
trchange characters-d delete, -s squeeze

Each one is small, but chained with | they become powerful:

cat words.txt | tr 'A-Z' 'a-z' | sort | uniq -c | sort -nr | head -n 5   # top 5 words, case-insensitive

Key terms

Text filter
A small program that takes text as input, processes it, and prints the result without changing the original source.
wc
Word count: prints the number of lines, words and bytes in text; -l, -w, -m and -c select lines, words, characters or bytes.
Newline
The invisible character (\n) stored each time a line ends. It counts as one character and one byte in wc.
Characters vs bytes
A character is one visible symbol; a byte is a unit of storage. English letters use 1 byte, but emojis and many scripts use 2 to 4 bytes per character.
sort
Prints lines in order: alphabetical by default, numeric with -n, reversed with -r, and de-duplicated with -u.
uniq
Collapses consecutive identical lines into one; -c shows how many copies there were. Usually used after sort.
cut
Extracts part of every line: by character position with -c, or by field with -d (delimiter) and -f (field number).
tr
Translate: replaces characters in SET1 with those in SET2, deletes with -d, or squeezes repeats with -s. Reads only from its input stream.
Pipe (|)
Sends the output of one command directly into the input of the next, so filters can be chained.

Self-check

Pick an answer. You’ll see right away whether it’s correct and why.

Which command tells you how many lines are in app.log?

  1. wc -w app.log
  2. wc -l app.log
  3. wc -c app.log
  4. sort -l app.log

-l counts lines; -w counts words; -c counts bytes.

A file holds 10, 2, 50, 1 (one per line). What does plain sort print?

  1. 1 2 10 50
  2. 50 10 2 1
  3. 10 2 50 1
  4. 1 10 2 50

Without -n, sort compares text character by character, so “10” comes before “2”.

Why do we usually write sort file | uniq instead of just uniq file?

  1. uniq only removes duplicates that are next to each other
  2. uniq can’t read files
  3. sort makes uniq faster but isn’t needed
  4. uniq deletes the file otherwise

uniq compares each line with the one before it. Sorting brings identical lines together.

What does cut -c 2-4 print for the line LINUX?

  1. LIN
  2. NUX
  3. INU
  4. IN

Positions start at 1: L1 I2 N3 U4 X5. Characters 2 to 4 are I, N, U.

What is the output of echo "banana" | tr 'a' 'o'?

  1. bonana
  2. bonono
  3. banana
  4. bnn

tr replaces every matching character, not just the first.

wc -m and wc -c give different numbers for a file. What is the most likely reason?

  1. The file is corrupted
  2. The file has blank lines
  3. wc counts spaces only in -m
  4. The file contains characters that take more than one byte, like emojis

-m counts characters and -c counts bytes. They match only when every character is 1 byte.

Which shows the highest score first from a file of numbers?

  1. sort -nr scores.txt
  2. sort -r scores.txt
  3. sort -u scores.txt
  4. uniq -c scores.txt

-n compares by value and -r reverses, so the biggest comes first. -r alone would compare as text.

Which command removes all digits from text?

  1. tr -s '0-9'
  2. cut -c 0-9
  3. tr -d '0-9'
  4. sort -u

tr -d deletes every character in the set; -s only squeezes repeats.

All of it, in one sentence

Text filters take text in and print a processed version: wc measures it, sort orders it, uniq removes adjacent repeats, cut keeps just the part you need, and tr swaps or deletes characters.
