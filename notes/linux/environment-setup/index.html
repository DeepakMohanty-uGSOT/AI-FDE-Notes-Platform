Environment Setup

Launch your own Ubuntu server on AWS, connect to it securely over SSH from your laptop, and run your first Linux commands on a real cloud machine.

Linux in the cloud: what is AWS?

You can run Linux on your own computer inside a virtual machine (for example with VirtualBox). In this note we do it the way companies do: on AWS, a cloud platform. Instead of running Linux on your laptop, you run it on a remote machine in the cloud that you can reach from anywhere over the internet.

Booking a cab instead of buying a carYou don’t need to own a car to get across the city; you book an Ola or Uber, use it for as long as you need, and pay only for that. AWS lets you “book” a computer on the internet in the same way: pick the size, use it, and switch it off when you’re done.

AWS (Amazon Web Services) is a cloud computing platform that lets you create and use virtual computers over the internet. These virtual computers are called instances. An instance behaves like a real computer with its own CPU, RAM, storage and operating system, but it runs on Amazon’s infrastructure instead of your machine. In simple words: a computer that lives on the internet.

Why use AWS, and what is EC2?

No powerful laptop needed

The heavy lifting happens on Amazon’s hardware.

Access from anywhere

Reach your Linux machine from any computer with internet.

Safe to experiment

Break something? Stop it, restart it, or create a fresh instance in minutes.

What companies use

Most real-world production systems run in the cloud. Essential for cloud, DevOps, IT and FDE roles.

The AWS service that gives you virtual machines is EC2 (Elastic Compute Cloud). With EC2 you can:

    Launch a Linux serverSuch as Ubuntu, in a few clicks.
  2. 2
    Connect to it using SSHA secure, encrypted remote terminal.
  3. 3

Create your AWS account

Signing up takes about ten minutes. Follow the screens in order.

Step 1 · Visit the AWS website

Open your web browser and go to the AWS website: https://aws.amazon.com/.

Step 2 · Create an AWS account

On the AWS homepage, look for the Create an AWS Account button and click it to begin the account creation process.

Step 3 · Enter your email address

Provide an email address you have access to: AWS sends important account information there. Also choose an AWS account name.

Verify your email address. AWS emails you a verification code; enter it on the next screen.

Next, create your password.

Step 4 · Fill in your personal information

AWS asks for basic information to set up your account: your name, company name (if applicable) and contact details. Don’t worry, this information is kept secure.

Step 5 · Payment information (no worries!)

To create an AWS free account you must provide payment information. It may seem intimidating, but AWS needs it to verify your identity and prevent misuse of the free tier. You won’t be charged unless you exceed the free-tier limits.

Step 6 · Identity verification

AWS checks that you’re a real person. Choose to receive a text message (SMS) or a voice call with a verification code, fill in your mobile number and the security check, and click Send SMS.

Then enter the verification code you receive on your phone:

Finally, answer a few identity questions: is the account for personal or business use, and is the ownership type individual or a group?

Step 7 · Choose a support plan (select the free plan)

AWS offers several support plans, including a free basic plan. Choose Basic support – Free unless you need more. No charge here either.

Step 8 · Welcome to AWS

Congratulations! Your AWS free account is created. You’ll see a welcome message, and AWS will guide you through setting up your first resources.

Step 9 · Explore the AWS Management Console

Once logged in, you land in the AWS Management Console, the control centre for all your AWS resources. Don’t worry if it looks overwhelming at first. Take your time to explore the services and features.

This is your AWS Console dashboard. Let’s explore the services.

Protect your wallet Set up a billing alert / budget in the console on day one, and stop instances when you’re not using them. Free-tier limits are real, and a forgotten machine keeps billing.

Launch an EC2 instance: name, image and size

Step 1 · Sign in to the AWS Management Console

Sign in with your AWS account credentials. (No account yet? Create one first, as shown above.)

Step 2 · Open the EC2 console

Search for EC2 in the services search bar and click EC2 in the results. This opens the EC2 console, where you manage your instances.

Step 3 · Launch instance

In the EC2 console, click the Launch instance button to start creating the instance. One page then takes you through the settings step by step.

After clicking it, you are taken to the Launch an instance page shown below.

Step 4 · Give the instance a name

A meaningful name makes the instance easy to identify and manage later. Here, enter aws_instance.

Step 5 · Choose an Amazon Machine Image (AMI)

An AMI is a pre-configured template containing the operating system and other software your instance needs. You can choose from many AMIs provided by AWS or the AWS Marketplace; pick the one that suits you. Here, choose Ubuntu.

Step 6 · Choose an instance type

The instance type is the “power” of the computer that runs your project: processing power, memory and network. Pick what fits your needs. For example, t2.micro is part of the AWS Free Tier, offering free usage within certain limits. (In regions where t2.micro isn’t offered, the free-tier type is t3.micro.)

Step 7 · Create a key pair (your login key)

To connect securely you need a key pair with two halves: a public key stored by AWS on the instance, and a private key that you download to your computer. You use the private key to log in. The server checks that it matches its public key, and no password travels over the internet.

You can select an existing key pair if you already have one, or create a new one by clicking Create new key pair.

A dialog box appears. Give your key pair a unique name, select the key pair type RSA, and choose the private key file format .pem. Finally, click Create key pair. The .pem file downloads immediately into the Downloads folder on your PC.

You can download it only once AWS does not keep a copy of your private key. Lose the .pem file and you can’t log in with that key. Never share it or commit it to Git.

Step 8 · Network, storage, firewall, then launch

Next, set up the remaining settings for what you need. All of them can be changed later, and for now you can leave them as they are.

Instance details

How many instances to launch, the network settings and VPC (Virtual Private Cloud), an optional role, and detailed monitoring if you want to track performance.

Storage

AWS uses EBS (Elastic Block Store) for permanent disks. Decide how much storage you need, the performance you expect, and whether to encrypt it.

Security group

Acts like a firewall: rules that control which traffic is allowed to reach your instance. SSH needs port 22 open.

On the right side of the launch page, the Summary section gives a consolidated view of every setting you chose, so you can review and verify them before launching.

Step 9 · Review and launch

Review the configuration: double-check the instance type, storage options, security group and any other settings. If everything looks good, click Launch instance.

After launching, a success message appears. Click the instance ID to see your instances; here it is i-03e9b83d4f0e3d0a9.

Clicking the instance ID takes you to the EC2 Instances page, where you can see the details of your instances and manage them.

This page shows full information about each instance: its status, instance type, public IP address and more. From here you can start, stop, terminate or modify your instances as you need.

In the field (FDE) On customer projects, the security group is often the first thing to check when “the server is unreachable”. Lock SSH (port 22) down to your IP rather than 0.0.0.0/0 (anyone), and open only the ports your app really needs, such as 443 for HTTPS.
Stop vs terminate Stop switches the machine off; its disk is kept and you can start it again. Terminate deletes the instance for good.

Step 10 · Connect to your instance with SSH

With the instance running, connect to it from your own computer using SSH (Secure Shell). SSH lets you access and control your cloud server remotely and securely, just as if you were working on a local Linux machine. Follow the steps below to establish the connection.

10.1 · Open the EC2 Instances page

Go to the AWS Management Console → Services → EC2 → Instances. You’ll see your running instance in the list. Find it by its instance ID (for example i-03e9b83d4f0e3d0a9).

Click the instance ID to open the detailed view. It shows the important information: the instance state (Running), the public IPv4 address, the public DNS name, the instance type and the security settings.

10.2 · Click the Connect button

On the instance details page, click Connect at the top right.

The Connect to instance window offers several connection options: EC2 Instance Connect, Session Manager, SSH client and EC2 Serial Console. Select the SSH client tab.

10.3 · Copy the SSH command

Under the SSH client tab, AWS shows an example SSH command:

ssh -i "aws_key.pem" ubuntu@ec2-13-203-160-58.ap-south-1.compute.amazonaws.com

The command contains:

ssh -i "aws_key.pem" ubuntu@ec2-13-203-160-58.ap-south-1.compute.amazonaws.com

ssh: the Secure Shell command.

-i "aws_key.pem": your private key file (the identity file).

ubuntu: the default username on Ubuntu instances.

ec2-13-203-160-58…amazonaws.com: the public DNS name of your instance. Its public IP (13.203.160.58) works the same way.

Copy this complete command.

10.4 · Go to the folder with your .pem file

The .pem file is the private key you downloaded when creating the instance, for example in C:\Users\Deepak\Downloads. Open Command Prompt and move to that folder:

cd Downloads

Or navigate to whichever folder holds your .pem file. (On macOS or Linux, use Terminal the same way.)

10.5 · Connect using SSH

Paste the copied SSH command into Command Prompt and press Enter:

On your laptop (Command Prompt)

ssh -i "aws_key.pem" ubuntu@ec2-13-203-160-58.ap-south-1.compute.amazonaws.com

On the first connection you are asked Are you sure you want to continue connecting (yes/no)? Type yes and press Enter.

10.6 · Successful connection

Once connected, you see Ubuntu’s welcome banner (“Welcome to Ubuntu 24.04 LTS…”, matching the AMI you chose) and then the server’s prompt, ubuntu@ip-172-31-XX-XXX:~$. Your local computer is now securely connected to the EC2 instance, and you can run Linux commands directly on your cloud server.

“Permissions are too open”? SSH refuses a private key that other users can read. On macOS/Linux run chmod 400 aws_key.pem first. On Windows, make sure only your user account has access to the file.

10.7 · Your first commands on the server

Now that you’re connected, you can start running Linux commands. These basic commands help you interact with the system, manage files and understand your environment.

CommandWhat it does
clearClears the screen, leaving just the prompt.
lsLists files and folders in the current directory.
whoamiShows the username you are logged in as.
pwdPrints your present working directory (where you are).
historyLists the commands you ran before.

clear · a clean workspace

clear

It removes all the previous text from the terminal, giving you a clean workspace. Afterwards only the prompt is visible.

ls · list files and directories

ls

It lists all files and folders in the current directory. If nothing is shown, the directory is empty, which is normal on a brand-new instance.

whoami · who am I logged in as?

whoami

It shows the username of the logged-in user. This confirms you are the default Ubuntu user.

pwd · where am I?

pwd

It shows your current location (directory) in the system: you are inside the ubuntu user’s home directory.

history · what did I run?

history

It shows the list of previously executed commands, which helps you track and reuse them. (cal prints a small calendar and date the current date and time; if cal is missing, install it with sudo apt install ncal.)

Shortcut Press ↑ to bring back the previous command, or run !3 to re-run command number 3 from the history list.

What this means: the full picture

Your local computer is now a client, and the EC2 instance is a remote Linux server. The architecture from the previous note now stretches across the internet:

You are now working inside a real Linux environment hosted in the cloud, exactly how servers are run in industry.

Key terms

AWS
Amazon Web Services, a cloud platform that rents out computing resources such as virtual machines, storage and networking over the internet.
EC2
Elastic Compute Cloud, the AWS service for creating and running virtual machines (instances).
Instance
A virtual computer in the cloud with its own CPU, RAM, storage and operating system.
AMI
Amazon Machine Image, a pre-configured template (operating system plus software) used to create an instance, e.g. Ubuntu.
Instance type
The size of an instance (CPU, memory, network), such as t2.micro; it decides performance and cost.
Key pair
A public key stored on the instance and a private key (.pem) kept by you; together they let you log in securely without a password.
SSH
Secure Shell, an encrypted protocol for logging in to and controlling a remote machine from a terminal.
Security group
A virtual firewall in AWS that controls which network traffic (ports and sources) can reach an instance.
EBS
Elastic Block Store, the persistent disk storage attached to EC2 instances.
VPC
Virtual Private Cloud, your own isolated network inside AWS where instances run.
Client and server
The client (your laptop) sends requests; the server (the EC2 instance) receives them and does the work.
Home directory
A user’s personal folder, such as /home/ubuntu, where you land after logging in.

What is an EC2 instance?

  1. A file you download from AWS
  2. A virtual computer running in the AWS cloud
  3. A type of SSH key
  4. A billing plan

EC2 instances are virtual machines with their own CPU, RAM, storage and OS, hosted on Amazon’s hardware.

Which choice decides the operating system of your new instance?

  1. Instance type
  2. Security group
  3. AMI
  4. Key pair

The AMI is the template that contains the OS (e.g. Ubuntu) and pre-installed software.

In ssh -i "aws_key.pem" ubuntu@ec2-…amazonaws.com, what is ubuntu?

  1. The username to log in as
  2. The key file name
  3. The AWS region
  4. The instance ID

The part before @ is the user; ubuntu is the default user on Ubuntu AMIs.

You lost your .pem file. What is true?

  1. Download it again from the EC2 console
  2. AWS emails it to you
  3. Any other .pem file will work
  4. AWS doesn’t keep a copy, so that key can’t be recovered

The private key is downloaded once. Keep it safe, and never share or commit it.

Your SSH connection times out. Which AWS setting should you check first?

  1. The AMI
  2. The security group rules for port 22
  3. The instance name
  4. The support plan

The security group is the instance’s firewall. If port 22 isn’t open to your IP, SSH can’t reach the server.

Right after logging in, pwd prints /home/ubuntu. What does that tell you?

  1. You are the root user
  2. The disk is empty
  3. You are in the ubuntu user’s home directory
  4. SSH failed

pwd shows your current directory; after login you start in your home directory.

Which is an advantage of the cloud setup over a local VirtualBox VM?

  1. You can reach it from anywhere and resize it by changing the instance type
  2. It works with no internet at all
  3. It uses your laptop’s RAM
  4. It never costs anything, whatever you run

Cloud instances are accessible from anywhere and scale easily, but they need internet and can incur charges beyond the free tier.
