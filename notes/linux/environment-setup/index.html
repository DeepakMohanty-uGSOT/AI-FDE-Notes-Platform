Environment Setup

Launch your own Ubuntu server on AWS, connect to it securely over SSH from your laptop, and run your first Linux commands on a real cloud machine.

Linux in the cloud: what is AWS?

You can run Linux on your own computer inside a virtual machine (for example with VirtualBox). In this note we do it the way companies do: on AWS, a cloud platform. Instead of running Linux on your laptop, you run it on a remote machine in the cloud that you can reach from anywhere over the internet.

Booking a cab instead of buying a carYou don’t need to own a car to get across the city; you book an Ola or Uber, use it for as long as you need, and pay only for that. AWS lets you “book” a computer on the internet in the same way: pick the size, use it, and switch it off when you’re done.

AWS (Amazon Web Services) is a cloud computing platform that lets you create and use virtual computers over the internet. These virtual computers are called instances. An instance behaves like a real computer with its own CPU, RAM, storage and operating system, but it runs on Amazon’s infrastructure instead of your machine. In simple words: a computer that lives on the internet.

Why use AWS, and what is EC2?

No powerful laptop needed

The heavy lifting happens on Amazon’s hardware.

Access from anywhere

Reach your Linux machine from any computer with internet.

Safe to experiment

Break something? Stop it, restart it, or create a fresh instance in minutes.

What companies use

Most real-world production systems run in the cloud. Essential for cloud, DevOps, IT and FDE roles.

The AWS service that gives you virtual machines is EC2 (Elastic Compute Cloud). With EC2 you can:

  1. 1
    Launch a Linux serverSuch as Ubuntu, in a few clicks.
  2. 2
    Connect to it using SSHA secure, encrypted remote terminal.
  3. 3
    Run Linux commandsExactly as you would on a normal computer.

Launch an EC2 instance: name, image and size

  1. 1
    Sign in to the AWS Management ConsoleUse your AWS account credentials.
  2. 2
    Open the EC2 consoleType EC2 in the services search bar and click it. This is where you manage your instances.
  3. 3
    Click “Launch instance”This opens a single page where you configure the new machine step by step.
  4. 4
    Give it a nameA meaningful name makes it easy to find later. Here: aws_instance.
  5. 5
    Choose an Amazon Machine Image (AMI)An AMI is a pre-configured template containing the operating system and software for your instance, from AWS or the AWS Marketplace. Choose Ubuntu.
  6. 6
    Choose an instance typeThis is the “power” of the computer: CPU, memory and network. Pick one marked Free tier eligible, such as t2.micro (or t3.micro in regions where that is the free-tier type).

Create a key pair (your login key)

To connect securely you need a key pair with two halves: a public key that AWS places on the instance, and a private key that you download and keep. When you log in, the server checks that your private key matches its public key. No password travels over the internet.

  1. 1
    Choose or createSelect an existing key pair, or click Create new key pair.
  2. 2
    Name it and pick the formatGive it a unique name, set the type to RSA and the private key file format to .pem.
  3. 3
    Create key pairThe .pem file downloads immediately, usually into your Downloads folder.
You can download it only once AWS does not keep a copy of your private key. Lose the .pem file and you can’t log in with that key. Never share it or commit it to Git.

Network, storage, firewall, then launch

Next, adjust the remaining settings. All of them can be changed later, and the defaults are fine for learning.

Instance details

How many instances to launch, the network and VPC (Virtual Private Cloud), an optional IAM role, and detailed monitoring if you want performance graphs.

Storage

AWS uses EBS (Elastic Block Store) for permanent disks. Choose size, performance type and whether to encrypt it.

Security group

Acts like a firewall: rules that decide which network traffic may reach your instance. SSH needs port 22 open.

On the right of the launch page, the Summary panel shows all your choices in one place so you can check them.

Review and launch

Double-check the instance type, storage, security group and any extra settings, then click Launch instance. A success message appears with your new instance ID, for example i-03e9b83d4f0e3d0a9. Click it to open the Instances page, which shows each instance’s state, type, public IP address and more. From there you can start, stop, terminate or modify instances.

In the field (FDE) On customer projects, the security group is often the first thing to check when “the server is unreachable”. Lock SSH (port 22) down to your IP rather than 0.0.0.0/0 (anyone), and open only the ports your app really needs, such as 443 for HTTPS.
Stop vs terminate Stop switches the machine off; its disk is kept and you can start it again. Terminate deletes the instance for good.

Connect to your instance with SSH

SSH (Secure Shell) lets you securely control a remote server from your own computer, just as if you were sitting at a local Linux machine.

  1. 1
    Open the Instances pageAWS Console → EC2 → Instances. Find your instance by its ID and click it. You’ll see the instance state (Running), public IPv4 address, public DNS name, instance type and security settings.
  2. 2
    Click “Connect”At the top right. The Connect to instance window offers EC2 Instance Connect, Session Manager, SSH client and EC2 Serial Console. Choose the SSH client tab.
  3. 3
    Copy the SSH commandAWS shows a ready-made example command. Copy it.
  4. 4
    Go to the folder with your .pem fileOpen Command Prompt (Windows) or Terminal (macOS/Linux) and cd to where the key is, e.g. C:\Users\Deepak\Downloads.
  5. 5
    Paste the command and press EnterOn the first connection, type yes to trust the server.
  6. 6
    You’re inThe prompt changes to the server’s prompt.

The SSH command, piece by piece

ssh -i "aws_key.pem" ubuntu@13.203.160.58

ssh: the Secure Shell command.

-i "aws_key.pem": the identity file, your private key.

ubuntu: the default username on Ubuntu instances.

13.203.160.58: your instance’s address. AWS’s example uses the public DNS name (ec2-13-203-160-58.ap-south-1.compute.amazonaws.com); the public IP works the same.

On your laptop (Command Prompt)

cd Downloads
ssh -i "aws_key.pem" ubuntu@ec2-13-203-160-58.ap-south-1.compute.amazonaws.com
The authenticity of host 'ec2-13-203-160-58.ap-south-1.compute.amazonaws.com' can't be established.
ED25519 key fingerprint is SHA256:...
Are you sure you want to continue connecting (yes/no/[fingerprint])? yes

Once connected you’ll see a welcome banner and the server’s prompt:

Welcome to Ubuntu 22.04 LTS
...
ubuntu@ip-172-31-XX-XXX:~$

Your laptop is now securely connected to the EC2 instance. Every command you type from here runs on the cloud server.

“Permissions are too open”? SSH refuses a private key that other users can read. On macOS/Linux run chmod 400 aws_key.pem first. On Windows, make sure only your user account has access to the file.

What this means: the full picture

Your local computer is now a client, and the EC2 instance is a remote Linux server. The architecture from the previous note now stretches across the internet:

You are now working inside a real Linux environment hosted in the cloud, exactly how servers are run in industry.

Key terms

AWS
Amazon Web Services, a cloud platform that rents out computing resources such as virtual machines, storage and networking over the internet.
EC2
Elastic Compute Cloud, the AWS service for creating and running virtual machines (instances).
Instance
A virtual computer in the cloud with its own CPU, RAM, storage and operating system.
AMI
Amazon Machine Image, a pre-configured template (operating system plus software) used to create an instance, e.g. Ubuntu.
Instance type
The size of an instance (CPU, memory, network), such as t2.micro; it decides performance and cost.
Key pair
A public key stored on the instance and a private key (.pem) kept by you; together they let you log in securely without a password.
SSH
Secure Shell, an encrypted protocol for logging in to and controlling a remote machine from a terminal.
Security group
A virtual firewall in AWS that controls which network traffic (ports and sources) can reach an instance.
EBS
Elastic Block Store, the persistent disk storage attached to EC2 instances.
VPC
Virtual Private Cloud, your own isolated network inside AWS where instances run.
Client and server
The client (your laptop) sends requests; the server (the EC2 instance) receives them and does the work.
Home directory
A user’s personal folder, such as /home/ubuntu, where you land after logging in.

Self-check

Pick an answer. You’ll see right away whether it’s correct and why.

What is an EC2 instance?

  1. A file you download from AWS
  2. A virtual computer running in the AWS cloud
  3. A type of SSH key
  4. A billing plan

EC2 instances are virtual machines with their own CPU, RAM, storage and OS, hosted on Amazon’s hardware.

Which choice decides the operating system of your new instance?

  1. Instance type
  2. Security group
  3. AMI
  4. Key pair

The AMI is the template that contains the OS (e.g. Ubuntu) and pre-installed software.

In ssh -i "aws_key.pem" ubuntu@ec2-…amazonaws.com, what is ubuntu?

  1. The username to log in as
  2. The key file name
  3. The AWS region
  4. The instance ID

The part before @ is the user; ubuntu is the default user on Ubuntu AMIs.

You lost your .pem file. What is true?

  1. Download it again from the EC2 console
  2. AWS emails it to you
  3. Any other .pem file will work
  4. AWS doesn’t keep a copy, so that key can’t be recovered

The private key is downloaded once. Keep it safe, and never share or commit it.

Your SSH connection times out. Which AWS setting should you check first?

  1. The AMI
  2. The security group rules for port 22
  3. The instance name
  4. The support plan

The security group is the instance’s firewall. If port 22 isn’t open to your IP, SSH can’t reach the server.

Right after logging in, pwd prints /home/ubuntu. What does that tell you?

  1. You are the root user
  2. The disk is empty
  3. You are in the ubuntu user’s home directory
  4. SSH failed

pwd shows your current directory; after login you start in your home directory.

Which is an advantage of the cloud setup over a local VirtualBox VM?

  1. You can reach it from anywhere and resize it by changing the instance type
  2. It works with no internet at all
  3. It uses your laptop’s RAM
  4. It never costs anything, whatever you run

Cloud instances are accessible from anywhere and scale easily, but they need internet and can incur charges beyond the free tier.
