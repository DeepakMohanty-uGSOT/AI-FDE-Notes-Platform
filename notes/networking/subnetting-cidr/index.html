Subnetting & CIDR

Carve one network into right-sized pieces, and for any address like 192.168.10.75/27 work out the network, broadcast and usable hosts in under a minute.

Why subnetting?

One big plot, four flatsA builder gets one large plot. Selling it whole to one family wastes space, and four families can’t share one kitchen. So the builder divides it into separate flats, each with its own door number and its own entrance. Subnetting divides one network into smaller, separate networks, each sized for who lives there.

The problem left by classful addressing

The previous note ended with a gap: classes came in only three sizes, Class A (huge), Class B (large) and Class C (254 usable). Anything in between either wasted thousands of addresses or didn’t fit.

Take a small company with 100 employees, one device each. The smallest classful option is a Class C:

2⁸ = 256 total256 − 2 = 254 usable254 − 100 = 154 unused

Now make it realistic: the company has 4 departments (Sales, Engineering, HR, Finance) and, for security and organisation, each should get its own network. One Class C is one network, with no built-in way to split it. That is exactly the problem subnetting solves.

What subnetting gives you

Address efficiency

Networks sized close to what is actually needed, so far fewer addresses go to waste.

Organisation

Each department, floor, team or purpose gets its own clearly separated subnet.

Basic isolation

Traffic inside one subnet (like broadcasts) stays there instead of reaching every device in the company.

Nearly everything in this note is about calculating those three parts (network address, host range, broadcast address) confidently for any subnet. First we need to be precise about where the network/host boundary sits.

The subnet mask: drawing the boundary

Every IPv4 address is 32 bits: a network portion followed by a host portion. Subnetting is just a precise, flexible way of deciding where that split happens.

The split is described by a second 32-bit value that travels with the address: the subnet mask. In a mask, 1 means “network bit” and 0 means “host bit”. The 1s always come first, all together, then the 0s.

Network bits = 1

The bits that identify the network. Written as 1s in the mask.

Host bits = 0

The bits that identify a device inside the network. Written as 0s in the mask.

CIDR: any prefix you need

Classful addressing tied every network to one of three prefixes: Class A = /8, Class B = /16, Class C = /24. Nothing in between.

CIDR (Classless Inter-Domain Routing) removes that restriction. A network can use any prefix length that fits its real size: /20, /25, /27, anything. This flexibility is what makes subnetting possible.

CIDR notation

Write the address, a slash, then the prefix length, the number of network bits:

192.168.1.0/24

The network’s address

Prefix: first 24 bits are network, so 32 − 24 = 8 host bits

  • /8 → 8 network bits, 24 host bits
  • /16 → 16 network bits, 16 host bits
  • /24 → 24 network bits, 8 host bits
  • /25, /26 … → same idea: the number after the slash is network bits, and 32 minus it is host bits

/24 and 255.255.255.0 say exactly the same thing. CIDR is just shorter: count the 1s in the mask and you have the prefix.

How many addresses does a subnet have?

Network and host bits always add up to 32. Everything follows from three formulas:

32 − prefixhost bits
2host bitstotal addresses
total − 2usable hosts

Why −2? Every subnet reserves two addresses that are never given to a device: the network address (all host bits 0, names the subnet) and the broadcast address (all host bits 1, reaches everyone on it).

Example: /24

  1. 1
    Host bits32 − 24 = 8
  2. 2
    Total2⁸ = 256
  3. 3
    Usable256 − 2 = 254

Example: /26

  1. 1
    Host bits32 − 26 = 6
  2. 2
    Total2⁶ = 64
  3. 3
    Usable64 − 2 = 62

A bigger prefix number means a smaller network: more bits go to the network, so fewer are left for hosts. /24 holds 254 devices; /26 only 62.

Total addresses vs usable hosts

Borrowing bits: how one network becomes many

Back to the company: one 192.168.1.0/24, and you want separate subnets. The trick: take some host bits and hand them to the network portion. This is borrowing bits. Each borrowed bit does two things at once:

More subnets

The network portion now has more possible combinations, so you get more separate networks.

Fewer hosts each

Fewer host bits are left, so each subnet holds fewer devices.

You are not creating address space out of nowhere. The same 32 bits are reorganised: more for “which subnet”, fewer for “which device”.

Borrow 1 bit: /24 → /25

  1. 1
    Write the current /24 mask11111111.11111111.11111111.00000000: 24 network bits, 8 host bits.
  2. 2
    Borrow the leftmost host bitThe last octet changes from 00000000 to 10000000. → /24 becomes /25
  3. 3
    Recount25 network bits + 7 host bits = still 32. New mask 11111111.11111111.11111111.10000000 = 255.255.255.128.
  4. 4
    See what the borrowed bit doesIt can be 0 or 1. Before, it helped pick a device; now it picks the subnet. Two values → two subnets.

The block-size shortcut

In every example above, subnets were spaced by one fixed number: 128 for /25, 64 for /26, 32 for /27, 16 for /28. That spacing is the block size, the distance from one subnet’s start to the next. You can get it straight from the mask:

256 − interesting octetblock size

The interesting octet is the mask octet that is neither 255 nor 0. That is where the boundary actually falls.

Finding the network address

The network address names the subnet itself. It is always the first address of the block and is never given to a device. Two ways to find it:

Method 1 · Binary AND

Line up the IP and the mask in binary and compare each pair of bits. The result is 1 only when both bits are 1.

IP bitMask bitResult
000
010
100
111

Warm-up: 10101100 AND 11111111 = 10101100. A mask of all 1s keeps every bit.

Real example: 192.168.1.25 with 255.255.255.0:

IP      11000000.10101000.00000001.00011001   192.168.1.25
Mask    11111111.11111111.11111111.00000000   255.255.255.0
        ----------------------------------- AND
Result  11000000.10101000.00000001.00000000   192.168.1.0

Where the mask is 1, the IP bit survives (1 AND x = x). Where the mask is 0, the result is 0 (x AND 0 = 0). So AND keeps the network part and zeroes the host part. Network address: 192.168.1.0.

Another one: 10.20.30.45 with 255.255.255.0:

IP      00001010.00010100.00011110.00101101   10.20.30.45
Mask    11111111.11111111.11111111.00000000
Result  00001010.00010100.00011110.00000000   10.20.30.0

AND really shines when the boundary is inside an octet. 192.168.1.70/26, last octet only:

70      0100 0110

AND     0100 0000   = 64   →  network 192.168.1.64

Broadcast address and usable host range

Broadcast: the last address

The broadcast address reaches every device on the subnet. It is always the last address of the block and, like the network address, never goes to a device. The easy way: broadcast = next subnet’s network address − 1.

  1. 1
    Find the next boundaryFor 192.168.1.70/26 the network is .64; the next boundary after 64 is 128.
  2. 2
    Subtract 1128 − 1 = 127 → broadcast 192.168.1.127.

In binary it is the network with all host bits set to 1: 01|000000 → 01|111111 = 64 + 63 = 127.

Usable host range: everything in between

network + 1first usable host
broadcast − 1last usable host

The interesting octet

Read the mask left to right; the first octet that is neither 255 nor 0 is the interesting octet. Octets before it are all 255 (pure network, nothing changes); octets after it are all 0 (pure host). The interesting octet is the only place where subnet boundaries are decided.

Designing subnets from a requirement

In real work the question is often reversed: nobody gives you the prefix. You are told what is needed and must choose it.

A · By hosts: “a subnet for 50 employees”

Find the smallest subnet with at least 50 usable addresses. Bigger would just waste addresses.

    Set up the condition2h − 2 ≥ 50, where h = host bits

VLSM: different sizes in one network

Real departments are never the same size. Suppose:

100Dept A hosts
50Dept B hosts
20Dept C hosts
10Dept D hosts

With equal subnets you would size everything for A: four /25s. Department D would sit on 126 usable addresses while needing 10. Worse, four /25s need 4 × 128 = 512 addresses, which is two whole /24s.

VLSM (Variable Length Subnet Masking) fixes this: different subnet sizes coexist in the same address space, each sized with the “smallest prefix that fits” method.

DeptNeedsPrefixUsable
A100/25126
B50/2662
C20/2730
D10/2814

The three VLSM rules

  1. 1
    Largest firstPlace A’s /25 before anything else, while a big continuous block is still free.
  2. 2
    Then progressively smallerB, then C, then D.
  3. 3
    Never overlapEach subnet starts at the next valid boundary for its size, after the previous one ends. No address belongs to two subnets.

Supernetting, /31 and /32

Subnetting vs supernetting

Subnettingone large networkseveral smaller networks
Supernettingseveral smaller networksone larger address block

Supernetting is the opposite of subnetting. It exists mainly for route aggregation: instead of a router keeping dozens of entries for small networks, one combined CIDR entry covers them all. For example, 192.168.0.0/24 + 192.168.1.0/24 = 192.168.0.0/23. Awareness only for now; the detail belongs to routing.

/31: point-to-point links

Host bits 32 − 31 = 1, total 2¹ = 2 addresses. Reserving a network and a broadcast address would leave zero for devices. So /31 is treated specially: on a point-to-point link (two routers wired directly to each other), both addresses are used as hosts, one per router. The “−2” rule does not apply.

/32: exactly one address

Host bits 32 − 32 = 0, total 2⁰ = 1 address. A /32 means one specific address and nothing else. It is used for host-specific routes and rules (e.g. “allow only 203.0.113.7/32”).

CIDR in IPv6: basic awareness

IPv6 keeps the prefix-length idea but never uses dotted-decimal masks; it only uses prefix notation. Same logic, 128 bits instead of 32:

2001:db8:abcd:0010::1/64
2001:0db8:abcd:0010:0000:0000:0000:0001

Routing prefix · commonly a /48 given to a site

Subnet ID · picks the subnet (here 16 bits)

Interface ID · 128 − 64 = 64 bits, identifies the device’s interface

  • Prefix: the network portion, same idea as IPv4.
  • Subnet ID: the part that identifies a specific subnet.
  • Interface ID: identifies one device’s interface, like IPv4’s host portion.
  • /64 is by far the most common IPv6 subnet size.
  • 2⁶⁴ addresses per subnet means IPv6 design rarely squeezes out efficiency the way IPv4 must.

Detailed IPv6 subnet design comes in a later note.

Real configurations and troubleshooting

Configuration 1 · does the gateway fit?

IP address : 192.168.10.75
Prefix     : /27
Gateway    : 192.168.10.65

From the four-answer method, this subnet is .64 – .95 with hosts .65 – .94. The gateway .65 is the first usable host. ✅ Correct: device and gateway are on the same subnet, 192.168.10.64/27.

Configuration 2 · the trickier one

IP address : 192.168.10.75/27
Gateway    : 192.168.10.100

Same subnet, .64 – .95. But .100 is bigger than .95, so it sits in the next /27 (.96 – .127). ❌ Broken: the device can’t reach its gateway, so it can’t reach the Internet or any other network.

Common problems

Wrong boundary

Incorrect subnet mask or prefix; network address calculated wrongly.

Bad host address

An address outside the valid range, or the network or broadcast address used as if it were a normal host.

Wrong neighbour

A gateway that belongs to a different subnet (Configuration 2).

Bad design

Overlapping subnets, or an incorrect VLSM allocation.

Key terms

Subnetting
Dividing one larger network into several smaller, independent networks (subnets), each with its own network address, host range and broadcast address.
Subnet mask
A 32-bit value with 1s for network bits and 0s for host bits, such as 255.255.255.192 for /26.
CIDR
Classless Inter-Domain Routing: allows any prefix length instead of the fixed /8, /16 and /24 of classful addressing, written like 192.168.1.0/24.
Prefix length
The number after the slash in CIDR notation; it counts the network bits, and 32 minus it gives the host bits.
Borrowing bits
Moving host bits into the network portion to create more subnets; each borrowed bit doubles the subnets and halves the addresses per subnet.
Block size
The spacing between consecutive subnet start addresses, calculated as 256 minus the interesting octet of the mask (e.g. 256 − 192 = 64).
Interesting octet
The first mask octet, reading left to right, that is neither 255 nor 0; it is where subnet boundaries are decided.
Network address
The first address of a subnet, with all host bits 0; it names the subnet and cannot be assigned to a device.
Broadcast address
The last address of a subnet, with all host bits 1; it reaches every host on the subnet and cannot be assigned to a device.
Usable host range
The addresses from network + 1 to broadcast − 1, the only ones that can be given to devices; there are 2host bits − 2 of them.
Binary AND
Bit-by-bit comparison of IP and mask where the result is 1 only if both bits are 1; IP AND mask gives the network address.
VLSM
Variable Length Subnet Masking: using different prefix lengths inside one address space so each subnet is sized to its real need, allocated largest first without overlaps.
Supernetting
Combining several smaller networks into one larger CIDR block, mainly so routers can use one aggregated route.
/31 and /32
Special prefixes: /31 gives 2 addresses both usable on point-to-point links; /32 identifies exactly one address for host-specific routes and rules.
Interface ID (IPv6)
The host part of an IPv6 address, usually the last 64 bits after a /64 prefix, identifying one device interface.

Self-check

Pick an answer. You’ll see right away whether it’s correct and why.

How many usable hosts does a /27 subnet have?

  1. 32
  2. 62
  3. 30
  4. 27

32 − 27 = 5 host bits → 2⁵ = 32 total → 32 − 2 = 30 usable.

What is the block size for the mask 255.255.255.240?

  1. 16
  2. 240
  3. 8
  4. 14

256 − 240 = 16. 14 is the usable hosts of a /28, not the block size.

What is the network address of 192.168.1.200/26?

  1. 192.168.1.128
  2. 192.168.1.0
  3. 192.168.1.200
  4. 192.168.1.192

Block 64 → 0, 64, 128, 192. 200 is in 192–255, so the network is .192.

What is the broadcast address of 10.0.0.37/29?

  1. 10.0.0.40
  2. 10.0.0.39
  3. 10.0.0.255
  4. 10.0.0.38

/29 → block 8 → 37 is in 32–39. Broadcast = next boundary (40) − 1 = 39. .38 is the last usable host.

A team needs 25 devices on one subnet. What is the smallest prefix that fits?

  1. /28
  2. /26
  3. /27
  4. /29

/28 gives only 14 usable; /27 gives 2⁵ − 2 = 30 ≥ 25. /26 also works, but it’s bigger than needed.

You subnet a /24 into /28s. How many subnets do you get?

  1. 16
  2. 14
  3. 4
  4. 28

28 − 24 = 4 borrowed bits → 2⁴ = 16 subnets.

What is the network address of 172.16.35.100/20?

  1. 172.16.35.0
  2. 172.16.32.0
  3. 172.16.0.0
  4. 172.16.48.0

/20 → 255.255.240.0 → block 16 in the third octet → 35 is in 32–47 → 172.16.32.0.

A PC is 192.168.10.75/27. Which gateway address would actually work?

  1. 192.168.10.64
  2. 192.168.10.95
  3. 192.168.10.100
  4. 192.168.10.94

The subnet is .64–.95. .64 is the network and .95 the broadcast, and .100 is in the next subnet. .94 is a valid host.

Why is VLSM more efficient than equal-sized subnets?

  1. It removes the network and broadcast addresses
  2. It makes every subnet a /24
  3. Each subnet gets a prefix sized to its own need, so small teams don’t waste big blocks
  4. It only works with IPv6

VLSM lets /25, /26, /27 and /28 coexist in one space, allocated largest first, so addresses aren’t wasted.

All of it, in one sentence

A prefix (or mask) draws the line between network and host bits; borrowing bits trades hosts for subnets, the block size (256 − interesting octet) finds the boundaries, and every subnet then has a network address, a usable host range and a broadcast address that you can now calculate, design with VLSM, and troubleshoot.

— Vishwa Mohan
