Networking Fundamentals III: OSI Model & Data Communication

See how all the networking pieces fit into seven tidy layers, watch data get wrapped and unwrapped, and trace exactly what happens when you open a website.

Why networking needs layers

Sending one message involves many jobs at once: turning data into physical signals, delivering it within the local network, addressing it across networks, choosing routes, making delivery reliable between applications, and presenting the data correctly at the other end. Handle all of that as one giant process and nobody could design, understand, fix or improve one part without risking everything else.

Departments in a companyA company doesn’t make every employee do sales, finance and engineering. It has departments, each doing one job well and trusting the others to do theirs. Layering splits networking into separate layers, each with one clear job, each relying on the layer below to have done its part.
The real benefit Change one layer without redesigning the others. Upgrading from an older Wi-Fi standard to a newer one doesn’t touch your browser, as long as each layer keeps doing its job and talking properly to its neighbours.

The OSI model: seven layers

The OSI Model (Open Systems Interconnection) is a framework for understanding how data travels from one device to another. It divides communication into seven layers, each with a specific job.

Why it was created

Long before everyday Internet use, companies in different countries built computers with completely different designs and communication methods. Even when cabled together, they often couldn’t interpret each other’s data, like one person who speaks only Tamil and another who speaks only German. The international body ISO (International Organization for Standardization) developed a common framework: the OSI Model.

Open

Built on common standards, not controlled by any one company.

Systems

Computers and other network devices.

Interconnection

Connecting those systems so they can communicate.

Upper layers (7, 6, 5)

The “software” layers: applications, data and communication sessions.

Transport (4): the heart

Sits between the two groups and manages end-to-end delivery. “Heart” is an informal nickname, not an official OSI term.

Lower layers (3, 2, 1)

The “hardware” side: network devices, connections and actual transmission.

SendingLayer 7… each layer down …Layer 1 → onto the wire
ReceivingLayer 1 ← off the wire… each layer up …Layer 7
OSI vs what the Internet actually runs The real Internet is built on the simpler TCP/IP model, which folds layers 5–7 into one Application layer (and 1–2 into a link layer). OSI is the shared vocabulary: engineers still say “that’s a Layer 7 problem” or “an L4 load balancer”.

The story: a report from Bengaluru to Bhubaneswar

Layers 7, 6, 5: application, presentation, session

Layer 7 · Application

The top layer provides network services to the applications people use. It is where the user’s wish to communicate begins: opening a website, sending an email, uploading or downloading a file, looking up a domain name. It cares about what the app wants to send or receive, not how it travels.

ProtocolUsed for
HTTP / HTTPSCommunication between web browsers and web servers
FTPTransferring files
DNSFinding the IP address for a domain name
DHCPAutomatically giving devices their network configuration
SMTPSending email
App ≠ Application-layer protocol Gmail is an application/service; SMTP is a protocol (rules) for sending email. A browser is an application; HTTP/HTTPS is the protocol it speaks to web servers.

In the story: Ananya opens the company’s mailing application, prepares the 500-page Kannada report, and decides to send it to Debashish. No thought yet of routes, IPs, cables or signals. Those belong to other layers.

Layer 6 · Presentation

Makes sure the data is in a form the receiving application can understand and use. Three jobs:

Translation

Convert data from one format or representation to another.

Encryption / decryption

Turn readable data into unreadable ciphertext before sending; decrypt at the other end.

Compression / decompression

Shrink data to send it efficiently; restore it on arrival.

SSL/TLS are associated with this kind of secure communication. In modern TCP/IP systems these functions are usually done by the application or application-level protocols rather than a separate Layer 6, but the responsibilities still exist.

In the story: Rakesh prepares the report into a suitable format and, because it is confidential, encrypts it so anyone intercepting it can’t read it.

Layer 5 · Session

A session is an ongoing period of communication between two systems. This layer:

  1. 1
    Creates sessionsEstablishes communication so the two systems can start exchanging data.
  2. 2
    Manages sessionsKeeps the conversation organised from start to end, so data from one conversation doesn’t mix with another.
  3. 3
    Terminates sessionsEnds it properly, manually or automatically, like a banking site logging you out after inactivity.

In the story: Faizan contacts Meghna Info Systems, confirms they’re ready for a large report, fixes 6:30 pm for the transfer, keeps it organised while it runs, and formally closes it once done.

Layer 4 · Transport: the heart

The Transport layer manages end-to-end delivery between the two communicating devices. Upper layers care about what the communication is; lower layers care about how it moves. Transport sits in between, which is why it is nicknamed the “heart” of OSI.

Segmentation

Break large data into smaller pieces (with TCP: segments).

Sequencing

Number the pieces so the receiver can rebuild them in order.

Acknowledgment

With TCP, the receiver confirms what arrived.

Retransmission

Missing data (no acknowledgment) is sent again.

Ports

The IP finds the device; the port finds the service on it.

The two big protocols are TCP (reliability, ordering, acknowledgments, retransmission) and UDP (simpler, without those guarantees). The three-way handshake and TCP headers come in the TCP & UDP module.

In the story: Meera divides the 500 pages into five parts of 100 pages and numbers them 1 to 5. If parts arrive out of order, the numbers fix it; if one is lost and a reliable transport (TCP) is in use, that part is sent again.

Layer 3 · Network: addressing and routing

The Network layer gets data from the source device to the destination device, even when they are on different networks. Here the data unit is a packet.

Logical addressing

Adds a source IP (where it came from) and a destination IP (where it must end up).

Path determination

Decides which path is best from the source network to the destination network.

Routing

Forwards the packet network by network. Each router reads the destination IP and picks the next hop.

Path determination is deciding the best path; routing is choosing and using that path to forward packets between networks.

In the story: Vikram labels each of the five parts with the source IP (Trident) and destination IP (Meghna), works out the best route, and sends them off through a chain of routers.

Layer 2 · Data Link: frames and the next hop

The Data Link layer delivers data from one device to the next directly connected device on the local network (home, office, building). The unit is a frame.

FunctionWhat it means
FramingPuts the packet from Layer 3 inside a structured unit called a frame
AddressingAdds a source MAC (device sending this frame) and destination MAC (device that should receive it next)
Node-to-node deliveryMoves the frame to the next directly connected node (computer, switch, router)
Flow controlStops a fast sender from overwhelming a slower receiver on that link
Error detectionAdds check information so the receiver can spot a damaged or altered frame
Local deliveryA switch reads the destination MAC and forwards the frame to the right port

The big idea: IP is the destination, MAC is the next hop

The laptop at Trident doesn’t put the Bhubaneswar server’s MAC in its frame; that server is on another network. The destination MAC is the next device on the local network, usually the company router. The router then builds a new frame for the next link. MAC addresses change at every hop; the IP addresses stay the same end to end.

In the story: Sandeep puts each addressed part into a frame, writes the source MAC (his device) and destination MAC (the next device: the switch or the local router), handles flow control and adds error-check information, then passes the frame to the Physical layer.

Layer 1 · Physical: bits become signals

The bottom layer deals with the actual medium: network cables, fiber, connectors, wireless antennas. It doesn’t understand meaning: no files, no IPs, no MACs. It just carries bits (0s and 1s) as physical signals.

Electrical signals

Over copper network cables.

Light pulses

Over fiber-optic cables.

Radio waves

Through the air, e.g. Wi-Fi.

frame0100 1101 0110 …signals on the medium

In the story: Om Prakash and Deepa run Trident’s cables, fiber links and Wi-Fi antennas. They convert everything into electrical signals, light pulses or radio waves, and the report physically leaves the Bengaluru building.

The receiving side: back up the stack

At Meghna Info Systems everything happens in reverse, from Layer 1 up to Layer 7. Each layer undoes what its partner did in Bengaluru.

  1. 1
    PhysicalCables, fiber or Wi-Fi receivers turn incoming signals back into digital data. No interpretation yet.
  2. 2
    Data LinkRebuilds frames, checks the destination MAC (“is this for me?”) and checks for transmission errors. Not for this interface? The frame is ignored here. → MAC check
  3. 3
    NetworkChecks the destination IP (“is this packet for Meghna?”). If it doesn’t match this device, the packet is not accepted and is dropped. → IP check
  4. 4
    TransportUses Meera’s numbers to put parts 1 → 2 → 3 → 4 → 5 in order and rebuild the 500 pages. A missing part? TCP gets it resent. → reassemble
  5. 5
    SessionConfirms Faizan’s session is still active and uninterrupted; closes it once the whole report has arrived.
  6. 6
    PresentationDecrypts Rakesh’s encryption, then translates the report into Odia. → readable
  7. 7
    ApplicationThe report lands in Debashish’s mailing app: complete, in order, decrypted, in Odia. He can finally read it.
Why bother with all seven?Ananya never thought about MAC addresses; Om Prakash and Deepa never thought about translation. Each person trusted the previous one and did one job well. The OSI model turns one enormous task into seven small, independent responsibilities.
In the field (FDE) Debug bottom-up, layer by layer. Is the cable/Wi-Fi up (L1)? Got an IP and gateway (L3)? Can you ping the host (L3)? Is the port open (L4)? Does TLS succeed (L6-ish)? Does the API return the right thing (L7)? Saying “it’s L4, the port is blocked” gets a customer’s network team moving fast.

Encapsulation, decapsulation and data units

As data moves down at the sender, each layer adds its own control information (a header; Layer 2 also adds a trailer) without changing the original content. That wrapping is encapsulation. At the receiver, each layer reads and removes the header added by its matching layer on the way up: decapsulation.

The complete journey: opening a website

Now tie all three notes together. You type https://example.com and press Enter.

  1. 1
    Application creates the requestThe browser, at Layer 7, prepares to talk to a web server using HTTPS. → L7
  2. 2
    DNS finds the destinationexample.com is a name, so the device resolves it: name → DNS → IP address. → note 2
  3. 3
    Local or remote?The device checks whether that IP is on its own network. For a website it almost never is, so traffic goes to the default gateway. → note 1
  4. 4
    Local network deliveryThe NIC, MAC addressing and the local switch carry the frame to the router. → L2
  5. 5
    TransportThe request is tied to port 443 (HTTPS) and prepared with TCP for reliable delivery. → L4
  6. 6
    NetworkIt becomes a packet with source and destination IP addresses, ready to be routed. → L3
  7. 7
    The Internet journeyThrough your ISP and many interconnected networks; every router decides the next hop. → routing
  8. 8
    Arrival at the serverThe server decapsulates up through its layers until the HTTPS request reaches its web software.
  9. 9
    The response travels backThe page content goes through the same layered process in reverse: Internet, ISP, router, local network, your device.
  10. 10
    The browser displays itBack at Layer 7, the browser renders the webpage.

See parts of the journey yourself

nslookup example.com           # step 2: DNS
ip route                       # step 3: your default gateway (Linux)
traceroute example.com         # step 7: the routers along the way (tracert on Windows)
curl -v https://example.com    # steps 5-10: TCP to :443, TLS, HTTP request and response

The whole series in one map

Every idea in these three notes answers one question: how can two devices, anywhere in the world, exchange information correctly and reliably?

Connect

Standalone computers can’t share. NICs, cables, Wi-Fi, switches (not hubs) and routers link devices and networks.

Scale

LAN for one location, WAN for long distances; the Internet is a network of networks joined through ISPs.

Identify

MAC locally, IP across networks, port for the exact app.

Agree

Protocols make sure data is formatted and understood the same way, whatever the brand.

Organise

The OSI model puts it all into seven layers.

Wrap & unwrap

Data → segment/datagram → packet → frame → bits, and back.

Key terms

Layering
Splitting a complex system into separate layers, each with one job, each relying on the layer below and serving the layer above.
OSI model
Open Systems Interconnection: ISO’s seven-layer framework (Application, Presentation, Session, Transport, Network, Data Link, Physical) for describing network communication.
Application layer (L7)
Provides network services to applications; protocols include HTTP/HTTPS, FTP, DNS, DHCP and SMTP.
Presentation layer (L6)
Makes data usable by the receiving application through translation, encryption/decryption and compression/decompression.
Session layer (L5)
Creates, manages and terminates communication sessions between two systems.
Transport layer (L4)
Manages end-to-end delivery with segmentation, sequencing, acknowledgment, retransmission and ports, using TCP or UDP.
Network layer (L3)
Adds source and destination IP addresses, determines the best path and routes packets between networks.
Data Link layer (L2)
Puts packets into frames with source and destination MAC addresses and delivers them to the next directly connected node, with flow control and error detection.
Physical layer (L1)
Transmits bits as electrical signals, light pulses or radio waves over the medium, without understanding their meaning.
Encapsulation
Each layer adding its own header (and at Layer 2 a trailer) around the data as it moves down the stack at the sender.
Decapsulation
Each layer reading and removing its matching header as data moves up the stack at the receiver.
Segment / Datagram
The Layer 4 unit of data: called a segment with TCP and a datagram with UDP.
Packet
The Layer 3 unit of data, carrying source and destination IP addresses; the unit routers work with.
Frame
The Layer 2 unit of data, carrying source and destination MAC addresses; the unit switches work with, rebuilt at every hop.

Self-check

Pick an answer. You’ll see right away whether it’s correct and why.

What is the main benefit of layering?

  1. It makes data travel faster
  2. It removes the need for protocols
  3. Each layer does one job, so one layer can change without redesigning the others
  4. It lets every device skip the Physical layer

Layering separates responsibilities, e.g. upgrading Wi-Fi doesn’t require changing your browser.

Which is the correct order from Layer 7 down to Layer 1?

  1. Application, Session, Presentation, Network, Transport, Data Link, Physical
  2. Application, Presentation, Session, Transport, Network, Data Link, Physical
  3. Physical, Data Link, Network, Transport, Session, Presentation, Application
  4. Application, Presentation, Transport, Session, Network, Physical, Data Link

“All People Seem To Need Data Processing.” Option 3 is the right list but in bottom-to-top order.

In the story, Meera splits the 500-page report into five numbered parts. Which layer is she?

  1. Network
  2. Session
  3. Data Link
  4. Transport

Segmentation and sequencing are Transport layer jobs.

Rakesh encrypts the report so interceptors can’t read it. Which layer does this represent?

  1. Presentation
  2. Application
  3. Physical
  4. Network

Translation, encryption and compression belong to the Presentation layer.

A packet travels laptop → router A → router B → server. What happens to the addresses?

  1. Both MAC and IP stay the same
  2. The IPs change at every hop; the MACs stay the same
  3. The MACs change at every hop; the source and destination IPs stay the same
  4. Both change at every hop

Each link gets a new frame with new MACs (next hop), while the IPs name the true source and destination end to end.

Which unit of data does a router mainly work with?

  1. Frame
  2. Packet
  3. Segment
  4. Bits

Routers read the IP header, which belongs to the Layer 3 packet. Switches work with frames.

What is decapsulation?

  1. Encrypting data before sending
  2. Splitting data into segments
  3. Adding headers as data goes down the stack
  4. Each receiving layer reading and removing its matching header as data goes up

Encapsulation wraps on the way down; decapsulation unwraps on the way up.

When you open https://example.com, what must happen before the browser can connect to the server?

  1. DNS must resolve example.com to an IP address
  2. The server must send its MAC address to you
  3. Your laptop must get a new MAC address
  4. The Session layer must pick port 80

Without the IP from DNS, nothing below Layer 7 knows where to send the request. HTTPS uses port 443, not 80.

All of it, in one sentence

The OSI model splits communication into seven layers; going down, each layer encapsulates the data (segment → packet → frame → bits), going up each layer decapsulates it, and opening a website is just DNS, ports, TCP, IP routing and MAC delivery working together through those layers.
