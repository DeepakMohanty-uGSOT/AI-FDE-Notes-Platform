FastAPI Fundamentals, Setup & Project Structure

Build your first API server in Python: set up the project, write a route, run it with Uvicorn, see the JSON in your browser, and organise it the way real projects are organised.

What is FastAPI?

The restaurant, from the kitchen sideIn API Basics you were the customer placing orders. Now you run the restaurant. Uvicorn is the front door that is always open, FastAPI is the head waiter who reads each order and hands it to the right cook, and your Python functions are the cooks. FastAPI lets you build an API by writing normal Python functions; it handles the web plumbing for you.

FastAPI is a Python library (framework) that helps you build APIs. An API (Application Programming Interface) is a way for one program to ask another program for data. When a mobile app shows your profile, it asks an API “give me this user’s details”, and the API sends them back.

What problem does FastAPI solve? Writing an API from scratch means handling web requests, reading URLs, converting data and handling errors yourself. FastAPI does all of this for you. You simply write normal Python functions.

Where is FastAPI used?

Frontend

What the user sees: buttons, pages, screens.

Backend

The hidden part that stores data and does the work. FastAPI is used to build the backend.

How a FastAPI application works

Every time someone uses your API, the same simple round trip happens:

  1. 1
    Client sends a requesta browser or an app asks, for example, “give me the home page data”.
  2. 2
    FastAPI reads the requestand finds the Python function that should handle it.
  3. 3
    Your Python function runsand returns some data.
  4. 4
    FastAPI converts that data into JSONand sends it back as the response.

Keep this picture in mind. Everything you build in this note is just this flow, step by step.

Setting up the project

Create the project folder

First, create a folder for the project. Open the terminal in VS Code (Terminal → New Terminal) and run:

mkdir fastapi-project
cd fastapi-project
  • mkdir = make directory: creates a new folder.
  • cd = change directory: moves you inside that folder.

fastapi-project/ is simply the workspace for the application. All your files will live here.

Open just this folder Now open it in VS Code with File → Open Folder → fastapi-project, so the Explorer shows only your project.

Create a virtual environment

A virtual environment is a private copy of Python just for this project. Packages you install here stay inside this project only.

Create it with this command:

python -m venv venv
  • python -m venv = run Python’s built-in venv tool.
  • The last venv = the name of the folder it creates. (You can pick any name, but venv is the common choice.)

Now activate it, so the terminal starts using it:

Operating systemActivate
Windowsvenv\Scripts\activate
Linux / macOSsource venv/bin/activate

How do you know it worked? Look at the start of the terminal line. After activation, (venv) appears in front:

Before:  PS C:\Kumar_All_Data\fastapi-project>
After:   (venv) PS C:\Kumar_All_Data\fastapi-project>
“running scripts is disabled on this system”? On Windows, run this once and try again: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
Why create the venv first? So that FastAPI gets installed inside this project, not on the whole computer. Always activate the venv before installing packages or running the app.

Installing FastAPI and Uvicorn

You need two packages. Install them one by one:

pip install fastapi
pip install uvicorn

Or install both with one command:

pip install fastapi uvicorn

pip also installs some helper packages that FastAPI needs, such as starlette (the web toolkit underneath) and pydantic (data validation). That is normal.

Understand the two packages

PackageJobSimple meaning
FastAPIHelps you build the APIWhere you write routes and functions
UvicornRuns the FastAPI applicationA server that waits for requests and passes them to FastAPI

Verify the installation

Check what is installed in the venv:

pip list

If you can see fastapi and uvicorn in the list, you are ready to write code.

Good to know FastAPI’s own docs also suggest pip install "fastapi[standard]", which installs FastAPI with Uvicorn and a few extras in one go. Installing the two packages separately, as above, works just as well.

Your first FastAPI application

The environment is ready. Now create a new file named main.py inside the project folder:

fastapi-project/
│
├── venv/
│
└── main.py

Start with the smallest possible FastAPI application:

main.py
from fastapi import FastAPI

app = FastAPI()

Running it with python main.py prints nothing, and that is expected. You have created the app, but nobody is running it as a server yet. You will do that with Uvicorn in a moment.

Understand the code

from fastapi import FastAPI

This line brings the FastAPI class from the fastapi package into your file.

app = FastAPI()

This line creates the FastAPI application instance and stores it in a variable named app.

What is an application instance? FastAPI is like a blueprint. FastAPI() builds one real application from that blueprint, and app is that real application. It will hold all your routes and settings.

Your first route

A route connects a URL path (like /) to a Python function. When someone visits that path, the function runs and its return value becomes the response. Add these lines below app = FastAPI():

@app.get("/")
def home():
    return {"message": "Hello FastAPI"}

Complete code of main.py:

main.py (complete)
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def home():
    return {"message": "Hello FastAPI"}

Parts of the route

Understand the flow

Running the app with Uvicorn

Your code is ready. Now ask Uvicorn to run it. Make sure the venv is active, then run:

uvicorn main:app --reload

The important line is Uvicorn running on http://127.0.0.1:8000. Your API is now live on your own computer.

Understand the command

So uvicorn main:app means: run the app object from the main.py file using Uvicorn.

  • 127.0.0.1 means this computer (also called localhost).
  • 8000 is the port: like a door number on your computer where the server listens.
  • To stop the server, click in the terminal and press Ctrl + C.
Keep this terminal open while you test. If you close it, the server stops and the browser can no longer reach your API.

Testing your first API

Open your browser and go to:

http://127.0.0.1:8000/

Expected output:

{
    "message": "Hello FastAPI"
}

Now look at the terminal. Uvicorn writes one log line for every request it receives:

"GET / HTTP/1.1" 200 OK means: someone asked for / using GET, and the server answered successfully (200 OK).

The application instance, and more routes

You have now used app yourself, so let’s understand it properly.

What is app?

app = FastAPI()

app is your whole API in one object. Uvicorn runs it, and every route is stored inside it.

Why do we need it?

Routes are registered (added) to the application using app:

@app.get("/")

@app.get means “add this route to app”. Without app, the route would have nowhere to go, and Uvicorn would have nothing to run.

Add more routes

Add two more routes to main.py:

@app.get("/about")
def about():
    return {"message": "About Page"}

@app.get("/contact")
def contact():
    return {"message": "Contact Page"}

Save the file. Because of --reload, Uvicorn restarts by itself. Now test all three paths in the browser:

http://127.0.0.1:8000/
http://127.0.0.1:8000/about
http://127.0.0.1:8000/contact

Exploring responses

Let’s experiment. Change what home() returns, save, and refresh the browser each time.

Return a string

@app.get("/")
def home():
    return "Hello"

The browser shows "Hello" with quotes. FastAPI sent the text as a JSON string.

Return a dictionary

@app.get("/")
def home():
    return {"message": "Hello"}

A dictionary becomes a JSON object, with keys and values. This is the most common type of response.

Return multiple values

@app.get("/")
def home():
    return {
        "name": "Rahul",
        "age": 21,
        "course": "BCA"
    }

To send many values, put them all in one dictionary. Notice that 21 stays a number (no quotes), while text gets quotes.

How Python data becomes JSON

You never convert to JSON yourself Just return normal Python data (string, number, list, dictionary) and FastAPI does the conversion.

Exploring invalid routes: 404

What happens if you visit a path that does not exist? Try:

http://127.0.0.1:8000/hello
{
    "detail": "Not Found"
}

Why does FastAPI return 404?

You never wrote @app.get("/hello"). FastAPI checks its route list, does not find /hello, and replies with 404 Not Found.

Paths must match exactly /About (capital A) and /about are different paths. A small typo gives you a 404.

Uvicorn options: port and reload

Change the port

By default Uvicorn uses port 8000. To use another port, add --port. First stop the server with Ctrl + C, then run:

uvicorn main:app --reload --port 8080

Now open the new address:

http://127.0.0.1:8080/

Changing the port is useful when port 8000 is already used by another program, or when you want to run two apps at once.

Port already in use If you see [Errno 10048] ... only one usage of each socket address, another program is already using that port. (On Linux/macOS it reads [Errno 98] Address already in use.) Pick a different port number.

Understand --reload

Go back to port 8000 (uvicorn main:app --reload). Now change the message in home() from:

return {"message": "Hello FastAPI"}

To:

return {"message": "Welcome to FastAPI"}

Save the file (Ctrl + S) and watch the terminal. Uvicorn notices the change and restarts by itself. Refresh the browser and the new message appears:

--reload is for development only It watches your files and restarts on every save. Real live servers run without it.

Basic project structure

So far everything lives in one file:

fastapi-project/
│
├── venv/
└── main.py

That is perfect for learning. But real applications have dozens of routes (users, products, orders, payments…). If all of them sit in one main.py, the file becomes very long and hard to manage. So we split the code into folders.

A common beginner-friendly structure looks like this:

a common beginner-friendly structure
fastapi-project/
│
├── app/
│   ├── __init__.py
│   ├── main.py
│   │
│   └── routes/
│       └── users.py
│
└── requirements.txt

For now, only understand why each item is there. You will put code in routes/ in a later module.

Move the application into the app package

Let’s organise the project. Do these steps:

  1. 1
    Create a foldernamed app inside fastapi-project.
  2. 2
    Add an empty __init__.pyinside app.
  3. 3
    Move main.pyinto the app folder, so it becomes app/main.py.
  4. 4
    (Optional)create app/routes/users.py and leave it empty for now.

The code inside main.py stays exactly the same. Now, what happens if you run the old command?

uvicorn main:app --reload

Uvicorn says Could not import module "main". It is looking for main.py in the project folder, but you moved it into app/. Tell Uvicorn the new location:

uvicorn app.main:app --reload

The app runs again, and http://127.0.0.1:8000/ shows the same response as before.

Reading app.main:app

Run from the project folder Always run Uvicorn from the project folder (fastapi-project), not from inside the app folder. The import path app.main only makes sense from there.

requirements.txt

Imagine your friend wants to run your project. How will they know which packages to install? You write them in a file called requirements.txt.

Create the file

pip freeze > requirements.txt
  • pip freeze lists every package installed in the venv, with its exact version.
  • > saves that list into a file instead of printing it on the screen.

Each line has the form package==version, for example fastapi==0.142.2.

Install from the file

On a new computer (or a new venv), one command installs everything from the list:

pip install -r requirements.txt

-r means read the package names from this file.

Keep it up to date Run pip freeze > requirements.txt again whenever you install a new package, so the file stays up to date.
In the field (FDE) When you hand an API to a customer’s team or deploy it on their server, “clone, create venv, pip install -r requirements.txt, uvicorn app.main:app” should be the entire setup. If it needs more, write it in the README.

Now build a complete small project on your own, from an empty folder. Final structure:

The API must have these four routes:

RouteWhat it returns
GET /A welcome message
GET /studentFull student details: name, course, skills
GET /courseCourse name and duration
GET /skillsList of skills

Follow these steps

Setup commands

Windows (on Linux/macOS use source venv/bin/activate)

mkdir fastapi-project
cd fastapi-project
python -m venv venv
venv\Scripts\activate
pip install fastapi uvicorn

Then create the app folder with an empty __init__.py and the main.py file below.

app/main.py
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def home():
    return {"message": "Welcome to the Student API"}

@app.get("/student")
def student():
    return {
        "name": "Rahul",
        "course": "BCA",
        "skills": ["Python", "FastAPI", "SQL"]
    }

@app.get("/course")
def course():
    return {"course": "BCA", "duration": "3 Years"}

@app.get("/skills")
def skills():
    return {"skills": ["Python", "FastAPI", "SQL"]}

Run it and test all four routes

uvicorn app.main:app --reload

Notice how the Python list ["Python", "FastAPI", "SQL"] became a JSON array, and the dictionary inside /student became a JSON object.

Save the dependencies

pip freeze > requirements.txt

Try it yourself

Change the student’s name to your own name and check that --reload picks it up.

Save the file, watch the terminal print “Reloading…”, then refresh /student.

Add a new route GET /college that returns your college name and city.

@app.get("/college") above def college(): return {"college": "...", "city": "..."}.

Visit /teacher (a route you did not create). What status code do you get, and why?

404 Not Found with {"detail":"Not Found"}, because no route matches /teacher.

Run the app on port 9000 instead of 8000.

uvicorn app.main:app --reload --port 9000, then open http://127.0.0.1:9000/.

Key terms

FastAPI
A Python framework for building APIs, where each endpoint is a normal Python function and return values are sent back as JSON automatically.
Uvicorn
The server program that listens for HTTP requests on a port and passes them to a FastAPI application.
Backend
The hidden part of an application that stores data and does the work; FastAPI is used to build it.
Application instance
The object created by app = FastAPI(); it holds every route and setting and is what Uvicorn runs.
Route
A connection between an HTTP method plus URL path, such as GET /about, and the Python function that handles it.
Decorator (@app.get)
The line above a function that registers it with the app as the handler for a given method and path.
localhost (127.0.0.1)
The address that always means “this computer”, used to reach a server running on your own machine.
Port
A numbered door on a computer where a server listens; Uvicorn uses 8000 unless you pass --port.
--reload
A Uvicorn option for development that restarts the server automatically whenever a code file is saved.
404 Not Found
The status FastAPI returns, with {"detail":"Not Found"}, when no route matches the requested path.
app.main:app
Uvicorn’s target format: the import path of the module (app/main.py), a colon, then the name of the FastAPI variable inside it.
__init__.py
A file (often empty) that marks a folder as a Python package, so its modules can be imported with dotted paths.

Self-check

Pick an answer. You’ll see right away whether it’s correct and why.

What is the job of Uvicorn?

  1. It defines the routes
  2. It runs the app as a server and passes requests to FastAPI
  3. It converts Python dicts to JSON
  4. It creates the virtual environment

FastAPI is where you build the API; Uvicorn is the server that listens on a port and hands each request to it.

You run python main.py on a file with only app = FastAPI(). What happens?

  1. A server starts on port 8000
  2. It raises an error
  3. Nothing is printed; the app is created but not served
  4. The browser opens

Creating the app object doesn’t start a server. You need uvicorn main:app for that.

In uvicorn main:app, what does the part after the colon refer to?

  1. The variable holding FastAPI() inside main.py
  2. The folder name
  3. The port
  4. The function for the home route

Before the colon is the module (main.py); after it is the name of the FastAPI object in that module.

Your route function returns {"age": 21}. What does the browser receive?

  1. The text age=21
  2. An HTML page
  3. {"age": "21"} with 21 as a string
  4. A JSON object where 21 is a number

FastAPI converts the dict to a JSON object and keeps numbers as numbers.

You visit /About but your route is @app.get("/about"). What do you get?

  1. The about page
  2. 404 with {"detail":"Not Found"}
  3. 500 Internal Server Error
  4. A redirect to /about

Paths are case-sensitive and must match exactly, so no route is found.

You moved main.py into an app/ package. Which command now works from the project folder?

  1. uvicorn main:app
  2. uvicorn app:main
  3. uvicorn app.main:app
  4. uvicorn app/main.py

The module path is app.main (folder.file), followed by :app for the variable.

Uvicorn says the address is already in use. What is the simplest fix?

  1. Run on another port with --port 8080
  2. Remove --reload
  3. Rename main.py
  4. Reinstall FastAPI

Another program holds port 8000; choosing a free port lets your server start.

You edit a route, save, and refresh, but the old response still shows. The terminal shows no “Reloading”. Most likely cause?

  1. FastAPI caches responses forever
  2. The browser is offline
  3. The route needs a POST
  4. The server was started without --reload

Without --reload, Uvicorn keeps running the old code until you restart it.

All of it, in one sentence

Create a venv, install FastAPI and Uvicorn, make app = FastAPI(), attach functions with @app.get(...), and run uvicorn app.main:app --reload: every request then flows browser → Uvicorn → FastAPI → your function, and whatever you return comes back as JSON.
