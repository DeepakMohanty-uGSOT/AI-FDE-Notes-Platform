FastAPI Fundamentals, Setup & Project Structure

Build your first API server in Python: set up the project, write a route, run it with Uvicorn, see the JSON in your browser, and organise it the way real projects are organised.

What is FastAPI?

The restaurant, from the kitchen sideIn API Basics you were the customer placing orders. Now you run the restaurant. Uvicorn is the front door that is always open, FastAPI is the head waiter who reads each order and hands it to the right cook, and your Python functions are the cooks. FastAPI lets you build an API by writing normal Python functions; it handles the web plumbing for you.

FastAPI is a Python framework for building APIs, the way one program asks another for data. When a mobile app shows your profile, it asks an API “give me this user’s details”, and the API sends them back.

What problem does it solve? Writing an API from scratch means handling web requests, reading URLs, converting data and handling errors yourself. FastAPI does all of that. You write ordinary functions.

Frontend

What the user sees: buttons, pages, screens.

Backend

The hidden part that stores data and does the work. FastAPI builds the backend.

How a FastAPI application works

Every time someone uses your API, the same round trip happens:

  1. 1
    Client sends a requesta browser or app asks, e.g. “give me the home page data”.
  2. 2
    FastAPI reads the requestand finds the Python function that should handle it.
  3. 3
    Your function runsand returns some ordinary Python data.
  4. 4
    FastAPI converts it to JSONand sends it back as the response.

Setting up the project

Create the project folder

Open the terminal in VS Code (Terminal → New Terminal) and run:

mkdir fastapi-project
cd fastapi-project
  • mkdir = make directory: creates a new folder.
  • cd = change directory: moves you inside it.

fastapi-project/ is the workspace for the application; all files live here. Open it in VS Code with File → Open Folder → fastapi-project so the Explorer shows only your project.

Create and activate a virtual environment

As you saw in Python Project Development, a virtual environment is a private Python just for this project; packages installed here stay here.

python -m venv venv
  • python -m venv runs Python’s built-in venv tool.
  • The last venv is the name of the folder it creates (any name works; venv and .venv are both common).
Operating systemActivate
Windowsvenv\Scripts\activate
Linux / macOSsource venv/bin/activate

How do you know it worked? (venv) appears at the start of the prompt:

Before:  PS C:\Kumar_All_Data\fastapi-project>
After:   (venv) PS C:\Kumar_All_Data\fastapi-project>
“running scripts is disabled on this system”? On Windows PowerShell, run this once, then activate again: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
Why the venv first? So FastAPI is installed inside this project, not on the whole computer. Always activate the venv before installing packages or running the app.

Installing FastAPI and Uvicorn

You need two packages. Install them one at a time, or together:

pip install fastapi
pip install uvicorn

# or both at once
pip install fastapi uvicorn

pip also installs helper packages FastAPI depends on, such as starlette (the web toolkit underneath) and pydantic (data validation). That is normal.

PackageJobSimple meaning
FastAPIHelps you build the APIWhere you write routes and functions
UvicornRuns the FastAPI applicationA server that waits for requests and passes them to FastAPI

Verify the installation

pip list

If fastapi and uvicorn appear in the list (alongside helpers like starlette and pydantic), you are ready to write code.

Good to know FastAPI’s own docs also suggest pip install "fastapi[standard]", which installs FastAPI with Uvicorn and a few extras in one go. Installing the two packages separately, as above, works just as well.

Your first FastAPI application

Create a file named main.py inside the project folder:

fastapi-project/
│
├── venv/
│
└── main.py

Start with the smallest possible FastAPI application:

main.py
from fastapi import FastAPI

app = FastAPI()

Running python main.py prints nothing, and that’s expected. You have created the app, but nobody is running it as a server yet. That comes in a moment.

Understand the code

  • from fastapi import FastAPI brings the FastAPI class from the fastapi package into your file.
  • app = FastAPI() creates the application instance and stores it in a variable named app.
What is an application instance? FastAPI is like a blueprint. FastAPI() builds one real application from that blueprint, and app is that application. It will hold all your routes and settings.

Your first route

A route connects a URL path (like /) to a Python function. When someone visits that path, the function runs and its return value becomes the response. Add these lines below app = FastAPI():

main.py (complete)
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def home():
    return {"message": "Hello FastAPI"}

Parts of the route

@app.get("/") def home(): return {"message": "Hello FastAPI"}

@app: a decorator that registers the function with your application

.get: the HTTP method this route answers (GET)

("/"): the URL path (here, the home page)

home(): the function that runs for this path (any name you like)

the returned dictionary, which FastAPI sends back as JSON

GET /FastAPI finds the routehome()returns a dictJSON response

Running the app with Uvicorn

Make sure the venv is active, then ask Uvicorn to run your app:

uvicorn main:app --reload
INFO:     Will watch for changes in these directories: ['C:\\Kumar_All_Data\\fastapi-project']
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
INFO:     Started reloader process [12345] using WatchFiles
INFO:     Started server process [12346]
INFO:     Waiting for application startup.
INFO:     Application startup complete.

The important line is Uvicorn running on http://127.0.0.1:8000. Your API is live on your own computer.

Understand the command

uvicorn main:app --reload

uvicorn: start the server

main: the file main.py (without .py)

app: the variable inside it, app = FastAPI()

--reload: restart automatically when you save a change

So uvicorn main:app reads as: run the app object from the main.py file using Uvicorn.

127.0.0.1this computer (localhost)
8000the port
Ctrl+Cstop the server
  • 127.0.0.1 means this computer, also called localhost.
  • 8000 is the port: like a door number on your computer where the server listens.
  • To stop the server, click in the terminal and press Ctrl + C.
Keep this terminal open while you test. Close it and the server stops, so the browser can no longer reach your API.
--reload is for development only It watches your files and restarts on every save. On a production server you run Uvicorn without it.

Testing your first API

Open your browser at:

http://127.0.0.1:8000/
{"message":"Hello FastAPI"}

(Some browsers show it neatly formatted, with each key on its own line.) Now look at the terminal. Uvicorn logs one line for every request:

INFO:     127.0.0.1:52344 - "GET / HTTP/1.1" 200 OK

"GET / HTTP/1.1" 200 OK means: someone asked for / using GET, and the server answered successfully (200 OK).

The complete journey

This is the most important picture of the note: everything that happened when you pressed Enter.

Free bonus: /docs Visit http://127.0.0.1:8000/docs. FastAPI generates interactive documentation for every route automatically, and you can try each one from there.

The application instance, and more routes

app is your whole API in one object. Uvicorn runs it, and every route is stored inside it.

Routes are registered (added) to the application through app: @app.get("/") means “add this route to app”. Without app, the route has nowhere to go and Uvicorn has nothing to run.

Add two more routes to main.py:

@app.get("/about")
def about():
    return {"message": "About Page"}

@app.get("/contact")
def contact():
    return {"message": "Contact Page"}

Save the file. Because of --reload, Uvicorn restarts by itself. Test all three paths:

URLResponse
http://127.0.0.1:8000/{"message":"Hello FastAPI"}
http://127.0.0.1:8000/about{"message":"About Page"}
http://127.0.0.1:8000/contact{"message":"Contact Page"}

Invalid routes: 404

Visit a path that doesn’t exist:

http://127.0.0.1:8000/hello
{"detail":"Not Found"}
INFO:     127.0.0.1:52344 - "GET /hello HTTP/1.1" 404 Not Found

You never wrote @app.get("/hello"). FastAPI checks its route list, doesn’t find /hello, and replies with 404 Not Found.

Paths must match exactly /About (capital A) and /about are different paths. One small typo gives you a 404.

Uvicorn options: port and reload

Change the port

Uvicorn uses port 8000 by default. Stop the server (Ctrl + C), then:

uvicorn main:app --reload --port 8080
INFO:     Uvicorn running on http://127.0.0.1:8080 (Press CTRL+C to quit)

Now open http://127.0.0.1:8080/. A different port is useful when 8000 is already taken by another program, or when you want to run two apps at once.

Port already in use On Windows, [Errno 10048] ... only one usage of each socket address ... is normally permitted means another program is already using that port. (On Linux/macOS it reads [Errno 98] Address already in use.) Pick a different port.

Watch --reload work

Go back to port 8000 (uvicorn main:app --reload) and change the message in home():

return {"message": "Hello FastAPI"}      # before
return {"message": "Welcome to FastAPI"} # after

Save (Ctrl + S) and watch the terminal. Uvicorn notices the change and restarts by itself:

WARNING:  WatchFiles detected changes in 'main.py'. Reloading...
INFO:     Started server process [12400]
INFO:     Application startup complete.

Refresh the browser and {"message":"Welcome to FastAPI"} appears.

Basic project structure

So far everything lives in one file. Perfect for learning, but real applications have dozens of routes (users, products, orders, payments…). In one main.py the file becomes long and hard to manage, so we split the code into folders.

a common beginner-friendly structure
fastapi-project/
│
├── app/                  → the application package
│   ├── __init__.py       → marks app/ as a Python package (can be empty)
│   ├── main.py           → creates app = FastAPI()
│   │
│   └── routes/           → route files, grouped by topic (later module)
│       └── users.py
│
└── requirements.txt      → the package list

For now, only understand why each item is there. You will put code in routes/ in a later note.

Move the application into the app package

  1. 1
    Create a foldernamed app inside fastapi-project.
  2. 2
    Add an empty __init__.pyinside app.
  3. 3
    Move main.pyinto app, so it becomes app/main.py. Its code stays exactly the same.
  4. 4
    (Optional)create app/routes/users.py and leave it empty for now.

Now run the old command:

uvicorn main:app --reload
ERROR:    Error loading ASGI app. Could not import module "main".

Uvicorn looks for main.py in the project folder, but it moved into app/. Tell Uvicorn the new location:

uvicorn app.main:app --reload

The app runs again and http://127.0.0.1:8000/ shows the same response.

Run from the project folder Always start Uvicorn from fastapi-project, not from inside app. The import path app.main only makes sense from there.

requirements.txt

Your friend wants to run your project. How will they know which packages to install? You list them in requirements.txt:

pip freeze > requirements.txt
  • pip freeze lists every package installed in the venv with its exact version.
  • > saves that list into a file instead of printing it.
requirements.txt (part of it; your versions will differ)
annotated-types==0.7.0
anyio==4.6.2
fastapi==0.115.6
pydantic==2.10.3
starlette==0.41.3
uvicorn==0.32.1
...

Each line has the form package==version. On a new computer (or a new venv), one command installs everything:

pip install -r requirements.txt

-r means read the package names from this file.

Keep it fresh Run pip freeze > requirements.txt again whenever you install a new package.
In the field (FDE) When you hand an API to a customer’s team or deploy it on their server, “clone, create venv, pip install -r requirements.txt, uvicorn app.main:app” should be the entire setup. If it needs more, write it in the README.

The API must have these four routes:

RouteWhat it returns
GET /A welcome message
GET /studentFull student details: name, course, skills
GET /courseCourse name and duration
GET /skillsList of skills

Setup commands

Windows (on Linux/macOS use source venv/bin/activate)

mkdir fastapi-project
cd fastapi-project
python -m venv venv
venv\Scripts\activate
pip install fastapi uvicorn

Then create the app folder with an empty __init__.py and this main.py:

app/main.py
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def home():
    return {"message": "Welcome to the Student API"}

@app.get("/student")
def student():
    return {
        "name": "Rahul",
        "course": "BCA",
        "skills": ["Python", "FastAPI", "SQL"]
    }

@app.get("/course")
def course():
    return {"course": "BCA", "duration": "3 Years"}

@app.get("/skills")
def skills():
    return {"skills": ["Python", "FastAPI", "SQL"]}

Run and test it

uvicorn app.main:app --reload
Open (after 127.0.0.1:8000)Browser output
/{"message":"Welcome to the Student API"}
/student{"name":"Rahul","course":"BCA","skills":["Python","FastAPI","SQL"]}
/course{"course":"BCA","duration":"3 Years"}
/skills{"skills":["Python","FastAPI","SQL"]}

The Python list ["Python", "FastAPI", "SQL"] became a JSON array, and the dictionary returned by /student became a JSON object.

Save the dependencies

pip freeze > requirements.txt

Yes. Save the file, watch the terminal print “Reloading…”, then refresh /student.

Key terms

FastAPI
A Python framework for building APIs, where each endpoint is a normal Python function and return values are sent back as JSON automatically.
Uvicorn
The server program that listens for HTTP requests on a port and passes them to a FastAPI application.
Backend
The hidden part of an application that stores data and does the work; FastAPI is used to build it.
Application instance
The object created by app = FastAPI(); it holds every route and setting and is what Uvicorn runs.
Route
A connection between an HTTP method plus URL path, such as GET /about, and the Python function that handles it.
Decorator (@app.get)
The line above a function that registers it with the app as the handler for a given method and path.
localhost (127.0.0.1)
The address that always means “this computer”, used to reach a server running on your own machine.
Port
A numbered door on a computer where a server listens; Uvicorn uses 8000 unless you pass --port.
--reload
A Uvicorn option for development that restarts the server automatically whenever a code file is saved.
404 Not Found
The status FastAPI returns, with {"detail":"Not Found"}, when no route matches the requested path.
app.main:app
Uvicorn’s target format: the import path of the module (app/main.py), a colon, then the name of the FastAPI variable inside it.
__init__.py
A file (often empty) that marks a folder as a Python package, so its modules can be imported with dotted paths.

Self-check

Pick an answer. You’ll see right away whether it’s correct and why.

What is the job of Uvicorn?

  1. It defines the routes
  2. It runs the app as a server and passes requests to FastAPI
  3. It converts Python dicts to JSON
  4. It creates the virtual environment

FastAPI is where you build the API; Uvicorn is the server that listens on a port and hands each request to it.

You run python main.py on a file with only app = FastAPI(). What happens?

  1. A server starts on port 8000
  2. It raises an error
  3. Nothing is printed; the app is created but not served
  4. The browser opens

Creating the app object doesn’t start a server. You need uvicorn main:app for that.

In uvicorn main:app, what does the part after the colon refer to?

  1. The variable holding FastAPI() inside main.py
  2. The folder name
  3. The port
  4. The function for the home route

Before the colon is the module (main.py); after it is the name of the FastAPI object in that module.

Your route function returns {"age": 21}. What does the browser receive?

  1. The text age=21
  2. An HTML page
  3. {"age": "21"} with 21 as a string
  4. A JSON object where 21 is a number

FastAPI converts the dict to a JSON object and keeps numbers as numbers.

You visit /About but your route is @app.get("/about"). What do you get?

  1. The about page
  2. 404 with {"detail":"Not Found"}
  3. 500 Internal Server Error
  4. A redirect to /about

Paths are case-sensitive and must match exactly, so no route is found.

You moved main.py into an app/ package. Which command now works from the project folder?

  1. uvicorn main:app
  2. uvicorn app:main
  3. uvicorn app.main:app
  4. uvicorn app/main.py

The module path is app.main (folder.file), followed by :app for the variable.

Uvicorn says the address is already in use. What is the simplest fix?

  1. Run on another port with --port 8080
  2. Remove --reload
  3. Rename main.py
  4. Reinstall FastAPI

Another program holds port 8000; choosing a free port lets your server start.

You edit a route, save, and refresh, but the old response still shows. The terminal shows no “Reloading”. Most likely cause?

  1. FastAPI caches responses forever
  2. The browser is offline
  3. The route needs a POST
  4. The server was started without --reload

Without --reload, Uvicorn keeps running the old code until you restart it.

All of it, in one sentence

Create a venv, install FastAPI and Uvicorn, make app = FastAPI(), attach functions with @app.get(...), and run uvicorn app.main:app --reload: every request then flows browser → Uvicorn → FastAPI → your function, and whatever you return comes back as JSON.
