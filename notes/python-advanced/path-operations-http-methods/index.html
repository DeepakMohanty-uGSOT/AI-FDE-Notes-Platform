Path Operations & HTTP Methods

Go beyond reading data: build an API that can add, replace, change and delete records, and test every request from your browser with Swagger UI.

What is a path operation?

The post office countersYour local post office has one address, but several counters inside: one for speed post, one for money orders, one for collecting parcels. The address tells you where to go; the counter decides what gets done; the clerk at that counter does the work. In FastAPI the address is the path, the counter is the HTTP method, and the clerk is your Python function.

So far our APIs could only read data. Real apps also add, change and remove data. In this note we build a small Books API that does all four, and test it with FastAPI’s built-in testing page.

Methods & CRUDSetupGETSwagger UIPOSTPUTPATCHDELETE404 vs 405Student CRUD API

Until now we used the word route. FastAPI’s official name for it is path operation: an operation (an action) performed on a path (a URL). Every path operation has three parts:

@app.get("/books") def get_books(): ...

Method: WHAT to do there? GET

Path: WHERE? Which URL? /books

Function: WHO does the work? get_books()

Together they form one path operation: GET /books → get_books().

HTTP methods and CRUD

This section is short. The goal is only to understand what each method does before we write any code.

Every request a client sends carries a method. The method is a verb: it tells the server what the client wants to do. Typing a URL into the browser always sends GET, which is why we have only used GET so far.

MethodIn one line
GETRetrieves data from the server without changing it.
POSTSends new data to the server to create a resource.
PUTReplaces an existing resource completely with the data sent.
PATCHUpdates only the specified fields of an existing resource.
DELETERemoves an existing resource from the server.
Resource? A resource simply means “a thing your API manages”: a book, a student, an order. To know more about HTTP methods, refer to the previous notes on HTTP methods.

Why can the same URL do different things?

Because the URL and the method have different jobs:

The URL is the noun

It says which thing: /books, /books/1.

The method is the verb

It says what to do with it: read it, add to it, change it, remove it.

So GET /books (show all books) and POST /books (add a book) use the same URL but are two different requests, handled by two different functions.

The four things every app does with data: CRUD

CRUD stands for Create, Read, Update, Delete. These are the four basic things any app does with data, and each has a matching HTTP method:

Create → POSTRead → GETUpdate → PUT / PATCHDelete → DELETE

GET: read items

Definition: GET retrieves data from the server without changing it. To know more, refer to the previous notes on API Basics.

Before we can add, change or remove books, we need some books. We keep them in a Python list of dictionaries, exactly like the student list in the previous note. Then we add two GET routes: one returns all books, the other returns one book by its id (a path parameter, which the next note covers in depth).

app/main.py
from fastapi import FastAPI

app = FastAPI()

books = [
    {"id": 1, "title": "Python Basics", "author": "Ravi"},
    {"id": 2, "title": "Learning FastAPI", "author": "Anita"}
]

@app.get("/books")
def get_books():
    return books

@app.get("/books/{book_id}")
def get_book(book_id: int):
    for book in books:
        if book["id"] == book_id:
            return book
    return {"message": "Book not found"}

Testing APIs with Swagger UI (/docs)

The problem

So far we tested everything by typing a URL into the browser. But the browser’s address bar can only send GET requests. There is no box to choose POST or DELETE, and no place to type the data for a new book.

What is Swagger UI?

Swagger UI is an interactive web page that lists every route in your API and lets you send any request with a few clicks: choose the method, fill in path values, type a request body, and see the response.

The best part: FastAPI creates this page for you automatically by reading your code. You do not install or write anything. It is always available at /docs while your server is running.

Built from your code Every time you add a route and save the file, it appears on this page after a refresh. From now on, we test every method here.

Each coloured bar is one path operation. The colour shows the method: GET is blue, and soon you will see POST in green, PUT in orange, PATCH in teal and DELETE in red. The grey title next to the path (“Get Books”) comes from your function name.

POST: add an item

Definition: POST sends new data to the server to create a resource. To know more, refer to the previous notes on API Basics.

New idea: the request body

With GET, everything the server needs fits in the URL (/books/2). But to add a book, we must send the whole book: its id, title and author. That data is too big and too important to squeeze into the URL, so it travels in a separate part of the request called the request body.

  • The request body is the data sent inside the request, not in the URL.
  • In APIs the body is almost always written in JSON, the same format our responses use.
  • GET requests normally have no body. POST, PUT and PATCH usually do.

Write the POST route

app/main.py · add below the GET routes
@app.post("/books")
def add_book(book: dict):
    books.append(book)
    return {"message": "Book added", "book": book}

PUT: replace an item

Definition: PUT replaces an existing resource completely with the data sent. To know more, refer to the previous notes on API Basics.

How PUT works

To replace a book, the server needs two things: which book to replace, and what to replace it with. So a PUT route takes values from two places:

ValueComes fromExample
book_idthe URL (path parameter)/books/1
updated_bookthe request body (JSON)the new full record

To replace an item in a list we need its position (index). Python’s enumerate() gives us the position and the item together in the loop:

for index, book in enumerate(books):
    print(index, book["title"])

# 1 Learning FastAPI

Write the PUT route

app/main.py
@app.put("/books/{book_id}")
def update_book(book_id: int, updated_book: dict):
    for index, book in enumerate(books):
        if book["id"] == book_id:
            books[index] = updated_book
            return {"message": "Book updated", "book": updated_book}
    return {"message": "Book not found"}

The first book is now just {"title": "Python Masterclass"}. The id and author are gone. PUT did exactly what it promises: it replaced the whole record with what we sent.

It gets worse. Try GET /books/1 now:

The loop in get_book() reads book["id"] on the first book, which no longer has an "id" key. Python raises a KeyError, and the client gets 500 Internal Server Error. Because the broken record is first in the list, even GET /books/2 now fails the same way.

With PUT, always send the complete record. Save main.py to restart the server and get the original two books back. If you only want to change one field, use PATCH, which is the next section.

PATCH: change part of an item

Definition: PATCH updates only the specified fields of an existing resource. To know more, refer to the previous notes on API Basics.

How PATCH works

Instead of throwing the old record away, PATCH keeps it and only overwrites the keys you send. Python dictionaries already have a method that does exactly this: dict.update().

book = {"id": 2, "title": "Learning FastAPI", "author": "Anita"}
book.update({"author": "Anita Sharma"})
print(book)   # {'id': 2, 'title': 'Learning FastAPI', 'author': 'Anita Sharma'}

Write the PATCH route

app/main.py
@app.patch("/books/{book_id}")
def patch_book(book_id: int, changes: dict):
    for book in books:
        if book["id"] == book_id:
            book.update(changes)
            return {"message": "Book partially updated", "book": book}
    return {"message": "Book not found"}

We do not need enumerate() here, because we change the existing dictionary in place instead of replacing it.

Test PATCH

Saving the file restarted the server, so the data is back to the original two books. Send PATCH to /books/2 with:

{
    "author": "Anita Sharma"
}

Only author changed. id and title are still there.

PUT vs PATCH

This is the most important comparison in this note. Let’s send the same body to the same book (book 2) with both methods, starting from fresh data each time.

PUTPATCH
What you sendThe complete recordOnly the fields that changed

Missing fieldsAre lostStay the same

DELETE: remove an item

Definition: DELETE removes an existing resource from the server. To know more, refer to the previous notes on HTTP methods.

To delete a book, the server only needs to know which book. The id in the URL is enough, so DELETE needs no request body.

app/main.py
@app.delete("/books/{book_id}")
def delete_book(book_id: int):
    for book in books:
        if book["id"] == book_id:
            books.remove(book)
            return {"message": "Book deleted"}
    return {"message": "Book not found"}

books.remove(book) is a normal Python list method: it removes that item from the list. (Removing while looping is safe here only because we return straight away.)

Same path, different methods: 404 vs 405

All five methods are written. Look at the complete picture in Swagger UI:

We have only two paths (/books and /books/{book_id}) but six path operations. FastAPI chooses the function using both the path and the method:

RequestFunction that runs
GET /books/1get_book()
PUT /books/1update_book()
PATCH /books/1patch_book()
DELETE /books/1delete_book()

Same URL, four different actions.

Experiment: a method that does not exist

What if we send DELETE to /books? We never wrote @app.delete("/books"). Swagger UI only shows routes that exist, so we use curl, a command-line tool that sends any HTTP request. Open a second terminal (keep the server running in the first) and run:

curl.exe -X DELETE http://127.0.0.1:8000/books
curl.exe http://127.0.0.1:8000/authors
  • -X DELETE chooses the method. Without -X, curl sends GET.
  • On Windows PowerShell, type curl.exe. Plain curl is a PowerShell shortcut for a different command. On Linux/macOS just type curl.

And in the server terminal:

StatusMeaning
404 Not FoundThe path does not exist.
405 Method Not AllowedThe path exists, but not with this method.

Mapping HTTP methods to FastAPI decorators

Look at all our decorators together. The pattern is simple: the decorator name is the HTTP method in lowercase.

Every new route, same recipe Once this pattern is clear, every new route is easy: pick the method, write @app.<method>("/path"), and write the function below it.
Where Pydantic comes in book: dict accepts any JSON object, even {"colour": "blue"}. Replace dict with a Pydantic model (like the ones from the previous note) and FastAPI validates every body for you, answering bad data with a 422 error. That is the natural next step for this API.

Final outcome

Remember The path says which thing, the method says what to do with it. Together with the function, they make one path operation.

Key terms

Path operation
FastAPI’s name for a route: one HTTP method on one path, handled by one Python function, e.g. GET /books → get_books().
HTTP method
The verb in a request (GET, POST, PUT, PATCH, DELETE) that tells the server what the client wants to do.
Resource
Any thing an API manages, such as a book, a student or an order, usually identified by a URL.
CRUD
Create, Read, Update, Delete: the four basic data operations, mapped to POST, GET, PUT/PATCH and DELETE.
Request body
Data sent inside a request rather than in the URL, usually JSON; used by POST, PUT and PATCH.
Swagger UI
The interactive documentation page FastAPI generates automatically at /docs, where you can send any request and see the response.
PUT
Replaces an entire resource with the data sent; any field you leave out is lost.
PATCH
Updates only the fields sent and keeps all the others unchanged.
405 Method Not Allowed
The status returned when the path exists but has no path operation for the method used.
404 Not Found
The status returned when no route matches the requested path at all.
curl
A command-line tool for sending HTTP requests with any method; -X chooses the method (type curl.exe in PowerShell).

Self-check

Pick an answer. You’ll see right away whether it’s correct and why.

Which three parts make up one path operation?

  1. Host, port and path
  2. Path, method and function
  3. URL, body and headers
  4. Request, response and status

The path says where, the method says what, and the function does the work.

Why can’t you test a POST route by typing its URL into the browser’s address bar?

  1. POST routes have no URL
  2. Browsers block JSON
  3. FastAPI hides POST routes
  4. The address bar always sends GET

The address bar can only send GET and has no place for a body. Swagger UI or curl can send any method.

Book 1 is {"id": 1, "title": "Python Basics", "author": "Ravi"}. You send PUT /books/1 with {"title": "X"}. What is book 1 now?

  1. {"title": "X"}
  2. {"id": 1, "title": "X", "author": "Ravi"}
  3. Unchanged
  4. Deleted

Our PUT replaces the whole record with the body, so id and author are lost.

Which Python tool does our PATCH route rely on?

  1. enumerate()
  2. list.remove()
  3. dict.update()
  4. list.append()

dict.update() overwrites only the keys you pass and keeps the rest, which is exactly PATCH’s behaviour.

Your API has GET /books and POST /books only. What does DELETE /books return?

  1. 404 Not Found
  2. 405 Method Not Allowed
  3. 200 with an empty list
  4. 422 Unprocessable Content

The path exists, but no path operation handles DELETE on it, so the answer is 405.

You POST a new book, then save main.py. The new book is gone. Why?

  1. POST never saves anything
  2. Swagger UI cleared it
  3. The reload restarted the server, rebuilding the in-memory list
  4. The book had an invalid id

The list lives in the server’s memory and is recreated from the code on every restart.

Which request normally carries no body?

  1. POST /books
  2. PUT /books/1
  3. PATCH /books/1
  4. DELETE /books/1

DELETE only needs to know which item, and the id in the URL says that.

All of it, in one sentence

A path operation is a path plus a method plus a function: the path says which thing, the method says what to do with it (GET read, POST add, PUT replace, PATCH change part, DELETE remove), and Swagger UI at /docs lets you test them all.
