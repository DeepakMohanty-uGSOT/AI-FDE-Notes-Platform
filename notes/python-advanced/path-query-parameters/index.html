Path & Query Parameters

Let the client tell your API exactly which item it wants, and how it wants a list back: filtered, combined and one page at a time.

Why do APIs need parameters?

At the library counter“Give me a book” is not enough for the librarian. You either say which book (“book number 101”) or what kind (“only science books, five at a time”). Those extra details are parameters: path parameters say which one, query parameters say how you want the list.

Quick recap: what is a route?

A route connects a URL path to a Python function:

@app.get("/about")
def about():
    return {"message": "About Page"}

When a request comes in, FastAPI compares its path (e.g. /about) with the path of every route. If one matches, it runs that function; if none does, it returns 404 Not Found. How it compares depends on whether the route is static or dynamic.

Static routes

A static route has a completely fixed path, such as /about, /contact, /students or /students/1. FastAPI runs it only when the URL is exactly the same, character for character. Even a small difference means no match.

Static routes are perfect for things that never change, like an About page, a Contact page or the list of all students.

The problem with static routes

To show one student at a time by id, static routes force you to write one route per student. This causes real problems:

/students/1   →  student_1()
/students/2   →  student_2()
/students/3   →  student_3()
...           →  ...

Repeated code

Every function does the same job; only the number changes.

New student = new code

Every admission means writing code and restarting the app.

Impossible at scale

A college with 5,000 students needs 5,000 functions.

Missing routes break

Forget /students/4 and that student just gets a 404.

Look closely: /students/ is always the same and only the number at the end changes. What if we wrote the fixed part once and left a blank for the number?

Dynamic routes

A dynamic route has two parts: a fixed part that must match exactly (/students/), and a changing part in curly brackets ({student_id}). The curly part is a placeholder, a blank filled with whatever the client sends.

@app.get("/students/{student_id}")

When a request comes in, FastAPI checks the fixed part first. If it matches, FastAPI takes whatever is written in the place of the blank and gives it to your function in a variable named student_id.

So one dynamic route can answer /students/1, /students/2, /students/250, and every other student, with one function.

Static routeDynamic route
PathCompletely fixed: /students/1Fixed part + blank: /students/{student_id}
URLs it matchesExactly oneMany: any value in the blank
Value from the URLNothing is passed to the functionThe value in the blank is passed to the function
Best forPages that never change: /about, /studentsOne item out of many

So, what is an API parameter?

The value the client puts in the blank (like 250 in /students/250) is a parameter: an extra piece of information sent with the request so the API knows exactly what to return. FastAPI has two main kinds:

KindWhere it goesExampleAnswers
Path parameterInside the path, in the blank/students/250Which item?
Query parameterAt the end, after ?/students?course=BCAHow should the list come back?

Practical: from static routes to one dynamic route

Step 1: static routes, one per student:

from fastapi import FastAPI

app = FastAPI()

@app.get("/students/1")
def student_1():
    return {"id": 1, "name": "Rahul"}

@app.get("/students/2")
def student_2():
    return {"id": 2, "name": "Priya"}

@app.get("/students/3")
def student_3():
    return {"id": 3, "name": "Aman"}

/students/1 works because a route with that exact path exists. /students/4 gives 404 Not Found, because no route has that exact path. This is exactly the problem described above.

Step 2: replace all of them with one dynamic route:

from fastapi import FastAPI

app = FastAPI()

@app.get("/students/{student_id}")
def get_student(student_id: int):
    return {"student_id": student_id}

For /students/250, FastAPI matched the fixed part /students/, put 250 into the blank {student_id}, and called get_student(student_id=250). The function simply returned the value it received.

Remember Static route = exact path, one URL. Dynamic route = fixed part + {blank}, many URLs. The value in the blank is a path parameter.

Path parameters: pick one specific item

A path parameter is a changing value written directly inside the URL path. It tells the API which specific item you want.

In FastAPI, mark the changing part with { } and add a function parameter with the same name:

@app.get("/students/{student_id}")
def get_student(student_id: int):
    return {"student_id": student_id}
  • {student_id} in the route means “this part of the URL can change”.
  • student_id: int in the function means “give me that value, as an integer”.
  • The two names must match exactly.

How path parameters work

When are path parameters used?

When to use a path parameter? Ask: “Which resource?” If the value points to one specific thing (a student, a user, an order), use a path parameter.

Type conversion and validation

String vs integer

Why write student_id: int? Remove : int and add a print() to see the value and its type in the terminal:

@app.get("/students/{student_id}")
def get_student(student_id):
    print(student_id, type(student_id))
    for student in students:
        if student["id"] == student_id:
            return student

    return {"message": "Student not found"}

Priya exists, yet we get “Student not found”! The terminal explains why: 2 <class 'str'>. Everything in a URL is text, so student_id is the string "2", and in Python "2" == 2 is False. The loop never finds a match.

Now put the type back, def get_student(student_id: int):, and try again:

This time the terminal prints 2 <class 'int'>. FastAPI read the type hint and converted the text to a number for us, so the comparison works.

Tidy up You can now delete the print() line. It was only for learning.

Invalid input

What if the value cannot become a number?

http://127.0.0.1:8000/students/abc

FastAPI rejected the request before our function even ran, with status 422 Unprocessable Content. "loc": ["path", "student_id"] says exactly where the problem is. (That message should look familiar: FastAPI uses Pydantic under the hood to do this checking.)

A type hint does two jobs It converts good input ("2" → 2) and rejects bad input ("abc" → 422). You get both for free.

Multiple path parameters and route order

A URL can carry more than one path parameter, for example “course 5 of student 2”:

/students/2/courses/5

student_id = 2

course_id = 5

Add this route:

@app.get("/students/{student_id}/courses/{course_id}")
def get_course(student_id: int, course_id: int):
    return {
        "student_id": student_id,
        "course_id": course_id
    }

Each { } needs a function parameter with the same name. Both are converted and checked separately, so /students/2/courses/abc gives a 422 that points at course_id:

{"detail": [{"type": "int_parsing", "loc": ["path", "course_id"],
             "msg": "Input should be a valid integer, unable to parse string as an integer", "input": "abc"}]}

Route order: fixed before dynamic

Many apps have a special URL /students/me meaning “the logged-in student”. It looks very similar to /students/{student_id}. Add it below the dynamic route:

from fastapi import FastAPI

app = FastAPI()

@app.get("/students/{student_id}")
def get_student(student_id: int):
    return {"student_id": student_id}

@app.get("/students/me")
def get_current_student():
    return {"message": "This is the logged-in student"}

A 422 saying "me" is not a valid integer! FastAPI checks routes from top to bottom and uses the first whose pattern fits. me fits into {student_id}, so FastAPI picks that route and then fails to turn "me" into a number. Our /students/me route is never reached.

Now move the fixed route above the dynamic one:

from fastapi import FastAPI

app = FastAPI()

@app.get("/students/me")
def get_current_student():
    return {"message": "This is the logged-in student"}

@app.get("/students/{student_id}")
def get_student(student_id: int):
    return {"student_id": student_id}

Both work now: /students/me hits the fixed route, and /students/5 still goes to the dynamic route.

Query parameters: how you want the list

Path parameters answer “which one?”. Often we want a list, filtered or arranged a certain way: “show me only BCA students”. For that we use the second kind of parameter.

A query parameter is a key=value pair added at the end of the URL, after a question mark ?. It gives extra instructions such as filtering, searching, sorting or pagination.

http://127.0.0.1:8000/students?course=BCA&age=21

Host and port: where the server is.

Path: the main resource, /students.

? starts the query string; & joins one pair to the next.

Key: the parameter name (course, age).

Value: what the client wants for that key.

In /students?course=BCA: /students is the main path, ? marks where the query parameters begin, and course=BCA is the query parameter (key course, value BCA).

Query parameter structure

When are query parameters used?

When to use a query parameter? Ask: “How do I want the resources returned?” Filtered? Sorted? One page at a time? Then use query parameters.

First practical example

Change the get_all_students() route into this (keep the students list):

@app.get("/students")
def get_students(course: str):
    return {"course": course}

Notice: the route is just "/students". There is no {course} in it, yet the function has a course parameter.

Filtering, optional parameters and defaults

Use the value to filter

Returning {"course": "BCA"} is not very useful. Let’s use the value to filter real data:

@app.get("/students")
def get_students(course: str):
    result = []

    for student in students:
        if student["course"] == course:
            result.append(student)

    return result

Only Rahul and Aman (the BCA students) come back. This is why query parameters exist: the same route returns different results based on what the client asks.

Watch out: values are case-sensitive /students?course=bca returns an empty list [], because "bca" != "BCA" in Python. An empty list is still a valid answer: “I searched, and nothing matched.”

Making the filter optional

We want /students to return everyone and /students?course=BCA only BCA students. So course must be optional:

@app.get("/students")
def get_students(course: str | None = None):
    if course:
        return [
            student for student in students
            if student["course"] == course
        ]

    return students
  • str | None means “a string, or nothing”.
  • = None means “if the client doesn’t send it, use None”. The default is what makes it optional.
  • if course: is true only when a course was actually sent; otherwise we return the whole list.

Both URLs work now with one function.

Default values

A query parameter can also have a normal default. To see it clearly, use a small default of 2:

@app.get("/students")
def get_students(limit: int = 2):
    return {"limit": limit, "students": students[:limit]}

Without ?limit=, FastAPI uses the default 2. With ?limit=3, the client’s value wins. Real APIs usually use something like limit: int = 10.

Multiple query parameters

Clients often combine filters, for example “BCA students who are 21”. Pairs are joined with &:

/students?course=BCA&age=21
@app.get("/students")
def get_students(
    course: str | None = None,
    age: int | None = None
):
    result = students

    if course:
        result = [
            student for student in result
            if student["course"] == course
        ]

    if age:
        result = [
            student for student in result
            if student["age"] == age
        ]

    return result

We start with all students in result, and each filter that was sent makes the list smaller.

RequestResult
/studentsAll 4 students
/students?course=BCARahul, Aman
/students?age=21Rahul, Sneha
/students?course=BCA&age=21Rahul

Notice that age was declared as int, so ?age=21 was converted to the number 21 automatically, just like path parameters.

A subtle trap if age: is False for 0 as well as for None, so ?age=0 would be ignored. When 0 is a meaningful value, write if age is not None: instead.

Pagination with skip and limit

Imagine 50,000 students. Sending all of them in one response is slow for the server, heavy on the network and useless for the user, who sees about 10 on screen. So we send data one page at a time. This is pagination.

ParameterMeaning
skipHow many records to jump over
limitHow many records to return
@app.get("/students")
def get_students(
    skip: int = 0,
    limit: int = 10
):
    return students[skip:skip + limit]

students[skip:skip + limit] is normal Python list slicing. For skip=2, limit=2 it becomes students[2:4]: the items at index 2 and 3.

Browser output

In the field (FDE) Customer systems (CRMs, ticketing tools) almost always paginate their APIs, often with offset/limit, the same idea as skip/limit. When you pull their data, loop page by page until you get an empty list, instead of assuming one call returns everything.

Path and query together, and how to tell them apart

Both kinds can appear in the same URL, for example “the courses of student 2, but only for semester 4”:

/students/2/courses?semester=4

Path parameter student_id: inside { } in the route, required.

Query parameter semester: not in the route, optional here.

@app.get("/students/{student_id}/courses")
def get_courses(
    student_id: int,
    semester: int | None = None
):
    return {
        "student_id": student_id,
        "semester": semester
    }

Without ?semester=4 the value is Python None, which appears as null in JSON.

    1: {4: ["Python", "DBMS", "Computer Networks"]},
    5: {4: ["Java", "Operating Systems", "Web Development"]}
}


@app.get("/students")
def get_students(
    course: str | None = None,
    city: str | None = None,
    year: int | None = None,
    skip: int = 0,
    limit: int = 10
):
    result = students

    if course:
        result = [s for s in result if s["course"] == course]
    if city:
        result = [s for s in result if s["city"] == city]
    if year:
        result = [s for s in result if s["year"] == year]

    return result[skip:skip + limit]


@app.get("/students/{student_id}")
def get_student(student_id: int):
    for student in students:
        if student["id"] == student_id:
            return student
    return {"message": "Student not found"}


@app.get("/students/{student_id}/courses")
def get_student_courses(student_id: int, semester: int | None = None):
    student_courses = courses.get(student_id, {})

    if semester:
        return {
            "student_id": student_id,
            "semester": semester,
            "subjects": student_courses.get(semester, [])
        }

    return {"student_id": student_id, "courses": student_courses}

How it works

  • get_students() handles every /students?... request. Each filter is optional and applied only if sent. Pagination (skip, limit) is applied last, on the filtered result.
  • get_student() uses a path parameter to return one student.
  • get_student_courses() combines a path parameter (student_id) with an optional query parameter (semester). courses is a small dictionary: student id → semester → list of subjects.

Key terms

Static route
A route with a completely fixed path that matches only one exact URL, such as /about.
Dynamic route
A route whose path has a fixed part plus one or more {placeholders}, so one function can serve many URLs.
Path parameter
A value taken from a {placeholder} inside the URL path, used to identify one specific resource, e.g. 2 in /students/2.
Query parameter
A key=value pair after the ? in a URL, used to filter, search, sort or paginate; in FastAPI, any simple-typed function parameter not named in the route.
Query string
The part of a URL after ?, holding query parameters joined by &.
Type conversion
FastAPI turning text from the URL into the declared type, such as "2" into the integer 2, based on the type hint.
422 Unprocessable Content
The status FastAPI returns when request data is missing or cannot be converted to the declared type; the body lists each problem with its loc.
loc
The field in a 422 error that says where the bad value was, such as ["path", "student_id"] or ["query", "course"].
Route order
FastAPI checks routes top to bottom and uses the first match, so fixed paths must come before dynamic paths that could also match them.
Pagination
Returning a large list one page at a time, typically with skip (records to jump over) and limit (records to return).

Self-check

Pick an answer. You’ll see right away whether it’s correct and why.

The route is /students/{student_id} but the function is def get_student(student_id): with no type hint. /students/2 returns “Student not found”. Why?

  1. The route is static
  2. FastAPI drops untyped parameters
  3. student_id is the string "2", and "2" == 2 is False
  4. Priya’s id is a string

URL values are text. Without : int nothing converts it, so the comparison with the integer id fails.

What does /students/abc return when student_id: int?

  1. 422 with loc: ["path", "student_id"]
  2. 404 Not Found
  3. 200 with “Student not found”
  4. 500 Internal Server Error

FastAPI validates before your function runs; “abc” cannot become an int, so it answers 422 and points at the path parameter.

In def get_students(course: str): on route /students, what kind of parameter is course?

  1. Path parameter
  2. Request body
  3. Header
  4. Required query parameter

It is not in the route’s { } and has a simple type, so it is a query parameter. No default makes it required.

/students/me is defined below /students/{student_id} (int). What happens on GET /students/me?

  1. The /students/me route runs
  2. 422, because the dynamic route caught “me”
  3. 404 Not Found
  4. Both routes run

Routes are checked top to bottom; “me” fits {student_id} first, then fails int conversion.

With 4 students, what does /students?skip=3&limit=10 return?

  1. Nothing, an error
  2. All 4 students
  3. Only Sneha
  4. The first 3 students

students[3:13] returns whatever exists from index 3 on: just the last student.

How do you make a query parameter optional?

  1. Give it a default, e.g. course: str | None = None
  2. Write it as Optional with no default
  3. Put it in { } in the route
  4. Name it starting with an underscore

A default value is what makes a parameter optional; | None just allows the value None.

A client sends /students?course=BCA?age=21. What happens?

  1. Both filters apply
  2. Only the age filter applies
  3. 422 error
  4. One pair, course="BCA?age=21", so nothing matches

Only the first ? starts the query string; pairs must be joined with &.

Which URL is best for “page 2 of BCA students, 5 per page”?

  1. /students/BCA/2/5
  2. /students?course=BCA&skip=5&limit=5
  3. /students?course=BCA&skip=2&limit=5
  4. /students/2?course=BCA
