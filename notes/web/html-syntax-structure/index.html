HTML Basics: Syntax and Structure

Learn the grammar of HTML (tags, elements and attributes), build and run your first page, and understand the skeleton that every web page is built on.

Why Tim Berners-Lee created HTML

Letters without addressesImagine every office in a city keeping its files in its own cupboard, in its own language, with no postal system between them. To read a file you would have to walk into that office yourself. That was information before the Web. HTML gave every document a common language and a way to point to any other document.

Before the Web, researchers stored information on many different computers, each with its own system. To read the data you needed special software or direct access to that machine. There was no easy way to link or browse documents across a network.

Tim Berners-Lee, working at CERN, set out to fix this. While building the World Wide Web he needed a simple, universal language that could:

Display information

Show text, images and links on any computer.

Link documents

Jump from one document to another with a click.

Be easy to write

Simple enough for anyone to read and write, not just programmers.

So he created HTML (HyperText Markup Language): a simple markup language for structuring and displaying content on web pages. He proposed the Web in 1989, and the first HTML pages appeared in 1990–91. In one line: HTML turned the Internet into the World Wide Web by giving everyone a standard way to write, view and link documents online.

What HTML is

HTML stands for HyperText Markup Language. It is the standard language for creating and structuring web pages. It tells the web browser what each piece of content is (a heading, a paragraph, an image, a link, a video) so the browser can display it properly.

HyperText

The way web pages are linked together. The clickable links that take you from one page to another are hypertext.

Markup

Labels placed around text to define what it is and how it should be presented.

Language

A fixed set of rules and syntax you follow when writing the code.

A real-world analogy makes it click:

The frame of a houseThink of a house being built. The walls, doors and windows give it its basic shape and layout. HTML does the same for a web page: it tells the browser what each part is, a heading, a paragraph, an image or a link. Paint and decoration (CSS) and electricity (JavaScript) come later.

HTML is the foundation of every website. It gives the page structure so that browsers can show it correctly to users.

HTML syntax: the grammar of the web

HTML syntax is the set of grammar rules for writing HTML. HTML is the language you use to talk to the browser:

Correct English grammar

Other people understand you. “Please build a house.”

Correct HTML syntax

The browser understands you and builds the page exactly as planned.

Say “house build a please” and people get confused. Write this, and the browser gets confused:

<h1><p>My Page</h1></p>
Why it matters With wrong syntax the browser has to guess what you meant. It may guess wrong, and the page can look broken. Correct syntax means the page is built exactly as you planned.

Before the rules, you need three words: tag, element and attribute.

Tags: labels for content

Kitchen jarsIn a kitchen you stick labels on jars: Sugar, Salt, Chai patti. The labels tell you what is inside. HTML tags label parts of a web page so the browser knows what each part is: a heading, a paragraph, an image.

A tag starts with the less-than sign <, then the tag name, then the greater-than sign >. A closing tag is the same but has a forward slash / before the name.

KindPatternExample
Opening tag<tagname><p> · start of the paragraph
Closing tag</tagname></p> · end of the paragraph
<p>This is a paragraph.</p>

Together, the two tags tell the browser: “this text is a paragraph.” A tag is a small piece of code that acts like a label.

Two types of tags

Paired (container) tags

Come in pairs: <tagname> … </tagname>. Everything between them is affected by the tag.

Void (empty / singular) tags

Have no closing tag and wrap no content. Used for things like line breaks and images.

paired tag
<h1>Hello World</h1>
void tags
<br>                                    <!-- inserts a line break -->
<img src="image.jpg" alt="Example image">
<hr>                                    <!-- draws a horizontal line -->
<input type="text">
<meta charset="UTF-8">
<link rel="stylesheet" href="style.css">
Don’t worry yet You will meet all of these tags properly in the next notes. For now, remember what a tag is, why we use it, and its basic shape.

Elements: the complete building block

An HTML element is the complete unit that represents one part of a page. It tells the browser what to display and how. An element usually has three parts: an opening tag (start), the content (what appears on the page) and a closing tag (end).

<p>This is sample text</p>

Opening tag · the element starts here

Content · the text shown on the page

Closing tag · the element ends here

Tag vs element A tag is just the label (<p>). The element is the whole thing: opening tag, content and closing tag together. A void element such as <br> is a single tag with no content.

Attributes: extra settings for a tag

The light bulbThink of a light bulb. The bulb itself is the element; the switch that controls its brightness or colour is like an attribute, an extra setting. The bulb is still a bulb, but now with a setting. An attribute gives a tag extra information about how to show it or how it should work.

Every attribute has two parts: a name (what kind of information) and a value (the actual setting). It is always written inside the opening tag:

syntax
<tagname attribute="value">Content</tagname>
<img src="flower.jpg" alt="Beautiful flower">

Tag · img, an image element (void, no closing tag)

Attribute name · src and alt

Attribute value · always in quotes

  • src="flower.jpg" tells the browser where the image file is.
  • alt="Beautiful flower" gives text to show if the image doesn’t load (and for screen readers).

Common HTML syntax rules

1 · Elements have opening and closing tags

Most elements are containers: an opening tag, content, then a closing tag. The closing tag always has a / before the name.

<p>This is a paragraph.</p>

2 · Attributes go in the opening tag, as name="value"

<a href="https://www.google.com">A link</a>

href is the attribute name

"https://www.google.com" is the value

3 · Nest correctly: close the inner tag first

Tags must open and close in order, like boxes packed inside boxes.

✅ correct
<h1><strong>Hello!</strong></h1>
❌ incorrect
<h1><strong>Hello!</h1></strong>

4 · Case doesn’t matter, but use lowercase

HTML is not case-sensitive: <P> and <p> mean the same thing. Professionals always write tags and attributes in lowercase because it is cleaner and easier to read.

5 · Comments are ignored by the browser

A comment is a note for yourself or other developers. It starts with <!-- and ends with -->, and never appears on the page.

<!-- This is a comment -->
<p>Hello, World!</p>

Remember later

Weeks later, comments remind you what each part of the code does.

Help others

Teammates and students follow your logic more easily.

Improves code organisation

Divide a long file into labelled sections.

comments as section markers
<!-- Header Section -->
<!-- Main Content Section -->
<!-- Footer Section -->

6 · Save the file with a .html extension

The extension is the label at the end of a file name. Saving as index.html tells your computer: “This isn’t a text file or a picture; it’s a web page. Open it with a web browser!”

The core structure: a blueprint for every page

Every website you visit (Google, YouTube, your favourite blog) is built on the same HTML skeleton. Don’t worry if it looks like a lot: it is easier than it looks.

The house blueprintAn architect’s blueprint shows where the foundation, walls, rooms and furniture go. HTML structure shows the browser where to place headings, text, images and links.

What does an HTML document look like?

Just as a house needs a proper plan to stand strong, a web page needs a proper HTML structure to work and look right. Let’s build one, then go through it part by part.

Your first “Welcome to HTML” document

<!DOCTYPE html>
<html lang="en">
  <head>
    <title>My Web Page</title>
  </head>
  <body>
    <h1>Welcome to HTML</h1>
    <p>This is a simple HTML structure.</p>
  </body>
</html>

Create index.html, paste this in, save, and open it in any browser. Done: your first HTML document.

Now let’s understand the code one part at a time: what each part does and why it’s important.

The DOCTYPE and the <html> root

The doctype declaration

<!DOCTYPE html> tells the browser which kind of HTML the page uses. In modern pages it means HTML5, and it makes the browser use its standards mode instead of an old “quirks” mode.

Purpose

Declares the HTML version, helps maintain cross-browser compatibility, and makes them display correctly.

Must be first

It has to be the very first line of every HTML document.

Not case-sensitive

<!doctype html> works just as well.

Not a tag Strictly, the doctype is a declaration, not an element. It has no closing tag and nothing appears on the page.

The <html> element

<html> is the root element: everything else, including <head> and <body>, lives inside it. It marks the start and end of the document and usually carries a lang attribute.

<html lang="en"> …head and body… </html>

lang · the language of the page’s content

"en" · English (Hindi would be "hi")

The head section: information about the page

<head> is the first room inside the house. It holds meta-information about the page: things the browser needs but that you don’t see on the page itself.

a typical head
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My Web Page</title>
</head>
Order tip Put <meta charset> first inside <head>. Browsers expect it near the top of the file, before any text (including the title) is read.

<meta>: data about data

The <meta> tag gives metadata, “data about data”: details that help the browser understand the page. It is a void tag.

<meta charset="UTF-8"> · character encoding

  • charset sets the character encoding: the system for turning stored bytes into characters.
  • UTF-8 (Unicode Transformation Format, 8-bit) is a variable-width encoding that can represent every character in Unicode, while staying backward compatible with ASCII. It is the dominant encoding on the web.

Why it matters: text displays correctly in any script (Hindi, English, Tamil) and special symbols like ₹, é or emoji don’t turn into garbage.

<meta name="viewport" …> · fitting the screen

This tag controls how a web page looks on different devices: mobile phones, tablets and computers.

<meta name="viewport" content="width=device-width, initial-scale=1.0">
  • Viewport is the user’s visible area of a web page. It can differ from the page’s full size.
  • width=device-width makes the viewport as wide as the device’s screen.
  • initial-scale=1.0 sets the zoom level on first load to 100% (no zoom).

<title>: the page’s name

The <title> tag names the page. Think of it as the label on the page.

<title>My Web Page</title>

Output: the title shows on the browser tab.

What it does

Shows the page name (1) on the browser tab, (2) as the bookmark name when saved as a favourite, and (3) as the headline in search results.

Why it matters

Users can identify your page among many tabs, and search engines like Google use it to understand what the page is about.

a) In the browser tab

The text inside <title> appears at the top of the browser window or tab. With <title>My Web Page</title>, the tab shows “My Web Page” (as in the screenshot above).

b) In bookmarks

When you bookmark a page, the title becomes the bookmark’s name. With <title>My Web Page</title>, the bookmark is called “My Web Page”.

The body section: everything you see

If the head is the storage room, <body> is the main living area, the second and most important room. It holds all the content you can actually see on the page. <body> says “the visible part starts here”; </body> says “it ends here.”

<h1> · the big-screen TV

Creates a big, important heading.
<h1>Welcome to HTML</h1>

<p> · the sofa

Creates a regular paragraph of text.
<p>This is a simple HTML structure.</p>

index.html · the complete document

<html lang="en">

    <title>My Web Page</title>
  </head>

In the field (FDE) When a customer says “the page looks broken” or “the special characters are garbled”, open DevTools and check the basics first: a missing doctype (quirks mode), a missing charset, or a missing viewport tag cause a surprising number of real bugs.

Block-level vs inline elements

Block-level

Always starts on a new line and takes the full width of its parent. Can contain block or inline elements.
<div>, <p>, <h1>–<h6>, <section>, <article>

Inline

Does not start a new line and takes only as much width as its content. Usually holds text or other inline elements.
<span>, <a>, <b>, <i>, <img>

Key terms

HTML
HyperText Markup Language: the standard language for creating and structuring web pages, telling the browser what each piece of content is.
HyperText
Text containing clickable links that connect one web page to another.
Tag
A label in angle brackets, such as <p> or </p>, that marks where a piece of content starts or ends.
Void element
An element with no closing tag and no content, such as <br>, <img> or <meta>. Also called an empty or singular tag.
Element
A complete building block of a page: the opening tag, the content and the closing tag together.
Attribute
Extra information written inside an opening tag as name="value", such as src="flower.jpg".
Nesting
Placing elements inside other elements. The inner element must be closed before the outer one.
HTML comment
A note written between <!-- and -->. The browser ignores it and it never appears on the page.
DOCTYPE
The declaration <!DOCTYPE html> on the first line, telling the browser the page is HTML5 so it renders in standards mode.
Root element
The <html> element, which wraps everything else in the document.
Metadata
“Data about data”: information about the page, such as its character set or title, kept in the <head> and not shown in the page body.
UTF-8
A variable-width character encoding that can represent every Unicode character and is backward compatible with ASCII. The standard encoding of the web.
Viewport
The visible area of a web page on the user’s screen. The viewport meta tag makes it match the device width.
Block-level element
An element that starts on a new line and takes the full available width, such as <p> or <div>.
Inline element
An element that stays within the line and takes only as much width as its content, such as <a> or <span>.

Which part of the name “HyperText Markup Language” refers to clickable links between pages?

  1. Markup
  2. Language
  3. HyperText
  4. None of them

HyperText is text with links that connect one document to another.

In <img src="cat.jpg" alt="A cat">, what is alt?

  1. A tag
  2. An attribute name
  3. An attribute value
  4. Content

alt is the attribute name; "A cat" is its value. Both sit inside the opening tag.

Which line is nested correctly?

  1. <p><b>Hi</p></b>
  2. <b><p>Hi</b></p>
  3. <p><b>Hi</p>
  4. <p><b>Hi</b></p>

The tag opened last (<b>) must be closed first, then the outer <p>.

Which of these is a void element with no closing tag?

  1. <br>
  2. <p>
  3. <h1>
  4. <title>

<br> just inserts a line break; it wraps no content, so it needs no closing tag.

You write a heading inside <head> instead of <body>. What is the core problem?

  1. Head is only for images
  2. Head must come after body
  3. Head holds information about the page, not the visible content
  4. Nothing; they are the same

<head> holds metadata like the title and charset. Visible content belongs in <body>.

Hindi text on your page shows up as strange symbols. Which tag most likely fixes it?

  1. <title>
  2. <meta charset="UTF-8">
  3. <html lang="hi"> alone
  4. The viewport meta tag

The charset tells the browser how to turn bytes into characters. UTF-8 covers every Unicode script.

Where does the text inside <title> appear?

  1. As a big heading on the page
  2. Only in the source code
  3. In the page footer
  4. On the browser tab, in bookmarks and in search results

The title is metadata. Browsers show it on the tab and as the bookmark name, and search engines use it as the result headline.

Two <a> links are written one after the other. How do they appear?

  1. Side by side on the same line
  2. Each on its own full-width line
  3. Stacked with a blank line between
  4. Only the first one appears

<a> is inline: it doesn’t start a new line and takes only the width it needs.

HTML labels content with tags; a tag plus its content makes an element, and attributes add settings, all following simple grammar rules, inside a fixed skeleton of DOCTYPE → html → head + body.
