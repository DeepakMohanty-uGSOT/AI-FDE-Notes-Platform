Modules & Packages

Break a big program into tidy files and folders, borrow code from Python’s library and from the internet, and keep test code from running when you only meant to import.

Why modules and packages are needed

Until now every program has lived in a single file. That’s fine for small programs, but think about what happens as a program grows. A complete student management system soon needs:

Student data

add, remove, update students

Marks

totals, averages, grades

Attendance

Fees

fee management

The kirana shop vs the supermarketIn a tiny kirana shop, everything sits in one heap behind the counter and only the owner can find anything. A supermarket puts rice in one aisle, soap in another, biscuits in a third. Modules are the aisles of your program: smaller, focused files, each with one clear job.

Each separate .py file is a module. A folder that groups several related modules is a package, which we’ll get to shortly.

Code organisation and reuse

Modules also make reuse possible across programs. A good module isn’t tied to one project: write it once, then bring it into any program without copy-pasting.

Avoiding duplicate code

Functions remove repetition within a file. Modules extend the same idea across files. Without modules, two programs that both need calculate_average() each carry their own copy:

program_one.py → contains its own copy of calculate_average()program_two.py → contains ANOTHER copy of calculate_average()

This brings back exactly the same problems we saw with repeated code earlier:

More code

The same function lives in two places.

Hard to maintain

Fix a bug in one copy, forget the other.

More mistakes

The two copies slowly drift apart.

With a module, there’s only one copy, living in one file, marks.py, and every program that needs it simply imports it. Fix a bug in that single file, and every program using it benefits immediately.

Separating related functionality

Group code by what it does. Everything about marks goes in one module, everything about attendance in another:

marks.py: only marks
def calculate_total(marks_list):
    return sum(marks_list)

def calculate_average(marks_list):
    return sum(marks_list) / len(marks_list)

def calculate_grade(average):
    return "A" if average >= 75 else "B"
attendance.py: only attendance
def mark_present(name):
    print(name, "is present")

def mark_absent(name):
    print(name, "is absent")

def attendance_percentage(present, total_days):
    return present / total_days * 100

Now each module has a clear purpose: marks.py holds only marks-related functionality, and attendance.py holds only attendance-related functionality.

What is a module?

A module is simply a Python file (.py) containing code, such as functions and variables, that other Python files can import and use. There’s nothing special to do to “make” one: any Python file is a module the moment another file imports it.

A .py filecontains functions, variables…another file imports itthat file is now a module
greetings.py: a normal Python file
def say_hello(name):
    print("Hello,", name)
main.py: importing makes it a module
import greetings
greetings.say_hello("Rahul")
Hello, Rahul
Think toolbox. Each module is a toolbox holding related tools (functions). Any program can borrow from it.

Module naming and file structure

A module’s name is its filename minus .py, so it follows the same rules as a variable name.

File nameWhy
marks.py✅import marks
student_utils.py✅import student_utils
my marks.py❌spaces are not allowed
2marks.py❌cannot start with a number
student-utils.py❌hyphens are not allowed
math.py⚠️avoid built-in module names
  • Use lowercase letters, with underscores if needed (student_utils).
  • Pick a name that describes what the module contains.
Don’t shadow the standard library. If you name your file random.py or math.py, Python may import yours instead of the real one, and you get baffling errors like “module 'random' has no attribute 'randint'”.

The import statement

Without import, a file can only use what is written inside it plus built-ins like print() and len(). Python ships with hundreds of ready-made modules, and you have your own too. import is how a file borrows code from another module.

print(sqrt(16))

Python doesn’t know sqrt: it lives in the math module, which we haven’t brought in.

Code lives in another moduleour file can’t see it automaticallyimport makes it available
import math

    Python locates the math module
  2. 2
    Runs it once and loads its contents→ a second import of the same module reuses it

Accessing members with dot notation

import math

print(math.sqrt(16))
print(math.pi)
print(math.factorial(5))

The module name in front tells Python where to look, which keeps things clear when two modules share a member name:

import math
import cmath

print(math.sqrt(16))      # from the math module
print(cmath.sqrt(-16))    # from the cmath module, a different function
4.0
4j

cmath works with complex numbers, so it can take the square root of a negative number (4j); math.sqrt(-16) would raise an error. Same name, different function. The same dot notation works with our own module:

import marks

print(marks.PASS_MARK)
print(marks.calculate_average([85, 72, 91]))

Importing multiple modules

one per line (recommended)
import math

several on one line, separated by commas
import math, random, marks

Both work the same, but one per line is easier to read and is what most Python code uses.

import math

print(math.sqrt(25))
print(random.randint(1, 10))

Aliases with as

When a module name is long, give it a short nickname, an alias:

syntax
import module_name as alias
without alias
import student_management_utils
print(student_management_utils.calculate_grade(85))
with alias
import student_management_utils as sm
print(sm.calculate_grade(85))

After aliasing, you must use the alias; the original name isn’t defined in your file:

import math as m

print(m.sqrt(16))       # works
print(math.sqrt(16))    # NameError
Aliases you’ll see everywhere import pandas as pd, import numpy as np. These are community conventions, so stick to them.

from ... import: bring in just what you need

With import math you write math. in front of everything. When you need only one or two members, pull them directly into your file:

syntax
from module_name import member_name
from math import sqrt

the module to look in

the specific member you want added to your file

For example, with import math you had to write math.sqrt(16) and math.pi. With from ... import:

from math import sqrt
print(sqrt(16))

Now you write sqrt(16), not math.sqrt(16): the name sqrt was brought straight into your file, so no prefix is needed. The same works for variables:

from math import pi
print(pi)

And for our own module from earlier:

from marks import calculate_average
scores = [85, 72, 91]
print(calculate_average(scores))

Only the named member is imported

from math import sqrt

print(sqrt(16))     # works
print(pi)           # NameError: name 'pi' is not defined
print(math.pi)      # NameError: name 'math' is not defined

Notice that the program stops at the first error, so the math.pi line never even runs; it would fail too, because math itself was not added to your file. Only sqrt is added; pi, factorial and the rest are not available.

Importing multiple members

To import several members from the same module, separate them with commas:

from math import sqrt, pi, factorial
print(sqrt(25))
print(pi)
print(factorial(5))

With our own module:

from marks import calculate_total, calculate_average, PASS_MARK
scores = [85, 72, 91, 68, 79]
print(calculate_total(scores))
print(calculate_average(scores))
print(PASS_MARK)

Aliases with from ... import ... as

syntax
from module_name import member_name as alias
from math import factorial as fact

print(fact(5))
# print(factorial(5))   -> NameError: only fact works now

Aliases also solve name clashes. Suppose marks.py and attendance.py both define calculate_average:

from marks import calculate_average as marks_average
from attendance import calculate_average as attendance_average

print(marks_average([85, 72, 91]))
print(attendance_average([90, 80, 100]))
82.66666666666667
90.0
Silent replacement Without aliases, the second from attendance import calculate_average would quietly overwrite the first, because both use the same name.

A caution about from module import *

Python also lets you import all public names from a module at once:

from math import *

print(sqrt(16))
print(pow(2, 3))
print(factorial(5))
4.0
8.0
120

Instead of the explicit version:

import math

print(math.sqrt(16))
print(math.pow(2, 3))
print(math.factorial(5))
Why * is risky: look at that 8.0. Python’s built-in pow(2, 3) returns the integer 8. But from math import * silently replaced it with math.pow, which always returns a float. That is exactly the danger: * dumps dozens of names into your file, can overwrite names you already have, and hides where each name came from. Prefer explicit imports.

Modules work well for a small project. But after a few months, the student project looks like this:

Everything is in one folder. It’s hard to see which files belong together, and what if you need two files with the same name? You need a way to group related modules: a package.

What is a package?

A package is a folder that contains related Python modules, along with a special file called __init__.py.

The labelled cupboardIf a module is a toolbox, a package is a labelled shelf in the cupboard that keeps related toolboxes together: all academic boxes on the “school” shelf, all money boxes on the “accounts” shelf.

Module vs package

The difference is very simple:

You have already used a package! Python’s own json is really a folder with several modules inside. Print both to see:

import math
import json

print(math)     # a single built-in module
print(json)     # a package - comes from json/__init__.py

math is a single built-in module. json comes from an __init__.py inside a json folder: that’s a package. (Your path will differ depending on where Python is installed.)

Importing from installed packages

Once installed, a package is imported exactly like any module, with everything from the last two sections.

Using import

import emoji

print(emoji.emojize("Great job :thumbs_up:"))
print(emoji.emojize("Python is fun :snake:"))

emoji.emojize() replaces codes like :thumbs_up: with real emojis. You didn’t write it; someone else did, and you simply installed and imported it.

Using from ... import

from emoji import emojize, demojize

print(emojize("Rahul scored 95 :party_popper:"))
print(demojize("I love Python 🐍"))

Using an alias

import emoji as em

message = "Rahul scored 95 🎉🎉"

print(em.emoji_count(message))
print(em.is_emoji("🎉"))

What if the package isn’t installed?

import emoji

The fix isn’t in your code. Run pip install emoji in the terminal first.

__name__ and "__main__"

The problem: code that runs when you only wanted to import

Suppose marks.py has a function plus two lines at the bottom to quickly test it:

marks.py
def calculate_average(marks_list):
    return sum(marks_list) / len(marks_list)

print("Testing marks module...")
print(calculate_average([80, 90, 100]))

Run python marks.py directly and the test lines are useful:

Now main.py imports it:

main.py
import marks

print(marks.calculate_average([85, 72, 91]))

You might expect only 82.66666666666667. But Python actually prints:

The first two lines came from marks.py. Why? When Python sees import marks, it loads marks.py and executes all its top-level code: the def (stores the function) and the two prints.

We want the function available when imported, but the test code to run only when the file is executed directly. That’s what __name__ is for.

What is __name__?

Every Python file automatically gets a special variable called __name__. Python sets its value depending on how the file is being used:

Run directly

python marks.py
→ __name__ = "__main__"

Imported

import marks
→ __name__ = "marks" (the module name)

See it for yourself:

show_name.py
print(__name__)
other.py
import show_name

The important difference, side by side:

What does "__main__" mean?

"__main__" is the special name Python gives to the file that starts the program. Run marks.py and it is the starting file, so its __name__ is "__main__". Run main.py (which imports marks) and main.py is the starting file, while marks.py is just an imported file with __name__ = "marks".

Using it with if

if __name__ == "__main__":
    print("This file is being run directly")

Fixing our original problem

marks.py (fixed)
def calculate_average(marks_list):
    return sum(marks_list) / len(marks_list)

if __name__ == "__main__":
    print("Testing marks module...")
    print(calculate_average([80, 90, 100]))

The file now has two parts: the function, usable by other files, and the guarded test code, which only runs directly.

Run python marks.py

  1. 1
    Python sets __name__ = "__main__"
  2. 2
    if "__main__" == "__main__": is True

Run python main.py (which imports marks)

  1. 1
    Inside marks.py, __name__ = "marks"
  2. 2
    if "marks" == "__main__": is False, so the tests are skipped
In the field (FDE) Nearly every runnable Python script you hand to a customer ends with if __name__ == "__main__": main(). It lets the same file work as a command-line tool and as an importable library for tests or other services.

Key terms

Module
A single Python file (.py) whose functions and variables other files can import and use.
import
The statement that loads a module and makes its contents reachable, e.g. import math, then math.sqrt(16).
Dot notation
Reaching a member inside a module or package with name.member, e.g. marks.PASS_MARK or school.marks.calculate_total().
from ... import
An import form that adds only the named members to your file, e.g. from math import sqrt, so you call sqrt() without a prefix.
Alias (as)
A nickname given to a module or member at import time, e.g. import math as m; afterwards only the alias works.
from module import *
Imports all public names of a module at once; discouraged because it hides where names come from and can overwrite existing names.
Package
A folder of related modules containing an __init__.py file, e.g. school/.
__init__.py
A (usually empty) file inside a folder that marks the folder as a Python package.
PyPI
The Python Package Index: the public online collection of packages that anyone can install.
pip
The Package Installer for Python, run in the terminal, e.g. pip install emoji, pip list, pip uninstall emoji.
ModuleNotFoundError
The error raised when you import a module or package Python can’t find, often because it isn’t installed yet.
__name__
A special variable in every file: "__main__" when the file is run directly, or the module’s name when it is imported.
if __name__ == "__main__":
A guard that runs its block only when the file is the program’s starting point, not when it is imported.

All of it, in one sentence

A module is one .py file and a package is a folder of modules with __init__.py; you bring their code in with import (use module.name) or from … import (use the name directly), rename with as, install outside packages with pip, and guard test code with if __name__ == "__main__".
