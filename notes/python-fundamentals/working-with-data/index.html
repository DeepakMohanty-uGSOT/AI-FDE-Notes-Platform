Working with Data

Save data to files so it survives after your program ends, then read it back as plain text, as JSON or as CSV tables.

Why store data outside the code?

You can already hold data in variables, lists, tuples and dictionaries:

student = {
    "name": "Rahul",
    "marks": 85
}

That works while the program runs. But one important question remains: what happens to the data when the program stops?

student_name = "Rahul"
marks = 85

print(student_name)
print(marks)

# Program stops -> student_name and marks are gone
# Next run      -> we must enter the data again
Rahul
85

While the program is running, the data is available. But when the program stops:

If you start the program again, you would need to enter the data again. That is not practical.

Real programs can’t work this way. A student system must remember every student between runs; a banking app can’t forget your balance the moment it closes. We need to store data outside the program, somewhere that survives after it ends.

The whiteboard and the registerA teacher works out sums on the classroom whiteboard: quick and handy, but wiped clean at the end of the day. Attendance goes into the register, which is still there next morning. Variables are the whiteboard (memory); files are the register (disk).
Data only in variablesexists only while the program runsstore it in a FILE insteadfiles live on disk and survive
with open("student.txt", "w") as file:
    file.write("Rahul, 85")

After this runs, a file student.txt containing Rahul, 85 sits in your folder, even after the program closes. (You’ll learn exactly how with open() works below.)

Real world: the bank balance A banking app saves the balance so it isn’t forgotten when the app closes. Files only store text, so the number is converted with str(): 
balance = 5000

with open("balance.txt", "w") as file:
    file.write(str(balance))

Persistent data vs temporary data

Data falls into two groups, based on how long it lives.

# Temporary data - lives in memory, lost when the program ends
cart = ["Shoes", "Watch"]

# Persistent data - saved on disk, available on the next run
with open("cart.txt", "w") as file:
    file.write("Shoes\nWatch\n")

Common data file formats

On disk, data isn’t stored as Python lists or dictionaries. It is stored as files in one of several common formats, each suited to a different kind of data.

Choosing the right format

Different formats suit different situations. Here’s the basic decision-making pattern:

.txt when…

the data is simple, free-form text with no rows, columns or nesting. A log file, a saved note, a message history.

.csv when…

the data is a table: the same fields repeated for every record, to open in Excel or Google Sheets. Student lists, sales records, attendance.

.json when…

the data is nested (lists in dicts, dicts in dicts) or shared with other programs, especially web apps. Settings, API data.

Opening and reading files

Before you can read or write a file you must open it with the built-in open().

syntax
open(filename, mode)
file = open("notes.txt", "r")

The second argument, the mode, says what you plan to do:

file = open("notes.txt", "r")    # read (file must already exist)
file = open("notes.txt", "w")    # write (creates a new file, or ERASES an existing one)
file = open("notes.txt", "a")    # append (adds to the end, without erasing)

Reading the complete file: .read()

.read() reads the entire file at once, as one string.

file = open("notes.txt", "r")
content = file.read()
print(content)
file.close()

Fine for small files. For very large files, loading everything into memory at once is wasteful, which is where line-by-line reading helps.

Reading line by line

Option 1: loop over the file. A file is iterable, so a for loop works on it just like on a list.

file = open("notes.txt", "r")
for line in file:
    print(line)
file.close()

Notice the extra blank lines. Each line already ends with a hidden \n (newline character), and print() adds its own newline on top. Strip it off:

file = open("notes.txt", "r")
for line in file:
    print(line.strip())
file.close()

Option 2: .readlines(). Reads the whole file but returns a list, one item per line (each line except the last still ends in \n):

file = open("notes.txt", "r")
lines = file.readlines()
print(lines)
file.close()

It’s a plain list, so everything from the Lists section applies:

file = open("notes.txt", "r")
lines = file.readlines()
print(lines[0])
print(len(lines))
file.close()

(The blank line is the \n still attached to lines[0].)

Option 3: .readline(). Reads just one line per call, moving forward each time:

file = open("notes.txt", "r")
print(file.readline())
print(file.readline())
print(file.readline())
file.close()
MethodGives you
file.read()the whole file as one string
file.readlines()the whole file as a list of lines
file.readline()one line per call
for line in file:loops through the file, one line per round (memory-friendly)

Closing a file

When you are done, close the file with file.close(). Why it matters:

  • An open file holds a connection reserved by the operating system; many open files waste resources.
  • When writing, Python may keep recent data in a temporary buffer instead of saving it immediately. .close() flushes it to disk.
  • Other programs (or other parts of yours) may not reliably access a file that is still open.
file = open("students.txt", "w")
file.write("Rahul\n")
file.close()     # flushes the data to disk and frees the file

A safer alternative: it’s easy to forget .close(), especially if an error happens first. The with statement closes the file automatically, even if something goes wrong:

with open("output.txt", "w") as file:
    file.write("Hello, this closes automatically!")

# file is already closed here - no need to call .close()

File modes

Every mode decides two things: what you’re allowed to do (read, write, or both), and what happens if the file already exists or doesn’t exist.

Here are the four basic modes:

Default mode: "r"

Leave out the mode and Python assumes "r". With students.txt holding Rahul, Priya, Amit:

file = open("students.txt")      # same as open("students.txt", "r")
content = file.read()
print(content)
file.close()

What if the file doesn’t exist?

This is very important. Suppose there is no marks.txt in your folder, and you run:

file = open("marks.txt", "r")

"r" can only open a file that already exists. "w" and "a" simply create a missing file:

file = open("marks.txt", "w")    # marks.txt didn't exist -> Python creates it
file.close()
"r"missing? ERROR"w"missing? creates"a"missing? creates

Exclusive creation: "x"

Want a new file but must never erase an existing one? "w" is risky because it silently replaces everything. Use "x":

file = open("new_students.txt", "x")
file.write("Karan\n")
file.close()

Since new_students.txt didn’t exist, Python creates it:

But what if you try "x" on a file that already exists?

file = open("students.txt", "x")

Python refuses and raises a FileExistsError, and your existing students are safe.

Real world: one file per student A registration program creates a file per roll number but must never overwrite an existing student’s file: 
roll_number = input("Enter roll number: ")

file = open(roll_number + ".txt", "x")
file.write("Registered\n")
file.close()
Enter 101 and 101.txt is created. Enter 101 again and you get FileExistsError instead of losing data.

Reading and writing together: the "+" modes

Till now, each mode allowed only one thing: either reading or writing. Adding a + to a mode allows both.

  • "r+": read and write (file must already exist, nothing is erased)
  • "w+": write and read (erases the file first)
  • "a+": append and read (new content always goes at the end)

Example with "r+" (students.txt holds Rahul, Priya, Amit):

with open("students.txt", "r+") as file:
    content = file.read()
    print(content)
    file.write("Sneha\n")     # read() moved the cursor to the end

And the file now contains:

Sneha went at the end because .read() moved Python’s position in the file, the cursor, all the way to the end, and .write() continued from there.

"a+" starts at the end

with open("students.txt", "a+") as file:
    content = file.read()
    print(content)     # prints an empty string

Only an empty line appears. The file isn’t empty; Python is already standing at the end, so there’s nothing left to read. (You could call file.seek(0) to jump back to the start.)

Using with open()

From here on, this is how you’ll open files almost every time.

Why with?

The manual way has two problems: you might forget file.close(), and if an error happens in the middle, the program stops before reaching it.

file = open("students.txt", "r")
content = file.read()
print(content + 5)     # TypeError happens here
file.close()           # this line never runs

Python stopped at line 3. file.close() was never reached, so the file was left open. with solves both problems.

syntax
with open(filename, mode) as file:
    # work with the file here

Example:

with open("students.txt", "r") as file:
    content = file.read()
  • with: tells Python to manage the file for you
  • open(filename, mode): opens the file, exactly as before
  • as file: gives the opened file a name to use inside the block
  • : and indentation: everything indented belongs to the with block, like the body of an if or a for loop

Automatic closing

The moment the indented block ends, Python closes the file automatically. Check with file.closed:

with open("students.txt", "r") as file:
    print(file.closed)      # inside the block

print(file.closed)          # after the block

Inside the block the file is open (False). As soon as you come out of the block it’s already closed (True), and you never wrote .close(). This happens even if an error occurs inside the block.

Reading with with

All the reading methods work the same inside with. Suppose students.txt holds Rahul, Priya, Amit, Sneha.

with open("students.txt", "r") as file:
    content = file.read()

print(content)     # content is still available after the file is closed

print(content) is outside the block. The file is closed, but content is an ordinary string now and stays available.

Reading line by line:

with open("students.txt", "r") as file:
    for line in file:
        print(line.strip())

Reading into a list:

with open("students.txt", "r") as file:
    lines = file.readlines()

print(lines)
print(len(lines))

Writing with with

with open("students.txt", "w") as file:
    file.write("Rahul\n")
    file.write("Priya\n")
    file.write("Amit\n")

The file becomes:

There’s no file.close() anywhere, yet the data is safely saved, because closing also flushes it to disk.

with works with every mode

Appending with "a":

with open("students.txt", "a") as file:
    file.write("Sneha\n")

Creating a backup safely with "x": copy the students, but never overwrite an old backup by mistake. Two with blocks, one after another:

with open("students.txt", "r") as file:
    content = file.read()

with open("backup.txt", "x") as backup:
    backup.write(content)     # FileExistsError if backup.txt already exists

Now backup.txt contains:

If backup.txt already existed, "x" would raise a FileExistsError instead of replacing it.

Reading and updating with "r+": count the students and write the total at the end.

with open("students.txt", "r+") as file:
    content = file.read()
    count = len(content.splitlines())
    file.write("Total: " + str(count) + "\n")

After .read() the cursor is at the end, so .write() adds the total after the last student.

Real world: daily sales total A shop reads today’s sales file (450, 1200, 300, one per line) and adds the total at the end. 
with open("sales.txt", "r+") as file:
    lines = file.read().splitlines()
    total = sum(int(line) for line in lines)
    file.write("Total: " + str(total) + "\n")
sales.txt ends with a new line Total: 1950. (Because the file already ends in \n, we don’t start the write with another \n, which would leave a blank line.)

JSON files

Why JSON?

Imagine saving this student:

student = {
    "name": "Rahul",
    "age": 21,
    "marks": [85, 90, 78]
}

In a .txt file it becomes just text: Rahul, 21, 85, 90, 78. Read it back and you get one string. Which number is the age? Where do the marks start? The structure (keys, list) is lost.

JSON (JavaScript Object Notation) saves dictionaries and lists as they are, so loading gives back the same structure.

Why this matters:

Structure kept

Dictionaries stay dictionaries, lists stay lists.

Human-friendly

Easy to read and edit by hand.

The web’s format

Standard for web applications and APIs.

Universal

Almost every programming language reads and writes it.

JSON structure

student.json
{
    "name": "Rahul",
    "age": 21,
    "marks": [85, 90, 78],
    "passed": true
}
  • Data is written as key: value pairs.
  • Keys must always be strings in double quotes.
  • Strings must use double quotes: 'Rahul' is not valid JSON, "Rahul" is.
  • Items are separated by commas, with no comma after the last item.

Objects and arrays

Object { }

key-value pairs, just like a Python dictionary.

Array [ ]

an ordered list of values, just like a Python list.

They nest, exactly like nested data structures. students.json is an array of objects, each holding an array of marks:

students.json
[
    {"name": "Rahul", "age": 21, "marks": [85, 90, 78]},
    {"name": "Priya", "age": 22, "marks": [90, 88, 95]}
]

JSON data types

JSON supports only a few data types. When Python reads JSON, each one turns into a Python type you already know:

Lowercase in JSON true, false and null are lowercase in JSON; in Python they are True, False, None. The json module converts them automatically.
import json

data = json.loads('{"passed": true, "failed": false, "grade": null}')
print(data)
{'passed': True, 'failed': False, 'grade': None}

The json module

Built in: nothing to install, just import json. Four main functions:

FunctionConverts
json.load(file)JSON file → Python object
json.dump(data, file)Python object → JSON file
json.loads(text)JSON string → Python object
json.dumps(data)Python object → JSON string

Reading JSON files: json.load()

Suppose students.json already exists in your folder:

import json

with open("students.json", "r") as file:
    students = json.load(file)

print(students)
print(type(students))

A real Python list of dictionaries, so all your list and dictionary skills apply:

print(students[0]["name"])
print(students[1]["marks"][2])

for student in students:
    print(student["name"], "→", sum(student["marks"]))

Writing JSON files: json.dump()

import json

student = {
    "name": "Sneha",
    "age": 20,
    "marks": [82, 91, 87],
    "passed": True
}

with open("student.json", "w") as file:
    json.dump(student, file)

student.json now contains:

True became true, and it’s all on one line: valid, but hard to read. Add indent:

with open("student.json", "w") as file:
    json.dump(student, file, indent=4)

indent=4 puts each item on its own line with 4 spaces of indentation.

Updating a JSON file: load → change → dump

You can’t “append” to JSON like a text file (that would break the brackets). Instead:

json.load()change it in Pythonjson.dump()
import json

with open("students.json", "r") as file:
    students = json.load(file)

students.append({"name": "Amit", "age": 20, "marks": [70, 75, 80]})

with open("students.json", "w") as file:
    json.dump(students, file, indent=4)

Converting to and from JSON strings

Sometimes you want JSON text, not a file, for example to send over the internet or print it.

import json

student = {"name": "Rahul", "age": 21, "passed": True, "grade": None}

text = json.dumps(student)
print(text)          # True becomes true, None becomes null
print(type(text))
import json

text = '{"name": "Priya", "age": 22, "passed": false}'

student = json.loads(text)
print(student)       # false becomes False
print(type(student))
print(student["name"])

Look carefully at the outputs: True became true and None became null when converting to JSON, and false became False when coming back to Python.

CSV files (basics)

CSV means Comma-Separated Values: a plain text file where each line is a record and commas separate the values.

  • It stores table-like data: the same fields for every record.
  • It opens directly in Excel or Google Sheets.
  • It’s small and simple: just plain text.
  • Many apps export CSV: attendance sheets, sales reports, bank statements.
bank_statement.csv
date,description,amount
01-07,UPI Payment,-250
02-07,Salary,45000
03-07,ATM Withdrawal,-2000

Rows and columns

Suppose students.csv contains:

students.csv
name,age,marks
Rahul,21,85
Priya,22,90
Amit,20,78
  • Each line is a row: one record (one student).
  • Commas split each row into columns: name, age, marks.
  • The first row is usually the header: it names the columns; it isn’t a student.

The csv module

You could split each line with .split(","), but what if a value contains a comma, like “Bengaluru, Karnataka”?

line = 'Rahul,"Bengaluru, Karnataka",85'
print(line.split(","))     # WRONG - the city is split into two
['Rahul', '"Bengaluru', ' Karnataka"', '85']

The built-in csv module handles quoting correctly (it reads that line as ['Rahul', 'Bengaluru, Karnataka', '85']).

CSV is plain text, so you get "85", not 85. Convert with int() before doing maths:

Basic handling of headers

In the first reader example, ['name', 'age', 'marks'] printed as if it were a student. Try converting marks on every row and the header breaks the program:

import csv

with open("students.csv", "r") as file:
    reader = csv.reader(file)
    for row in reader:
        print(row[0], int(row[2]))

The first row’s “marks” is a word, which can’t become a number. next(reader) reads just one row (the header) and moves forward, so the loop starts at real data:

import csv

with open("students.csv", "r") as file:
    reader = csv.reader(file)
    header = next(reader)
    print("Columns:", header)

    for row in reader:
        print(row[0], "scored", int(row[2]))

Putting it together: average marks

import csv

total = 0
count = 0

with open("students.csv", "r") as file:
    reader = csv.reader(file)
    next(reader)            # skip the header

    for row in reader:
        total = total + int(row[2])
        count = count + 1

print("Average marks:", round(total / count, 2))

When writing, the header is simply the first row you write, like writer.writerow(["name", "age", "marks"]) above. When appending with "a", you don’t write the header again, because it’s already there.

Key terms

Persistent data
Data saved on disk (files, databases) that survives after the program ends.
Temporary data
Data held in memory (variables, lists, dicts) that disappears when the program stops.
open()
The built-in function that opens a file and returns a file object: open(filename, mode).
File mode
The second argument to open() that sets what you can do: "r" read, "w" write (erases), "a" append, "x" create new only, plus "+" variants.
read() / readline() / readlines()
Read the whole file as one string, one line per call, or all lines as a list.
write()
Writes a string to an open file; it doesn’t add a newline, so you add \n yourself.
close()
Closes a file, flushing buffered data to disk and releasing the file.
with open()
A statement that opens a file for the indented block and closes it automatically when the block ends, even after an error.
File cursor
The current position in a file where the next read or write happens; read() moves it to the end.
JSON
JavaScript Object Notation: a text format of objects {} and arrays [] that keeps nested structure; the standard for web APIs.
json.load / json.dump
Read a JSON file into Python objects, or write Python objects to a JSON file.
json.loads / json.dumps
Convert a JSON string into Python objects, or Python objects into a JSON string.
CSV
Comma-Separated Values: a plain-text table where each line is a row and commas separate columns.
csv.reader / csv.writer

students.txt holds three names. You run open("students.txt", "w") and write “Sneha”. What is in the file?

  1. The three names plus Sneha
  2. Sneha plus the three names
  3. Only Sneha
  4. An error, the file exists

"w" erases the file when it opens it. Use "a" to add instead.

Which mode protects an existing file from being overwritten by raising an error?

  1. "x"
  2. "w"
  3. "a"
  4. "r+"

"x" creates a new file only and raises FileExistsError if it already exists.

Why does for line in file: print(line) show blank lines between lines?

  1. The file has blank lines
  2. The loop runs twice
  3. print() is called with end=""
  4. Each line already ends with \n and print adds another

Use line.strip() to remove the trailing newline.

When the block ends, for any reason, Python closes the file for you.

You want a JSON string from a Python dict to send to an API. Which function?

  1. json.dump()
  2. json.load()
  3. json.dumps()
  4. json.loads()

The “s” means string; “dump” goes Python → JSON.

What does Python’s None become in JSON?

  1. null
  2. "None"
  3. none
  4. 0

JSON uses lowercase null; likewise True → true.

csv.reader gives the row ['Rahul', '21', '85']. What is row[2] + 5?

  1. 90
  2. '855'
  3. '85 5'
  4. A TypeError

Every CSV value is a string, and you can’t add a string and an int. Use int(row[2]) + 5.

Why open a CSV with newline="" when writing?

  1. To skip the header
  2. To avoid extra blank lines between rows on Windows
  3. To make values numbers
  4. To allow commas inside values

The csv writer adds its own line endings; newline="" stops Python adding a second one.

How do you add a new student to students.json (a list of objects)?

  1. Open in "a" and write the new object
  2. Open in "x" and dump the new object
  3. Load the list, append in Python, dump the whole list back
  4. Use csv.writer

Appending raw text would break the JSON brackets; use load → change → dump.

All of it, in one sentence

Variables are temporary and files are persistent: open them with open(name, mode) (preferably inside with), choose the mode carefully ("r" read, "w" erase-and-write, "a" append, "x" create-only), use plain .txt for free text, the json module for nested data and the csv module for tables.
