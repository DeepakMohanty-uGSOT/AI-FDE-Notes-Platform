Python Basics — Part 1

From “what is a program?” to writing your first small Python programs that store values, convert them, ask the user for input and print a result.

What is Python?

Ordering at a dhabaYou don’t walk into the kitchen and operate the stove yourself. You tell the waiter “one paneer tikka, less spicy”, and he turns that into actions in the kitchen. A programming language is how you give a computer instructions in words you can read, and Python’s interpreter is the waiter that carries them out.

A programming language lets you write instructions for a computer in a form that is far easier to read and write than raw binary. Python uses an interpreter: a program that reads your code and runs it, statement by statement.

Python was created by Guido van Rossum and first released in 1991. It is named after the comedy show Monty Python’s Flying Circus, not the snake. The version used today, and in this course, is Python 3.

What kind of language Python is

High-level

Code reads close to plain English, not low-level machine instructions.

General-purpose

The same language can build a website, analyze data, automate a task, or build an AI model.

Interpreted

The interpreter runs your statements directly, so you can test code quickly.

Dynamically typed

You never declare a variable’s type. Python works it out from the value.

Key features and where it is used

  • Simple, readable syntax
  • Free and open source
  • Cross-platform: the same program runs on Windows, macOS and Linux
  • A large standard library plus a huge ecosystem of third-party packages
  • Supports procedural, object-oriented and functional styles
  • Automation and scripting
  • Data science and analytics
  • AI and machine learning
  • Web development (backend)
  • DevOps and software testing

How Python code becomes something that runs

You write instructions in a .py source file. On its own that file does nothing; the Python interpreter reads it and executes it.

A small precision “Interpreted” doesn’t mean Python looks at one line, runs it, then reads the next. The standard interpreter (CPython) first compiles the whole file to bytecode, then runs that bytecode statement by statement. That is why a syntax error anywhere in the file stops it before even the first line runs.

Your first Python program

print("Hello, World!")

A statement is one instruction. The line above is one statement. Python runs statements one after another, from top to bottom.

Understanding print()

print is a built-in function. You call a function by writing its name followed by parentheses; whatever you put inside is the argument passed to it.

print("Hello, World!")

print: the function being called

( ): marks this as a function call

"Hello, World!": the argument, a string, that print() displays on the screen (the console)

Running a Python program

Save your code in a .py file and run it from the terminal:

python app.py

Most editors also have a “Run” button that does the same thing.

Syntax: the rules Python follows

Syntax is the set of rules Python code must follow, just as English has grammar. A statement that follows the rules is valid; one that breaks a rule is invalid, and Python refuses to run it with a SyntaxError.

✅ valid
print("Deployment successful")

Here is an invalid one, missing its closing quotation mark and its closing parenthesis:

❌ invalid: no closing quote or parenthesis
print("Deployment successful
SyntaxError: unterminated string literal (detected at line 1)

Close the quote but still forget the parenthesis, and Python stops with a different message, pointing at the bracket it never saw closed:

❌ invalid: no closing parenthesis
print("Deployment successful"

Statements run in order

A program can contain one statement or thousands. Python runs them in the exact order they appear, top to bottom, unless something like a condition or a loop (coming soon) changes that order.

print("Connecting to server...")
print("Connection established")
print("Server ready to accept requests")

Python is case-sensitive

Uppercase and lowercase letters are different characters to Python, so two names that differ only in capitalisation are two separate names pointing at two different values.

name = "Deepak"
Name = "Python"

print(name)
print(Name)
Classic beginner slip Print("hi") fails with NameError: name 'Print' is not defined. The function is print, all lowercase.

Indentation: how Python groups code into blocks

Sub-points in a to-do listWhen you write “Go to market” and then indent “buy tomatoes” and “buy onions” under it, everyone understands those two belong to the market trip. Python reads indentation the same way: indented lines belong to the line above them.

Indentation is the blank space at the start of a line. In many languages it is only for neatness. In Python it is part of the syntax: it decides which lines belong together as a block.

Whenever a group of statements should run together under some condition, that group is indented one level deeper than the line that introduces it:

attendance_days = 22

if attendance_days >= 20:
    print("Eligible for bonus")
Eligible for bonus

The indented print belongs to the if above it, so it runs only when the condition is true. (You will study if properly in the Control Flow note; for now, focus on how indentation marks the block.)

Without correct indentation

If Python expects an indented block and doesn’t find one, it raises an error before the program even starts:

if attendance_days >= 20:
print("Eligible for bonus")

Rules to follow

  • Use 4 spaces per level. This is the accepted standard in the Python community.
  • Don’t mix tabs and spaces in the same block. They can look identical on screen but Python does not treat them as equal.
  • Every line in the same block must have exactly the same indentation; inconsistent indentation is also an IndentationError.

if statements, loops and functions all use indentation in the same way to define their blocks.

Let the editor do it Set VS Code or PyCharm to “insert spaces” with a tab size of 4. Then the Tab key always produces 4 spaces and you never mix the two.

Comments: notes inside your code

A comment is text in your source code written for humans and completely ignored by the interpreter. Use comments to explain what a piece of code does, leave a reminder for yourself or a teammate, or temporarily disable a line while testing without deleting it.

Single-line (standalone) comments

Start with #. Everything from the # to the end of the line is ignored.

# Calculate the employee's net salary after deductions
net_salary = 45000 - 3200
print(net_salary)

Inline comments

A comment at the end of a line that already has code:

retry_limit = 3  # maximum number of retry attempts allowed

Multi-line (block) comments

Python has no special multi-line comment symbol. Write several single-line comments, each starting with its own #:

# This section calculates the final payable amount
# after applying tax and any applicable discount
# before displaying it to the customer
total_payable = 1000

Docstring-style notes

A triple-quoted string written on its own (not assigned to anything) is evaluated and then thrown away, so it can hold a longer note across several lines:

"""
This program calculates an employee's net salary
by subtracting deductions from the basic salary.
"""
net_salary = 45000 - 3200
Strictly speaking a triple-quoted string is not a comment, it is a string that nobody uses. When it is the first statement of a file, function or class it becomes that object’s docstring, which help() can show. You will use these properly in the Functions note.

Writing useful comments

A good comment explains why, especially when the reason isn’t obvious from the code. A comment that only repeats the code adds nothing.

❌ just repeats the code
quantity = 5  # bad comment: just repeats the code
✅ explains the reason
quantity = 5  # good comment: default order quantity when the customer does not specify one

Identifiers: naming things

Look at a number sitting alone in code:

95

Is it an age? A score? A quantity? There is no way to tell. Attach a name and it means something:

marks = 95

An identifier is the technical word for any name you create to refer to something: a variable, a function, a class. Every identifier must follow Python’s naming rules.

Rules for identifiers

  • May contain letters (a–z, A–Z), digits (0–9) and the underscore _.
  • Must start with a letter or underscore, never a digit.
  • No spaces, and no symbols such as @, $ or -.
  • Cannot be a reserved keyword.
  • Case-sensitive: age, Age and AGE are three different names.
  • No fixed maximum length, but clear, concise names are easier to read.

These are valid: Python recognises them as names that can identify variables, functions, classes and other objects.

✅ valid
student_name = "Rahul"
age2 = 20
_total = 100

print(student_name, age2, _total)

These are invalid. Python raises a SyntaxError for both, because it cannot recognise them as names:

❌ invalid: starts with a digit
2age = 20

print(2age)
❌ invalid: contains a space
student name = "Rahul"

Variables: giving names to data

Luggage tags at the stationA tag that says “Sharma, Coach B2” isn’t the suitcase; it’s tied to the suitcase so you can find it. A Python variable is a name tag tied to a value in memory. Re-tie the tag to another bag and the name now finds that bag instead.

A variable is a name that refers to a value stored in memory. Once created, you use the name anywhere to read, use or change the value, instead of repeating the value everywhere. Variables let a program store information, calculate with it and reuse the results.

Creating a variable

Write the name, the assignment operator =, then the value. No type declaration is needed: the variable comes into existence the moment a value is assigned.

employee_name = "Deepak"
employee_age = 30

Understanding assignment

It helps to break the statement employee_age = 30 into its three parts:

employee_age = 30

the variable name

the assignment operator: put the value on the right into the name on the left

the value being stored

= is not “equals” In maths, = states that two things are equal. In Python it is an action: “assign the right-hand value to the left-hand name”. Checking equality uses ==, which you’ll see in Part 2.

Reading a variable

employee_age = 30
print(employee_age)

Changing (updating) a variable

Assigning a new value to the same name does not create a second variable. The same name now refers to the new value.

stock_count = 20
print(stock_count)

stock_count = 15
print(stock_count)

Several variables in one line

List the names and the values, separated by commas. Each name gets the value in the same position.

employee_name, employee_age, department = "Rahul", 21, "Bengaluru"

print(employee_name)
print(employee_age)
print(department)

The same value for several variables

Chain the assignment instead of repeating it:

retries_allowed = max_retries = default_retries = 3

print(retries_allowed, max_retries, default_retries)

Variables refer to objects

In Python every value is an object in memory, and a variable is a label attached to that object, not a box that holds it. Writing employee_age = 31 after employee_age = 30 doesn’t change the object 30; Python points the name at a different object, 31. Naming conventions: writing meaningful code

Naming conventions are the rules and common practices for giving consistent, meaningful names to variables, functions, classes and other identifiers. Good names make code easier to read, understand and maintain.

❌ unclear: what is 50000?
x = 50000
y = 450
✅ meaningful
monthly_salary = 50000
total_marks = 450

monthly_salary immediately tells you what 50000 is. Choose names that describe what the value represents, for you and for every developer after you.

Use snake_case

Python variables and functions are written in snake_case: all lowercase, words joined by underscores, no spaces.

student_name = "Rahul"
total_marks = 450
monthly_salary = 50000

Data and data types

10
"10"

These look alike, but Python treats them completely differently: the first is a number you can calculate with, the second is text. Every value has a data type, and the type decides which operations are allowed on it. Using an unsupported operation raises an error (for example "10" + 5 is a TypeError).

int · integer

A whole number: positive, negative or zero.
employee_age = 30

float · decimal

A number with a decimal point, for prices and measurements.
unit_price = 99.50

str · string

A sequence of characters: text.
employee_name = "Deepak"

bool · boolean

Only True or False: the two outcomes of a decision (more in Part 2).
is_logged_in = True

NoneType

The special value None: a deliberate “no value yet” (more in Part 2).
last_login_time = None

The built-in type() tells you exactly what type a value or variable is, handy whenever you’re unsure what you are dealing with.

Type conversion: changing one type into another

Sometimes a value is stored as one type but you need it as another. The most common case: anything a user types arrives as text, even if it looks like a number.

age = "20"

The quotes make this a string, and you can’t do arithmetic on text. Type conversion (also called type casting) turns a value of one type into another so it can be used correctly.

FunctionConverts a value to…
int(value)an integer (whole number), when possible
float(value)a floating-point (decimal) number
str(value)text (a string)
bool(value)True or False

int(value)

Converts a value into an integer (whole number), when possible.

age = int("20")
print(age, type(age))

float(value)

Converts a value into a floating-point (decimal) number.

price = float("99.5")
print(price)

str(value)

Converts a value into text (a string).

age_text = str(20)
print(age_text, type(age_text))

bool(value)

Converts a value into either True or False.

print(bool(1), bool(0))

Notice that 20 and "20" print the same; only type() reveals the difference.

How bool() decides 0, 0.0, the empty string "" and None become False; almost everything else becomes True. So bool("False") is True, because it is a non-empty string!

When conversion fails

Not every value can become every type. If the text isn’t a valid number, Python raises a ValueError:

int("hello")

Python raises a ValueError because "hello" doesn’t represent any valid whole number, so there is no sensible way to convert it.

Explicit vs implicit conversion

Explicit

You call int(), float() or str() yourself, as above.

Implicit (type coercion)

Python converts automatically: adding an int and a float gives a float.

result = 5 + 2.5
print(result, type(result))

Input and output: making programs interactive

So far every program has printed fixed text. Real programs talk to the person using them: they accept information and respond.

Output with print()

print() can show several values at once, separated by commas. By default it puts one space between them.

employee_name = "Rahul"
employee_age = 21

print(employee_name, employee_age)

The sep parameter

sep controls what is placed between multiple values, replacing the default single space.

print("2026", "09", "21", sep="-")

The end parameter

By default print() moves to a new line after its output. end replaces that newline with something else, such as a space, so the next print() continues on the same line.

print("Processing", end=" ")
print("request")

Taking input with input()

input() pauses the program, waits for the user to type something and press Enter, and returns what they typed. The optional text in the brackets is shown as a prompt.

employee_name = input("Enter employee name: ")
print("Welcome,", employee_name)

input() always returns a string

This is one of the most important rules to remember: whatever the user types, even digits, input() gives you a str.

age = input("Enter your age: ")
print(type(age))

The user typed 22, but Python stored the string "22", not the integer 22. Type 20 and you get the string "20"; the rule never changes.

Converting user input

So convert it with int() or float() before calculating:

age = int(input("Enter your age: "))
years_until_retirement = 60 - age
print(years_until_retirement)
Forget to convert and it breaks Without int(), 60 - age raises TypeError: unsupported operand type(s) for -: 'int' and 'str'. And if the user types twenty, even int() raises a ValueError. You will learn to handle that gracefully in the Error Handling note.

Python runs your statements top to bottom, uses indentation to group them, stores values under variable names that point to typed objects (int, float, str, bool, None), and talks to users through print() and input(), which always hands you a string to convert.
