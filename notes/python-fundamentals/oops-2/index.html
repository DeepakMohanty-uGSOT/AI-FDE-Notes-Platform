Introduction to OOP — Part 2

Give every object its data automatically with a constructor, learn what decorators do, and know exactly which kind of variable and method to reach for.

Putting data into a new object

An object is useful only when it has its own data. So the first question is: how do we put the starting data into an object?

Idea 1: a normal method that sets the data

class Student:
    def set_details(self, name, roll_no):
        self.name = name
        self.roll_no = roll_no

    def show_details(self):
        print("Name:", self.name)
        print("Roll No:", self.roll_no)

s1 = Student()
s1.set_details("Sunny", 101)    # called explicitly
s1.show_details()
Name: Sunny
Roll No: 101

Student() creates the object, but at that moment it has no data. Only after you explicitly call set_details() is it ready. This works, but it depends on the programmer remembering that call for every object.

The problem: what if you forget?

s2 = Student()
s2.show_details()    # set_details() was never called
Traceback (most recent call last):
  ...
AttributeError: 'Student' object has no attribute 'name'

s2 exists but has no name and no roll number, so reading self.name fails with an AttributeError.

s1 = Student()s1.set_details(…)ready
s2 = Student()set_details forgottenAttributeError

Two problems: making a ready object always takes two steps (create, then initialise), and forgetting the second step even once makes the program fail at runtime. Initialisation should not depend on memory; it should happen automatically, the moment the object is created.

Python’s answer is a special method, __init__(), called the constructor. This note covers it, then decorators, the parts of an object, the three types of variables and the three types of methods.

The constructor: __init__()

The new SIM cardWhen you buy a new phone connection, the shop activates the SIM, registers your name and number and loads the starter plan before handing it over. You don’t go home and do it later. The constructor is that setup counter: it prepares every object the moment it is created.

A constructor is a special method that runs automatically when an object is created and sets its starting data (its instance variables). In Python it is always named __init__(), short for initialisation.

It runs automatically

class Student:
    def __init__(self):
        print("Constructor is executed")

s1 = Student()
Constructor is executed

Nobody called __init__(); Python ran it while creating s1.

It runs only once per object

class Student:
    def __init__(self):
        print("Constructor executed")

    def show(self):
        print("Normal method executed")

s1 = Student()
s1.show()
s1.show()
Constructor executed
Normal method executed
Normal method executed

The constructor ran once, at creation. The normal method runs every time you call it.

Its main purpose: create and fill instance variables

class Student:
    def __init__(self, name, roll_no, marks):
        self.name = name
        self.roll_no = roll_no
        self.marks = marks

    def display(self):
        print("Name:", self.name)
        print("Roll Number:", self.roll_no)
        print("Marks:", self.marks)

s1 = Student("Sunny", 101, 90)
s1.display()
Name: Sunny
Roll Number: 101
Marks: 90

The constructor receives values at creation time, stores them with self, and later methods such as display() use the same data. Real-world version: opening a bank account must record the holder, account number and opening balance immediately.

class BankAccount:
    def __init__(self, holder_name, account_no, balance):
        self.holder_name = holder_name
        self.account_no = account_no
        self.balance = balance

    def display(self):
        print("Holder:", self.holder_name)
        print("Account No:", self.account_no)
        print("Balance:", self.balance)

acc1 = BankAccount("Priya", "ACC1001", 5000)
acc1.display()
Holder: Priya
Account No: ACC1001
Balance: 5000
In the field (FDE) Clients for databases, LLM APIs and queues are classes whose constructor takes the URL, API key and timeouts. Because __init__ runs once, a missing key fails at startup instead of at 2 a.m. on the first customer request.

Constructor rules in Python

It needs at least one parameter: self

Python always passes the new object in, so the constructor must accept at least self. It can set fixed values with no other parameters:

class Student:
    def __init__(self):
        self.name = "Durga"
        self.roll_no = 101

    def show(self):
        print(self.name, self.roll_no)

s1 = Student()
s1.show()
Durga 101

Leave self out (def __init__():) and creating an object fails with TypeError: A.__init__() takes 0 positional arguments but 1 was given.

It is optional

You don’t have to write a constructor. If a class has none, Python uses a default one (inherited from Python’s built-in object class) that takes no arguments and does nothing.

class Student:
    def show(self):
        print("No constructor defined")

s1 = Student()
s1.show()
No constructor defined

It can be called explicitly, but that creates no new object

class Student:
    def __init__(self):
        print("Constructor executed")

s1 = Student()
s1.__init__()
Constructor executed
Constructor executed

The first line comes from object creation, the second from the manual call. Still only one object exists; the manual call just re-runs the setup code on it.

Constructor overloading is not supported

If you write two __init__ methods, the second definition simply replaces the first. Only the last one counts.

class Student:
    def __init__(self):
        print("First constructor")

    def __init__(self, name):
        print("Second constructor:", name)

s1 = Student("Sunny")
Second constructor: Sunny
Gotcha Now Student() with no name fails: TypeError: Student.__init__() missing 1 required positional argument: 'name'. The first constructor is gone. To support “with or without a name”, use one constructor with a default: def __init__(self, name="Unknown"):.

Constructor vs normal method

ConstructorNormal method
NameAlways __init__Any name you choose
When it runsAutomatically, when the object is createdOnly when you call it
How oftenOnce per objectAny number of times
PurposeDeclare and initialise instance variablesBusiness logic: actions the object performs

Points to remember

  • Its name is always __init__(), and it runs automatically, once per object.
  • Its main job is initialising instance variables.
  • It is optional; explicit calls don’t create new objects; overloading isn’t supported.

Decorators

Gift wrappingThe shop wraps your gift in paper and a ribbon. The gift inside is unchanged, but how it is presented is different. A decorator wraps a function to change how it behaves or is treated, without touching the code inside.

A decorator modifies the behaviour of a function or method without changing its internal code. It is written with the @ symbol, on the line immediately above the definition:

syntax
@decorator_name
def function_name():
    pass

Why we need them

By default every method in a class is an instance method that works with one object’s data. Real programs also need:

Class-level methods

Methods that work with data shared by the whole class.

Independent methods

Helpers that need neither object nor class data.

Extra behaviour

Logging, validation or access control added to many functions.

A decorator doesn’t rewrite the function’s code; it changes how Python calls and treats it.

Writing your own decorator

A decorator is just a function that takes a function and returns a modified function. You write one to add common behaviour to many functions, avoid repetition, and apply rules like validation, logging or authorisation automatically. Its structure is always:

  1. 1
    An outer functionthat receives the function to be decorated (func).
  2. 2
    An inner function(the wrapper) that adds the extra behaviour and calls func().
  3. 3
    A returnthat hands back the inner function.
def simple_decorator(func):
    def wrapper():
        print("Before function execution")
        func()
        print("After function execution")
    return wrapper

@simple_decorator
def greet():
    print("Hello, welcome!")

greet()
Before function execution
Hello, welcome!
After function execution

simple_decorator receives greet, wrapper adds behaviour before and after, and the original logic stays unchanged. Real-world version: a shopping app logs every important action without repeating the logging code.

def log_action(func):
    def wrapper():
        print("Action started")
        func()
        print("Action finished")
    return wrapper

@log_action
def place_order():
    print("Order placed successfully")

@log_action
def cancel_order():
    print("Order cancelled")

place_order()
cancel_order()
Action started
Order placed successfully
Action finished
Action started
Order cancelled
Action finished
In the field (FDE) You will use decorators constantly: FastAPI routes are @app.get("/items"), retries on flaky LLM calls are often a @retry decorator, and timing or auth checks wrap many endpoints at once.

Decorators in OOP: @classmethod and @staticmethod

In OOP, decorators mainly decide the type of a method. Python has two built-in ones for this.

@classmethod

Declares a class method: it works with class-level data, belongs to the class rather than one object, and receives the class reference (cls) automatically.

class Student:
    school_name = "Durga Soft"

    @classmethod
    def show_school(cls):
        print("School Name:", cls.school_name)

Student.show_school()
School Name: Durga Soft

No object was needed to call it.

@staticmethod

Declares a static method: it uses neither object data nor class data and performs a general-purpose task. Python passes it no automatic reference.

class MathUtility:
    @staticmethod
    def add(a, b):
        print("Sum:", a + b)

MathUtility.add(10, 20)
Sum: 30
Decorators in one breath They change behaviour without changing logic, use @, sit directly above the definition, help you avoid repeated code, and @classmethod / @staticmethod are essential in OOP.

The two parts of every object

Every real-world thing we model in Python has properties and behaviour.

Properties (data) → variables

What the object has. A student: name, roll number, marks. A mobile phone: brand, colour, price.

Behaviour (actions) → methods

What the object does. A student: talks, reads, writes. A phone: calls, sends texts, plays music.

Instance variables (object level)

Instance variables store data unique to each object, like a student’s name and roll number. Each object keeps its own independent copy, so changing one object never affects another.

  • How to spot them: usually created inside __init__ with the pattern self.variable_name.
  • Memory: allocated when the object is created; every object gets its own copy.
class Student:
    def __init__(self, name, roll_no):
        # These are Instance Variables
        self.name = name
        self.roll_no = roll_no

# Creating two different objects
s1 = Student("Kumar Deepak", 101)  # s1's object stores its own name and roll_no
s2 = Student("Ravi", 102)          # s2's object stores its own name and roll_no

print(f"Student 1: {s1.name}")
print(f"Student 2: {s2.name}")
Student 1: Kumar Deepak
Student 2: Ravi
Precise wording s1 and s2 are reference variables. The instance variables live inside the actual objects, Student("Kumar Deepak", 101) and Student("Ravi", 102). Same variable names, separate copies.

Real-world version: each food-delivery customer has their own name and address.

class Customer:
    def __init__(self, name, address):
        self.name = name
        self.address = address

c1 = Customer("Arjun", "MG Road, Bengaluru")
c2 = Customer("Meera", "Park Street, Kolkata")

print(f"{c1.name} lives at {c1.address}")
print(f"{c2.name} lives at {c2.address}")
Arjun lives at MG Road, Bengaluru
Meera lives at Park Street, Kolkata

Static variables (class level)

The college notice boardEvery student has their own ID card (instance data), but there is one notice board in the corridor that everyone reads. Change the notice and every student sees the new one. A static variable is the notice board: one copy, owned by the class, shared by all objects.

Static variables store data common to all objects. All students of one college share the same college name, while their names and roll numbers differ. They exist to store common data, avoid duplicating the same value in every object, and keep it consistent.

  • One copy in memory, owned by the class; all objects see the same value.
  • How to spot them: defined inside the class but outside all methods; usually accessed with the class name, e.g. Student.school_name.
  • Memory: allocated once, when the class is defined, not each time an object is created.
class Student:
    # Static Variable
    school_name = "XYZ College"

    def __init__(self, name):
        self.name = name

# Creating objects
s1 = Student("Kumar Deepak")
s2 = Student("Ravi")

print(Student.school_name)
XYZ College

Real-world version: all employees share the company name, but each has their own name.

class Employee:
    # Static Variable
    company_name = "TechNova Pvt Ltd"

    def __init__(self, name):
        self.name = name

e1 = Employee("Rahul")
e2 = Employee("Sneha")

print(e1.name, "works at", Employee.company_name)
print(e2.name, "works at", Employee.company_name)
Rahul works at TechNova Pvt Ltd
Sneha works at TechNova Pvt Ltd
Change it through the class, not an object Student.school_name = "New College" changes it for everyone. But s1.school_name = "ABC" does not touch the shared value: it creates a new instance variable on s1 only, hiding the class one. After that, s1.school_name is ABC while s2.school_name and Student.school_name are still XYZ College.

Local variables (method level)

Local variables are created inside a method and used only within that method, for temporary work like calculations or intermediate steps. They keep methods clean and avoid storing short-term data on the object.

  • How to spot them: defined inside a method, not prefixed with self.
  • Lifetime: created when the method starts, destroyed when it finishes; can’t be accessed outside.
class Calculator:
    def add(self, a, b):
        result = a + b  # Local Variable
        print(result)

c = Calculator()
c.add(10, 20)
print(result)       # outside the method
30
Traceback (most recent call last):
  ...
NameError: name 'result' is not defined
c.add(10, 20) startsresult = 30 createdprint(result)method ends · result gone

Real-world version: a cart needs the discount amount only while calculating the final price.

class Cart:
    def final_price(self, price, discount_percent):
        discount = price * discount_percent / 100  # Local Variable
        print("Final price:", price - discount)

cart = Cart()
cart.final_price(2000, 10)
Final price: 1800.0

(It prints 1800.0, a float, because / always returns a float in Python 3.)

Instance methods

Variables describe what an object has; methods describe what it can do. A method is a function defined inside a class. Python has three types: instance, class and static.

Instance methods work with the data of one specific object. You can spot them because they are defined in the class, take self as the first parameter, and are usually called on an object.

class Student:
    def __init__(self, name, roll_no):
        self.name = name
        self.roll_no = roll_no

    def talk(self):
        print("Name:", self.name)
        print("Roll No:", self.roll_no)

s1 = Student("Sunny", 101)
s1.talk()
Name: Sunny
Roll No: 101

talk() prints the data of whichever object calls it. Real-world version: a bank account that can take deposits and show its own balance.

class BankAccount:
    def __init__(self, holder_name, balance):
        self.holder_name = holder_name
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount
        print(self.holder_name, "deposited", amount)

    def show_balance(self):
        print(self.holder_name, "has a balance of", self.balance)

acc = BankAccount("Kavya", 3000)
acc.deposit(1500)
acc.show_balance()
Kavya deposited 1500
Kavya has a balance of 4500

Class methods

Class methods work with class-level data shared by all objects. The @classmethod decorator makes Python pass the class itself as the first argument, named cls by convention. They’re usually called with the class name, and need no object.

class Student:
    school_name = "XYZ College"

    @classmethod
    def show_school_name(cls):
        print("School:", cls.school_name)

Student.show_school_name()
School: XYZ College

Real-world version: a cinema chain changes the ticket price for all shows at once.

class MovieTicket:
    ticket_price = 200

    @classmethod
    def update_price(cls, new_price):
        cls.ticket_price = new_price
        print("New ticket price for all shows:", cls.ticket_price)

MovieTicket.update_price(250)
New ticket price for all shows: 250

Because cls.ticket_price changes the class variable, every MovieTicket object, old or new, now sees 250.

Static methods

Static methods use neither object data nor class data. They are helper functions kept inside a class for logical grouping. @staticmethod tells Python not to pass self or cls, so the method behaves like a normal function. You can call it with the class name or through an object.

class MathUtils:
    @staticmethod
    def add(a, b):
        return a + b

print(MathUtils.add(10, 20))
30

Real-world version: a rupees-to-dollars helper that needs no account or class data.

class CurrencyConverter:
    @staticmethod
    def rupees_to_dollars(rupees, rate):
        return rupees / rate

print(CurrencyConverter.rupees_to_dollars(8300, 83))
100.0

Key terms

Constructor (__init__)
A special method Python runs automatically, once, when an object is created; it sets the object’s starting instance variables.
Default constructor
The do-nothing constructor a class uses when you don’t write __init__; it is inherited from Python’s built-in object.
Constructor overloading
Having several constructors with different parameters. Python doesn’t support it: a later __init__ replaces an earlier one.
Decorator
A function, applied with @name above a definition, that takes a function and returns a modified one, changing its behaviour without editing its code.
Wrapper function
The inner function a decorator returns; it adds extra behaviour and calls the original function.
Instance variable
A variable stored in one object, usually created with self.name = value; every object has its own copy.
Static (class) variable
A variable defined in the class body outside all methods; one copy is shared by every object of the class.
Local variable
A variable created inside a method without self; it exists only while that method runs.
Instance method
A method whose first parameter is self; it works with the data of the object that calls it.
Class method
A method marked @classmethod that receives the class as cls and works with class-level data.
Static method
A method marked @staticmethod that receives neither self nor cls; a helper grouped inside a class.

Self-check

Pick an answer. You’ll see right away whether it’s correct and why.

Why is __init__ better than a set_details() method for initial data?

  1. It runs faster
  2. It runs automatically at creation, so an object can’t be left without its data
  3. It can be called many times
  4. It makes variables private

With a normal method you must remember a second step; forgetting it causes an AttributeError later.

A class has __init__ that prints “hi”, and a method show(). You create one object and call show() three times. How many times is “hi” printed?

  1. 0
  2. 3
  3. 1
  4. 4

The constructor runs once per object, at creation.

A class defines __init__(self) and then __init__(self, name). What does Student() do?

  1. Runs the first constructor
  2. Runs both
  3. Creates the object with name = None
  4. Raises TypeError: missing 1 required positional argument: 'name'

The second definition replaces the first, and it needs a name.

What does @simple_decorator above def greet(): mean?

  1. greet = simple_decorator(greet)
  2. simple_decorator = greet()
  3. greet runs once immediately
  4. greet becomes a class method

The decorator receives the function and the name is rebound to whatever it returns (the wrapper).

Where is a static (class) variable defined?

  1. Inside __init__ with self.
  2. Inside any method without self
  3. In the class body, outside all methods
  4. Outside the class

Variables in the class body belong to the class and are shared by all its objects.

Student.school_name is “XYZ”. You run s1.school_name = "ABC". What is s2.school_name?

  1. ABC
  2. XYZ
  3. An error
  4. None

Assigning through s1 creates an instance variable on s1 only. The shared class value is unchanged.

A method needs no object data and no class data, it just converts units. Which type fits?

  1. Instance method
  2. Class method
  3. Constructor
  4. Static method

Static methods get no automatic first argument; they’re helpers grouped in the class.

What does Python pass as the first argument to a @classmethod?

  1. The class itself
  2. The calling object
  3. Nothing
  4. The module

That’s why it can read and change class variables through cls.

All of it, in one sentence

The constructor __init__ sets up every object automatically; decorators wrap functions to change how they behave; data lives in instance, static or local variables, and behaviour in instance, class or static methods depending on whose data they need.
