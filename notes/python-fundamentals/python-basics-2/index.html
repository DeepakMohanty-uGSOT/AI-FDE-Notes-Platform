Operator precedence: what Python calculates first

When an expression has more than one operator, the order matters:

result = 10 + 5 * 2

Reading left to right suggests (10 + 5) * 2 = 30. But Python follows a fixed order of operations called operator precedence, like BODMAS/PEMDAS in school maths, so it calculates 10 + (5 * 2) = 20. Python finds the highest-priority operator, calculates that part, and repeats until one value is left.

PriorityOperator(s)Meaning
1 (highest)( )Parentheses: always first
2**Exponentiation
3* / // %Multiplication, division, floor division, modulus
4+ -Addition, subtraction
5== != > < >= <= (and in, is)Comparison, membership, identity
6notLogical NOT
7andLogical AND
8 (lowest)orLogical OR

Operators with equal priority are evaluated left to right.

Two exceptions worth knowing ** groups right to left: 2 ** 3 ** 2 is 2 ** 9 = 512. And ** binds tighter than a leading minus: -2 ** 2 is -4, not 4. When in doubt, add parentheses.

Worked example 1: multiplication before addition

print(10 + 5 * 2)
20

* outranks +, so 5 * 2 = 10 first, then 10 + 10 = 20. A mobile bill with a fixed rental of 199 plus 2 GB of extra data at 25 per GB works the same way, and so does a food order of 3 plates at 180 plus a delivery charge of 50:

monthly_bill = 199 + 2 * 25
print(monthly_bill)

bill_amount = 50 + 3 * 180
print(bill_amount)
249
590

Worked example 2: several operators mixed

print(2 + 3 * 4 - 6 / 2)
11.0

Monthly pay: basic salary 30,000, plus 10 overtime hours at 300, minus a yearly tax of 12,000 split over 12 months:

print(net_monthly_pay)
32000.0

Parentheses override precedence

print((10 + 5) * 2)

The parentheses force 10 + 5 = 15 first, then 15 * 2 = 30. Without them the answer is 20. Four friends each buying a movie ticket and a snack combo:

Strings: working with text

Beads on a threadA string is like a mala of beads: each character is one bead, in a fixed order. Because the beads are in order, you can count them, pick one out by its position, or cut out a stretch.

A string (str) is Python’s type for text: a sequence of characters. Names, messages, file paths, responses from other systems: almost every real program handles strings.

Creating strings

Write text inside quotes:

employee_name = "Deepak"
language = 'Python'

passenger_name = "Arjun Mehta"        # details on a train ticket
train_name = 'Shatabdi Express'
coach = "C2"

You can also build strings by concatenation (below) or by converting another type with str():

employee_id = str(1042)
print(employee_id, type(employee_id))
pin_code = str(560001)                # a PIN code stored as part of an address
print(pin_code, type(pin_code))
560001 <class 'str'>

Single vs double quotes

There is no difference in behaviour. If the text contains an apostrophe, wrap it in double quotes so the apostrophe isn’t mistaken for the closing quote:

status_message = "It's ready for deployment"
shop_notice = "We're closed on Sundays"
review = "The chef's special was excellent"

Negative indexing

Negative indexes count backwards from the end, starting at -1 for the last character:

Index out of range

Trying to access an index that does not exist in the string causes an error, rather than returning something meaningless:

word = "Python"
print(word[10])
IndexError: string index out of range

"Python" has 6 characters, so valid positive indexes are 0 to 5. The same thing happens reading a fifth digit from a 4-digit OTP:

otp = "4821"
print(otp[4])   # IndexError: valid indexes are 0 to 3
Rule of thumb The last valid index is always len(s) - 1.

String slicing: cutting out a piece

Indexing gives one character; slicing extracts a whole range in one step:

syntax
string_value[start:stop]
order_id = "ORD-2026-0042"
print(order_id[0:3])
ORD

Why the stop index is excluded

The slice stops just before the stop index. order_id[0:3] takes indexes 0, 1 and 2 (O, R, D) and stops before index 3 (-). This rule is the same everywhere slicing is used in Python.

Extracting the year from a date of birth stored as text:

date_of_birth = "1998-07-14"
print(date_of_birth[0:4])
1998

Leave out start and Python begins at index 0; leave out stop and it goes to the end.

order_id = "ORD-2026-0042"

print(order_id[9:])

f-strings: building dynamic text

The problem with plain concatenation

Once you mix several pieces of text with several variables, especially non-strings, + gets clumsy:

name = "Deepak"
age = 30
print("Employee " + name + " is " + str(age) + " years old")

account_holder = "Meera"
amount = 2500
print("Dear " + account_holder + ", Rs. " + str(amount) + " has been credited to your account.")
Employee Deepak is 30 years old
Dear Meera, Rs. 2500 has been credited to your account.

What is an f-string?

An f-string (“formatted string literal”) has an f right before the opening quote. Anything inside { } is evaluated and inserted into the text, converted to a string automatically.

name = "Deepak"
age = 30
print(f"Employee {name} is {age} years old")

account_holder = "Meera"
amount = 2500
print(f"Dear {account_holder}, Rs. {amount} has been credited to your account.")
Employee Deepak is 30 years old
Dear Meera, Rs. 2500 has been credited to your account.

Expressions inside the braces

Any valid expression works, including calculations:

unit_price = 250
quantity = 4
print(f"Total amount: {unit_price * quantity}")

units_consumed = 180
rate_per_unit = 6.5
print(f"Electricity bill: Rs. {units_consumed * rate_per_unit}")
Total amount: 1000
Electricity bill: Rs. 1170.0

Why f-strings are preferred: they are more readable than concatenation, need no manual str(), accept full expressions, and format numbers without extra function calls. They are the standard way to build text in modern Python.

Truthy and falsy values

Whenever Python needs a yes/no answer, it can treat any value as “truthy” (acts like True) or “falsy” (acts like False). Values that mean “nothing” or “empty” are falsy: 0, 0.0, "" and None (and, as you’ll see later, empty collections). Almost everything else is truthy.

print(bool(0))
print(bool(""))
print(bool("Python"))
print(bool(10))
False
False
True
True

Did the user leave the feedback box empty? Here they just pressed Enter:

feedback_text = input("Enter your feedback: ")
print("Feedback given:", bool(feedback_text))
Enter your feedback:
Feedback given: False

Booleans drive conditions, validation and loops; the next note (Control Flow) is built entirely on them.

None: the absence of a value

None is a special value meaning “deliberately no value”. Its type is NoneType, and there is only ever one None object in a running program. It is used for a value not assigned yet, data that is genuinely missing, or the result of a function that doesn’t return anything (more in the Functions note).

last_error_message = None

profile_photo = None        # a new user hasn't uploaded a photo
middle_name = None          # ...or added a middle name

None is not 0, False or ""

None is falsy, but it is not equal to 0, False or an empty string. Those are “zero” or “empty” values; None is the total absence of a value.

print(None == 0)
print(None == False)
print(None == "")

False

sold_out_count = 0     # counted, nothing left

Checking for None

Because None is a single unique object, the recommended check is is, not ==:

last_error_message = None
print(last_error_message is None)

delivery_date = None
print("Delivery date pending:", delivery_date is None)
True

A general approach to fixing errors

Don’t guess randomly. Work through it:

  1. 1
    Read the message carefullyThe whole traceback, not just the red colour.
  2. 2
    Identify the error typeIt is on the last line: TypeError, NameError…
  3. 3
    Find the line numberThe traceback points at the line (and often the exact spot with ^).
  4. 4
    Connect it to the conceptTypeError → data types; IndexError → indexing; and so on.
  5. 5
    Fix the cause, not the symptom→ e.g. convert input properly instead of deleting the line
In the field (FDE) When a customer pastes you a stack trace from production, the same five steps apply. The last line tells you what, the line number tells you where; read both before touching any code.

Key terms

Operator
A symbol or keyword, such as + or and, that tells Python to perform an operation on values called operands.
Floor division (//)
Divides and rounds the result down to a whole number: 17 // 5 is 3.
Modulus (%)
Gives the remainder left after division: 17 % 5 is 2.
Compound assignment
An operator like += or -= that updates a variable from its own value: x += 5 means x = x + 5.
Operator precedence
The fixed order in which Python evaluates operators in one expression: parentheses, then **, then * / // %, then + -, then comparisons, then not, and, or.
Membership operator
in / not in: checks whether a value is found inside a sequence such as a string.
Identity operator
is / is not: checks whether two names refer to the same object; mainly used as x is None.
Escape sequence
A backslash combination inside a string that stands for a special character, such as \n (new line) or \t (tab).
Raw string
A string with r before the quote, in which backslashes are kept as plain characters: r"C:\reports".
Immutable
Cannot be changed after creation; string methods therefore return new strings rather than modifying the original.
Index
A character’s position in a string, counted from 0 at the front or from -1 at the back.
Slicing
Extracting part of a sequence with [start:stop:step]; start is included, stop is excluded.
f-string
A string prefixed with f in which expressions inside { } are evaluated and inserted, with optional formatting like :.2f.
Truthy / falsy
How any value behaves when Python needs a yes/no answer; 0, empty strings and None are falsy, most other values are truthy.
None
Python’s single special value meaning “no value”, of type NoneType; check for it with is None.

Self-check

Pick an answer. You’ll see right away whether it’s correct and why.

What does 23 % 4 give?

  1. 5.75
  2. 5
  3. 3
  4. 4

4 goes into 23 five times (20), leaving a remainder of 3. % returns that remainder.

What does print(2 + 3 * 4) show?

  1. 14
  2. 20
  3. 24
  4. 9

* has higher precedence than +, so it is 2 + 12 = 14.

code = "ORD-2026". What is code[4:]?

  1. "ORD-"
  2. "-2026"
  3. "2"
  4. "2026"

Start at index 4 (the 2) and, with no stop, go to the end.

What is "Python"[-2]?

  1. "n"
  2. "o"
  3. "y"
  4. An IndexError

-1 is the last character (n), so -2 is the one before it, o.

Which line correctly prints Total: 500?

  1. print("Total: " + 500)
  2. print("Total: {500}")
  3. print(f"Total: {500}")
  4. print("Total: " - 500)

Only the f-string evaluates {500}. Option 1 is a TypeError; option 2 lacks the f and prints the braces literally.

What does print(None == 0) show?

  1. False
  2. True
  3. None
  4. An error

None means “no value”; 0 is a value (zero). Both are falsy, but they are not equal.

name = " Asha ". After name.strip() on its own line, what is name?

  1. "Asha"
  2. " Asha "
  3. None
  4. " Asha"

Strings are immutable. .strip() returns a new string; unless you assign it back, name is unchanged.

Which value is truthy?

  1. 0
  2. ""
  3. None
  4. "False"

"False" is a non-empty string, so it is truthy. The other three are classic falsy values.

The last line of an error says NameError: name 'totl' is not defined. The most likely cause?

  1. A missing parenthesis
  2. Adding a string and a number
  3. A misspelled variable name
  4. Wrong indentation

A NameError means Python has never seen that name, which is usually a typo of a real one.

All of it, in one sentence

Operators do the processing (calculate, compare, combine), precedence decides their order, strings can be indexed, sliced and formatted with f-strings, every decision boils down to True or False with None meaning “no value”, and an error’s last line and line number tell you what to fix.
